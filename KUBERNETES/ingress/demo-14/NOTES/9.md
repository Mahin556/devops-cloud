Your setup is working exactly as expected. Here's what's happening.

---

## 1. `curl myapp.example.com`

```text
308 Permanent Redirect
```

This is because your Ingress has:

```yaml
annotations:
  nginx.ingress.kubernetes.io/ssl-redirect: "true"
```

When a client sends:

```text
HTTP
http://myapp.example.com
```

the NGINX Ingress responds:

```text
308 Permanent Redirect
Location: https://myapp.example.com/
```

A **308** means "use HTTPS instead."

You can see the redirect target with:

```bash
curl -I http://myapp.example.com
```

Expected:

```text
HTTP/1.1 308 Permanent Redirect
Location: https://myapp.example.com/
```

---

## 2. `curl https://myapp.example.com`

```text
SSL certificate problem: self-signed certificate
```

This is also expected.

You created a **self-signed certificate**, so your system does not trust the certificate authority that signed it.

Browsers show:

> Your connection is not private

and `curl` refuses to connect.

---

## 3. `curl -k https://myapp.example.com`

```text
Hello from Frontend
```

The `-k` (or `--insecure`) option tells `curl`:

> Ignore certificate verification.

The TLS handshake succeeds, and the request reaches your frontend service.

---

## 4. `curl -k https://myapp.example.com/api`

```text
Hello from API service
```

This confirms:

* ✅ HTTPS is working.
* ✅ The TLS Secret is being used by the Ingress.
* ✅ Host matching (`myapp.example.com`) works.
* ✅ Path-based routing (`/api`) works.

The request flow is:

```text
Client
   │
HTTPS
   │
NGINX Ingress
   │
Host = myapp.example.com
   │
Path = /api
   │
API Service
```

---

## Why doesn't `curl` trust it?

Your certificate is:

```text
Self-signed
```

Normal certificate chain:

```text
Server Certificate
        │
Intermediate CA
        │
Root CA
        │
Trusted by OS
```

Your lab certificate looks like:

```text
Server Certificate
        │
Self-signed
```

Since there is no trusted CA, clients reject it unless you:

* use `curl -k`, or
* import your self-signed CA/certificate into the operating system's trust store.

---

## If you want HTTP instead of the redirect

Remove or change the annotation:

```yaml
nginx.ingress.kubernetes.io/ssl-redirect: "true"
```

or set:

```yaml
nginx.ingress.kubernetes.io/ssl-redirect: "false"
```

Then:

```bash
curl http://myapp.example.com
```

will go directly to the backend without redirecting to HTTPS.
