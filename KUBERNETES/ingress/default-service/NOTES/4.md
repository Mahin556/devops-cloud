The issue is **not the Ingress**. It's your **NGINX container**.

A standard NGINX serves only files that exist under:

```text
/usr/share/nginx/html
```

So:

* `/` → `index.html` ✅
* `/abc` → looks for `/usr/share/nginx/html/abc` ❌ 404
* `/anything` → 404

That's why your Ingress forwards `/da` to `default-service`, but the backend NGINX returns **404**.

## Option 1: Configure NGINX to return the same response for every path (Recommended)

Replace your Deployment with this:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: default-app
spec:
  replicas: 1
  selector:
    matchLabels:
      app: default-app
  template:
    metadata:
      labels:
        app: default-app
    spec:
      containers:
      - name: nginx
        image: nginx:1.25.2
        command:
        - sh
        - -c
        - |
          cat <<EOF >/etc/nginx/conf.d/default.conf
          server {
              listen 80;
              server_name _;

              location / {
                  return 200 "Hello from DEFAULT backend\n";
                  add_header Content-Type text/plain;
              }
          }
          EOF

          nginx -g 'daemon off;'
```

Now **every path** returns:

```text
Hello from DEFAULT backend
```

Examples:

```bash
curl http://localhost/
curl http://localhost/login
curl http://localhost/payment
curl http://localhost/abc
curl http://localhost/anything/here
```

All return:

```text
Hello from DEFAULT backend
```

## Option 2: Use `try_files`

If you want NGINX to always serve `index.html`:

```nginx
server {
    listen 80;

    location / {
        try_files $uri /index.html;
    }
}
```

Then:

```
/abc
```

serves:

```
index.html
```

---

## Option 3: Use a simple HTTP echo server (Great for Kubernetes labs)

Instead of NGINX, use an echo server that responds to any request.

Example:

```yaml
containers:
- image: hashicorp/http-echo
  args:
  - "-text=Hello from DEFAULT backend"
```

or

```yaml
- image: ealen/echo-server
```

This is very useful for testing Ingress because it responds to **all paths** and can even show you the request details.

---

### For Ingress practice

I recommend **Option 1** (custom NGINX config). It behaves like a real web server but always returns a successful response, making it easy to verify that your Ingress routing is working regardless of the requested path.
