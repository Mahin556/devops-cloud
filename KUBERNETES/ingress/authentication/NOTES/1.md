# Kubernetes Ingress NGINX – Basic Authentication (Detailed Guide)

## What is Basic Authentication?

**Basic Authentication** is an HTTP authentication mechanism where the client sends a **username** and **password** with every request.

The credentials are sent in the `Authorization` header after being **Base64 encoded** (not encrypted).

Example:

```http
Authorization: Basic a3ViZTprdWJl
```

where

```text
kube:kube
```

is Base64 encoded to

```text
a3ViZTprdWJl
```

> **Important:** Base64 is **not encryption**. Anyone can decode it. Therefore, Basic Authentication should always be used over **HTTPS** in production.

---

# Why use Basic Authentication?

Basic Authentication is commonly used for:

* Protecting internal applications
* Admin dashboards
* Development environments
* Monitoring dashboards (Grafana, Prometheus)
* Temporary authentication before implementing OAuth/OIDC
* Restricting access to APIs

Example:

```
Internet
      │
      ▼
NGINX Ingress Controller
      │
      │  Username + Password
      ▼
Authenticated?
     │
 ┌───┴────┐
 │        │
Yes       No
 │         │
 ▼         ▼
Backend   HTTP 401
Service
```

# How Basic Authentication works

```
Client
   │
   │ GET /
   ▼
Ingress Controller
   │
   │ Checks Secret
   ▼
Username & Password valid?
        │
   ┌────┴─────┐
   │          │
 Yes          No
   │          │
   ▼          ▼
Backend     HTTP 401
Service
```

Notice that:

* Authentication happens at the **Ingress Controller**
* Backend application never sees unauthenticated requests

# Step 1 – Create an htpasswd file

The NGINX Ingress Controller expects credentials stored in **Apache htpasswd format**.

Install the tool if needed.

Ubuntu

```bash
sudo apt install apache2-utils
```

RHEL

```bash
sudo dnf install httpd-tools
```

Generate a password file

```bash
htpasswd -c auth kube
```

Example

```
New password:
Re-type new password:

Adding password for user kube
```

The generated file

```
auth
```

contains something like

```
kube:$apr1$Q9.......
```

Notice:

* Password is **hashed**
* Plain-text password is **not stored**

---

# Step 2 – Create Kubernetes Secret

Create the Secret

```bash
kubectl create secret generic basic-auth \
  --from-file=auth
```

Verify

```bash
kubectl get secret basic-auth
```

Describe

```bash
kubectl describe secret basic-auth
```

Output

```
Name: basic-auth

Type: Opaque

Data
====
auth: 40 bytes
```

---

# Why must the file be named `auth`?

This is extremely important.

The controller expects

```
data.auth
```

inside the Secret.

Correct

```
Secret
└── data
    └── auth
```

Incorrect

```
Secret
└── data
    └── password
```

If the key isn't named `auth`, ingress-nginx cannot find the credentials and typically responds with:

```
503 Service Temporarily Unavailable
```

# Step 4 – Create the Ingress

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress

metadata:
  name: auth-demo

  annotations:

    nginx.ingress.kubernetes.io/auth-type: basic

    nginx.ingress.kubernetes.io/auth-secret: basic-auth

    nginx.ingress.kubernetes.io/auth-realm: "Authentication Required"

spec:

  ingressClassName: nginx

  rules:

  - host: app.example.com

    http:

      paths:

      - path: /

        pathType: Prefix

        backend:

          service:

            name: app-service

            port:

              number: 80
```

---

# Understanding each annotation

## auth-type

```yaml
nginx.ingress.kubernetes.io/auth-type: basic
```

Enables Basic Authentication.

Supported values

* basic

---

## auth-secret

```yaml
nginx.ingress.kubernetes.io/auth-secret: basic-auth
```

Tells the controller which Secret contains the credentials.

---

## auth-realm

```yaml
nginx.ingress.kubernetes.io/auth-realm: "Authentication Required"
```

Controls the browser popup.

Browser shows

```
Authentication Required

Username:
Password:
```

# Common Errors

## 401 Unauthorized

Reason

* Wrong username
* Wrong password

---

## 503 Service Temporarily Unavailable

Usually means

* Secret missing
* Secret name incorrect
* Secret key is not `auth`

---

## 404 Not Found

Authentication succeeded, but the backend or Ingress path doesn't match.

---

## Secret in wrong namespace

Ingress can only reference a Secret in the **same namespace**.

# Security Considerations

### Always use HTTPS

Basic Authentication transmits credentials on every request. Without HTTPS, they can be intercepted.

### Passwords are hashed

The `htpasswd` file stores password hashes, not plaintext passwords.

### Suitable use cases

* Internal applications
* Development clusters
* Small administrative interfaces

### Less suitable for

* Public-facing applications with user accounts
* Single Sign-On (SSO) environments
* Large enterprise authentication

For those scenarios, consider OAuth2, OpenID Connect (OIDC), or an external authentication provider.

---

# Best Practices

* Use HTTPS with Basic Authentication.
* Store credentials in Kubernetes Secrets.
* Keep the Secret in the same namespace as the Ingress.
* Rotate passwords periodically.
* Grant access only to users who need it.
* Use stronger authentication methods (OIDC/OAuth2) for production user-facing applications when appropriate.

---

# Summary

1. Create an `htpasswd` file containing hashed user credentials.
2. Store it in a Kubernetes Secret with the key named `auth`.
3. Configure your Ingress with the `auth-type`, `auth-secret`, and `auth-realm` annotations.
4. Requests without valid credentials receive `401 Unauthorized`.
5. Requests with valid credentials are forwarded to the backend service.
6. Authentication is enforced by the **NGINX Ingress Controller**, so unauthenticated requests never reach your application.
