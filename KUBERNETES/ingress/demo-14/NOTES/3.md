| URL              | Match? | Reason                          |
| ---------------- | :----: | ------------------------------- |
| `/api`           |    ✅   | Ends right after `/api` (`$`)   |
| `/api/`          |    ✅   | `/` after `/api`                |
| `/api/users`     |    ✅   | `/` followed by anything        |
| `/api/v1`        |    ✅   | `/` followed by anything        |
| `/api/v1/orders` |    ✅   | `/` followed by anything        |
| `/api/test/123`  |    ✅   | `/` followed by anything        |
| `/apis`          |    ❌   | `s` is not `/` or end of string |
| `/api123`        |    ❌   | `1` is not `/` or end of string |
| `/api-test`      |    ❌   | `-` is not `/` or end of string |
| `/ap`            |    ❌   | Does not start with `/api`      |
| `/apix/users`    |    ❌   | `x` is not `/` or end of string |
| `/abc/api`       |    ❌   | Does not start with `/api`      |

### Regex

```regex
/api(/|$)(.*)
```

* `/api` → Match exactly.
* `(/|$)` → After `/api`, there must be either:

  * `/`, or
  * the end of the URL.
* `(.*)` → Match everything after that.

This is commonly used in **NGINX Ingress** to match `/api` and all of its subpaths while **not** matching similar paths like `/apis` or `/api123`.
