### You updated a Secret, but the running pod doesn't receive the new values.

Solution:

Method 1 - Rollout Restart:

```bash
kubectl rollout restart deployment/<deployment-name>
```

Method 2 - Delete Pod:

```bash
kubectl delete pod <pod-name>
```

Key Points:
- Kubernetes does NOT automatically propagate Secret/ConfigMap changes to running pods
- Pods read environment variables only at startup
- Two solutions: rollout restart or delete the pod
- When pod is deleted, the ReplicaSet creates a new pod with updated configuration
- kubectl rollout restart is the preferred method for Deployments
- This triggers a rolling update, ensuring zero downtime
