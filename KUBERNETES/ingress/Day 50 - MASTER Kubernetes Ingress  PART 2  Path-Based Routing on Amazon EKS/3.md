# Idea

One Ingress Controller → Many Load Balancers

Example:

```text
Ingress Controller
   ├── LB1 → app1
   ├── LB2 → app2
   └── LB3 → app3
```

---

# Example with AWS Load Balancer Controller

Using **AWS Load Balancer Controller**, each Ingress can create its own **AWS Application Load Balancer**.

## Ingress 1 → Load Balancer 1

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: app1-ingress
  annotations:
    alb.ingress.kubernetes.io/scheme: internet-facing
spec:
  ingressClassName: alb
  rules:
  - host: app1.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: app1-service
            port:
              number: 80
```

This creates:

```
ALB-1 → app1-service
```

# Result

Same controller → Multiple load balancers

```text
AWS Load Balancer Controller
        │
   ┌────┴────┐
   │         │
 ALB1      ALB2
   │         │
 app1      app2
```

---

# When This Happens

You get multiple LBs when:

* Different Ingress resources exist
* Different annotations are used
* Different hostnames are used
* Different groups are not merged

---

# When You Get Only One Load Balancer

If Ingress resources share the same group annotation:

```yaml
alb.ingress.kubernetes.io/group.name: my-group
```

Then:

```
One ALB → Multiple apps
```

---

# Two Patterns

## 1. One LB per App

```
Ingress1 → LB1 → app1
Ingress2 → LB2 → app2
```

## 2. One LB for Many Apps

```
Ingress1 → LB1 → app1
Ingress2 → LB1 → app2
```

---

# Key Point

The **controller manages LBs**, but **Ingress objects decide how many LBs exist**.
