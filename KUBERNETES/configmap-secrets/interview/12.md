## ConfigMap was updated, but the pod still shows old configuration values.

### Root Cause:
Environment variables from ConfigMaps are **only injected at pod startup**. When the pod starts, it reads the ConfigMap values once. If the ConfigMap changes later, the running pod doesn't automatically get the new values.

### How to Fix:

**Method 1: Restart the Pod**
```bash
kubectl rollout restart deployment <deployment-name>
```

**Method 2: Mount ConfigMap as Volume**
- When mounted as a volume, changes reflect immediately
- The file inside the container gets updated automatically
- No pod restart needed

| Method | Update Behavior |
|--------|-----------------|
| **Environment Variables** | Need pod restart |
| **Volume Mount** | Changes reflect automatically |
