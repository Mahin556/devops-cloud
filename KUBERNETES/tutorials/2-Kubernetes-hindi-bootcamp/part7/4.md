### Where is `/var/cache/apt` Stored on the Host?

The path `/var/cache/apt` exists **inside the container**; it is a temporary cache directory mounted by BuildKit for the `RUN` instruction. It does **not** correspond to a single, fixed folder on your host machine.

Its actual storage location depends on the **BuildKit driver** you are using.

---

### 1. The Default `docker` Driver
This is the driver used when you run `docker build` directly. 

- **Metadata**: Stored in the BuildKit database at `/var/lib/docker/buildkit/`.
- **Actual Cache Data**: If your Docker uses the `overlay2` storage driver (the default), the cache data is stored as layers (or snapshots) inside directories like `/var/lib/docker/overlay2/<ID>/diff/`.
- **Important Note**: `/var/lib/docker` is the default location. If you have configured a custom `data-root` for Docker, this path will be different.

---

### 2. The `docker-container` or `kubernetes` Driver
If you created a standalone BuildKit container using `docker buildx create --driver docker-container`, or if you are using the `kubernetes` driver, the cache data is **stored inside a persistent Docker volume**. 

- You **cannot** access this cache through a direct, predictable host filesystem path.

---

### How to Manage and View the Cache

Since you cannot directly access the host path (except in specific cases), you need to use Docker commands to inspect and manage the BuildKit cache.

#### 1. View Cache Details
Use the `docker buildx du --verbose` command to list all build cache entries. The entries of type `exec.cachemount` are exactly the caches generated by `RUN --mount=type=cache`.

```bash
docker buildx du --verbose
```
This will show you the total size and individual breakdown of all cached artifacts.

#### 2. Clean Up the Cache
If you need to free up space, you can use the prune command:

```bash
docker buildx prune
```

---

### How to Export the Cache to a Specific Host Directory

If you need to store the cache in a **predictable and accessible** host path (for example, in a CI/CD pipeline where you want to reuse the cache between builds), you can explicitly export and import the cache using the `local` cache type.

**1. Export the cache to a local directory during build:**
```bash
docker buildx build --cache-to type=local,dest=./my-build-cache -t myapp .
```
*(The cache content will now be saved directly in the `./my-build-cache` folder on your host.)*

**2. Import the cache from that local directory on the next build:**
```bash
docker buildx build --cache-from type=local,src=./my-build-cache -t myapp .
```

**The Golden Rule:** 
- By default, BuildKit manages the cache internally, and you shouldn't need to poke around `/var/lib/docker/` directly.
- For CI/CD or when you need explicit host control, **always use `--cache-to type=local`** to save the cache exactly where you want it.
