### Containerizing a legacy application that only reads configuration from environment variables (DB_HOST, DB_PORT, DB_USER). Cannot rebuild image or modify application code.

**Solution:**

**Step 1 - Create ConfigMap at runtime (no YAML file):**
```bash
kubectl create configmap legacy-app-config \
  --from-literal=DB_HOST=postgres.example.com \
  --from-literal=DB_PORT=5432 \
  --from-literal=DB_USER=legacy-app-user \
  --from-literal=LOG_LEVEL=info \
  -n production
```

**Step 2 - Inject as Environment Variables:**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: legacy-app
spec:
  replicas: 2
  selector:
    matchLabels:
      app: legacy-app
  template:
    metadata:
      labels:
        app: legacy-app
    spec:
      containers:
      - name: legacy-app
        image: legacy-app:latest    # Cannot be modified/ rebuilt
        envFrom:
        - configMapRef:
            name: legacy-app-config  # All keys become env vars
        # Individual env vars also possible:
        env:
        - name: APP_NAME
          value: "LegacyApp"
        - name: EXTRA_CONFIG
          valueFrom:
            configMapKeyRef:
              name: legacy-app-config
              key: DB_HOST
```

**Restart to apply:**
```bash
kubectl rollout restart deployment/legacy-app
```

**Key Points:**
- **ConfigMap** is the correct resource for non-sensitive configuration
- `envFrom.configMapRef` injects ALL key-value pairs as environment variables
- No image rebuild required - configuration is external
- Application code remains unchanged
- ConfigMap created at runtime via `kubectl` - no YAML needed
- Each key in ConfigMap becomes an environment variable name
- Values are injected at container startup
- Pod restart needed for ConfigMap changes to take effect
