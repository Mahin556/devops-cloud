## Communication Boundaries Between Pods in Kubernetes

Kubernetes uses **Network Policies** to control and restrict communication between Pods.

A Network Policy acts like a firewall at:

* Layer 3 (IP level)
* Layer 4 (Port level)

By default:

* All Pods in Kubernetes can communicate with each other.

When Network Policies are applied:

* Only allowed traffic is permitted.
* Unauthorized communication is blocked.
* Helps implement a zero-trust security model.

---

## What Network Policies Control

* Pod-to-Pod communication
* Pod-to-Service communication
* External traffic access
* Allowed ports and protocols

---

## Kubernetes Networking Components

| Component      | Purpose                                     |
| -------------- | ------------------------------------------- |
| Service        | Internal connectivity and load balancing    |
| Ingress        | External HTTP/HTTPS routing                 |
| Network Policy | Security and traffic filtering between Pods |

---

## Benefits

* Improved security
* Traffic isolation
* Controlled Pod communication
* Zero-trust networking

“Kubernetes enforces communication boundaries between Pods using Network Policies. Network Policies control which Pods can communicate with each other based on IP addresses, ports, and protocols, helping secure the cluster with controlled network access.”
