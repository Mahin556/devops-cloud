If you **cannot change the IP addresses** (`192.168.56.11` and `192.168.57.11`), the only way to make them reachable without a router is to **change the netmask to `/16`** on both `enp0s8` interfaces. This does not change the IP addresses themselves, only the subnet size, so both IPs end up in the same logical subnet (`192.168.0.0/16`).

Below are the exact steps and commands to solve your problem using `ip route` and `socat` **without changing the IP addresses**.

---

## 1. Change netmask to `/16` (no IP change)

### On **Server One**
```bash
sudo ip addr del 192.168.56.11/24 dev enp0s8
sudo ip addr add 192.168.56.11/16 dev enp0s8
```

### On **Server Two**
```bash
sudo ip addr del 192.168.57.11/24 dev enp0s8
sudo ip addr add 192.168.57.11/16 dev enp0s8
```

Verify from Server One:
```bash
ping 192.168.57.11
```
If ping works, proceed.

---

## 2. Variables for each server

### On **Server One**
```bash
NODE_IP="192.168.56.11"
TO_NODE_IP="192.168.57.11"
TUNNEL_IP="10.0.0.1"
```

### On **Server Two**
```bash
NODE_IP="192.168.57.11"
TO_NODE_IP="192.168.56.11"
TUNNEL_IP="10.0.0.2"
```

---

## 3. Exact commands from the screenshot (with correct interfaces)

Run the following on **both** servers.  
Replace `eth0` with your actual interfaces (`enp0s3`, `enp0s8`, `br0`, `tundudp`).

```bash
# ------------------- Step 4 Specific Setup ------------------- #

echo "Starts the UDP tunnel in the background"
sudo socat UDP:$TO_NODE_IP:9000,bind=$NODE_IP:9000 TUN:$TUNNEL_IP/16,tun-name=tundudp,iff-no-pi,tun-type=tun &

echo "Setting the MTU on the tun interface"
sudo ip link set dev tundudp mtu 1492

echo "Disables reverse path filtering"
sudo bash -c 'echo 0 > /proc/sys/net/ipv4/conf/all/rp_filter'
sudo bash -c 'echo 0 > /proc/sys/net/ipv4/conf/default/rp_filter'
sudo bash -c 'echo 0 > /proc/sys/net/ipv4/conf/enp0s3/rp_filter'
sudo bash -c 'echo 0 > /proc/sys/net/ipv4/conf/enp0s8/rp_filter'
sudo bash -c 'echo 0 > /proc/sys/net/ipv4/conf/br0/rp_filter'
sudo bash -c 'echo 0 > /proc/sys/net/ipv4/conf/tundudp/rp_filter'
```

---

## 4. Add routes over the tunnel

### On **Server One**
```bash
sudo ip route add 172.16.1.0/24 via 10.0.0.2 dev tundudp
```

### On **Server Two**
```bash
sudo ip route add 172.16.0.0/24 via 10.0.0.1 dev tundudp
```

Enable IP forwarding on **both** servers:
```bash
sudo sysctl -w net.ipv4.ip_forward=1
```

---

## 5. Fix the bridge IP addresses

Your `br0` on Server One had `172.16.0.0/24` (the network address, not a host address).  
Correct it as follows.

### On **Server One**
```bash
sudo ip addr del 172.16.0.0/24 dev br0 2>/dev/null
sudo ip addr add 172.16.0.1/24 dev br0
sudo ip link set br0 up
```

### On **Server Two**
```bash
sudo ip addr add 172.16.1.1/24 dev br0
sudo ip link set br0 up
```

---

## 6. Set default routes inside the namespaces

### On **Server One**
```bash
sudo ip netns exec NS1 ip route add default via 172.16.0.1
sudo ip netns exec NS2 ip route add default via 172.16.0.1
```

### On **Server Two**
```bash
sudo ip netns exec NS1 ip route add default via 172.16.1.1
sudo ip netns exec NS2 ip route add default via 172.16.1.1
```

---

## 7. Test the tunnel

From **Server One**:
```bash
sudo ip netns exec NS1 ping 172.16.1.2
```

From **Server Two**:
```bash
sudo ip netns exec NS1 ping 172.16.0.2
```

If ping succeeds, your `socat` tunnel and routing are working correctly.

After running these, test with `ping` from inside the namespaces.

> **Note:** If you cannot change the netmask either, then there is no way to make `192.168.56.11` and `192.168.57.11` communicate without an intermediate router. `socat` alone cannot bridge two isolated subnets.
