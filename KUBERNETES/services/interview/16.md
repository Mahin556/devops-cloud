### Deploy public-facing API on managed Kubernetes in cloud. Make it accessible on the internet with minimal configuration.

**Solution:**

**API Deployment:**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: api
  template:
    metadata:
      labels:
        app: api
    spec:
      containers:
      - name: api
        image: nginx-api:latest
        ports:
        - containerPort: 8080
```

**LoadBalancer Service:**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: api-service
spec:
  type: LoadBalancer                   # Cloud-managed load balancer
  selector:
    app: api
  ports:
  - port: 80                           # External port
    targetPort: 8080                   # Container port
    protocol: TCP
```

**Verify and Access:**
```bash
# Check external IP/hostname (may take a few minutes)
kubectl get service api-service

# Output:
# NAME          TYPE           CLUSTER-IP      EXTERNAL-IP      PORT(S)
# api-service   LoadBalancer   10.96.100.1     34.120.50.100    80:30080/TCP

# Access the API
curl http://34.120.50.100/api/endpoint
```

**Key Points:**
- **LoadBalancer Service** provisions a cloud-managed external load balancer
- Cloud provider assigns a public IP or DNS name automatically
- Minimal configuration - just set `type: LoadBalancer`
- Traffic flow: Internet → Cloud Load Balancer → Service → Pods (port 8080)
- Load balancer distributes traffic evenly across all 3 replicas
- Works with AWS (ELB), GCP (Cloud LB), Azure (Azure LB)
- Production-ready for public-facing applications
