### What are ConfigMaps and Secrets in Kubernetes, and how do they differ?

| ConfigMap                                                                                           | Secret                                                  |
| --------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| Stores non-sensitive configuration data.                                                            | Stores sensitive information.                           |
| Used for application configuration like environment variables, config files, and command arguments. | Used for passwords, API keys, SSH keys, and tokens.     |
| Data is stored as plain text.                                                                       | Data is stored as Base64-encoded values.                |
| No special protection by default.                                                                   | Supports better security and RBAC-based access control. |
| Suitable for general application settings.                                                          | Suitable for confidential data.                         |

### Examples

#### ConfigMap

```yaml id="8p2m6"
data:
  APP_ENV: production
  LOG_LEVEL: debug
```

#### Secret

```yaml id="5x7n1"
data:
  password: cGFzc3dvcmQ=
```

---

## Simple Interview Answer

“In Kubernetes, ConfigMaps and Secrets are used to store external configuration separately from application code. ConfigMaps store non-sensitive data like environment variables and configuration files, while Secrets store sensitive data such as passwords, API keys, and tokens with controlled access.”
