There are two common ways to create the certificate for this Ingress:

1. **Automatically with cert-manager + Let's Encrypt** (recommended for public domains)
2. **Manually using a self-signed certificate** (good for labs and local testing)

---

# Option 1: Automatic certificate with cert-manager

Your Ingress already contains:

```yaml
annotations:
  cert-manager.io/cluster-issuer: "letsencrypt-prod"

tls:
- hosts:
  - myapp.example.com
  secretName: myapp-tls
```

This tells cert-manager:

> "Request a certificate for `myapp.example.com` and store it in the Secret `myapp-tls`."

## Step 1: Install cert-manager

```bash
kubectl apply -f https://github.com/cert-manager/cert-manager/releases/latest/download/cert-manager.yaml
```

Wait until all pods are running:

```bash
kubectl get pods -n cert-manager
```

---

## Step 2: Create a ClusterIssuer

For Let's Encrypt production:

```yaml
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: letsencrypt-prod
spec:
  acme:
    email: you@example.com
    server: https://acme-v02.api.letsencrypt.org/directory

    privateKeySecretRef:
      name: letsencrypt-prod

    solvers:
    - http01:
        ingress:
          class: nginx
```

Apply it:

```bash
kubectl apply -f clusterissuer.yaml
```

Verify:

```bash
kubectl get clusterissuer
```

Expected:

```text
NAME                READY
letsencrypt-prod    True
```

---

## Step 3: Deploy your Ingress

```bash
kubectl apply -f tls-path-routing.yaml
```

cert-manager will automatically:

* Request a certificate from Let's Encrypt.
* Complete the ACME challenge.
* Create the Secret:

```text
myapp-tls
```

Check:

```bash
kubectl get certificate
```

```bash
kubectl get secret myapp-tls
```

---

## Step 4: Verify

```bash
kubectl describe certificate
```

or

```bash
kubectl describe secret myapp-tls
```

---

# Option 2: Self-signed certificate (local labs)

Generate a private key:

```bash
openssl genrsa -out tls.key 2048
```

Generate a certificate:

```bash
openssl req -x509 \
    -new \
    -nodes \
    -key tls.key \
    -sha256 \
    -days 365 \
    -out tls.crt
```

When prompted:

```text
Common Name (CN):
```

enter:

```text
myapp.example.com
```

---

Create the Kubernetes Secret:

```bash
kubectl create secret tls myapp-tls \
    --cert=tls.crt \
    --key=tls.key
```

Verify:

```bash
kubectl get secret myapp-tls
```

---

# Option 3: Create a self-signed certificate with cert-manager

Instead of OpenSSL, cert-manager can generate one for you.

Create an Issuer:

```yaml
apiVersion: cert-manager.io/v1
kind: Issuer
metadata:
  name: selfsigned
spec:
  selfSigned: {}
```

Apply:

```bash
kubectl apply -f issuer.yaml
```

Then create a Certificate:

```yaml
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: myapp-cert
spec:
  secretName: myapp-tls
  issuerRef:
    name: selfsigned
    kind: Issuer

  dnsNames:
  - myapp.example.com
```

Apply:

```bash
kubectl apply -f certificate.yaml
```

cert-manager creates:

```text
Secret:
myapp-tls
```

automatically.

---

# How your Ingress uses it

Your Ingress already references:

```yaml
tls:
- hosts:
  - myapp.example.com
  secretName: myapp-tls
```

The Secret should contain:

```text
tls.crt
tls.key
```

When a client connects over HTTPS:

```text
Browser
     │
HTTPS
     │
Ingress Controller
     │
Reads Secret:
myapp-tls
     │
Uses tls.crt + tls.key
     │
Backend Service
```

---

## Which method should you use?

* **Public domain (`myapp.example.com`) accessible from the internet:** Use **Let's Encrypt + cert-manager**.
* **Local lab (Kind, Minikube, MetalLB, VirtualBox):** Use a **self-signed certificate** or a **self-signed cert-manager Issuer**, since Let's Encrypt cannot validate private or non-public environments.
