### Backend legacy application expects `/v1/users` format but external clients call `/api/users`. Cannot modify application code.

**Solution:**

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: rewrite-ingress
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /v1/$2
    nginx.ingress.kubernetes.io/use-regex: "true"
spec:
  ingressClassName: nginx
  rules:
  - http:
      paths:
      - path: /api(/|$)(.*)            # Matches /api/users, /api/products, etc.
        pathType: ImplementationSpecific
        backend:
          service:
            name: legacy-service
            port:
              number: 80
```

**How Rewriting Works:**
```
Client Request:   /api/users          → Rewritten to: /v1/users
Client Request:   /api/products/123   → Rewritten to: /v1/products/123
Client Request:   /api/orders/list    → Rewritten to: /v1/orders/list
```

**Alternative - Simpler Rewrite:**
```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: simple-rewrite-ingress
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /v1/$1
spec:
  ingressClassName: nginx
  rules:
  - http:
      paths:
      - path: /api/(.*)
        pathType: ImplementationSpecific
        backend:
          service:
            name: legacy-service
            port:
              number: 80
```

**Key Points:**
- `rewrite-target` annotation modifies request path before forwarding
- `use-regex: "true"` enables regular expression matching
- Capture groups `(.*)` capture parts of the path for rewriting
- `$1`, `$2` reference captured groups in rewrite target
- External URLs remain modern (`/api/users`)
- Internal application receives expected paths (`/v1/users`)
- No application code changes needed
- Rewrite happens at Ingress level, transparent to application
