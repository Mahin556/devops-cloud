## Can We Expand a PV at Runtime? I have a 50GB PV that is about to be 95% full. Can I expand it while it's running? What things do I need to consider?

**Answer:** Yes, PV can be expanded at runtime, but **three conditions must be met**:

### Three Requirements for PV Expansion:

**1. Dynamic Provisioning:**
- The PV must be created using **dynamic provisioning** (via StorageClass)
- Static PVs (manually created) cannot be expanded easily
- The PV must have been created through StorageClass + CSI provisioner

**2. Backend Storage Must Support Expansion:**
- The underlying storage system must have volume expansion capability
- Not all storage backends support online expansion
- Examples:
  - AWS EBS: Supports expansion (gp2, gp3, io1, io2)
  - Some storage types: Once created, size is fixed; need to create new volume
- If backend storage doesn't support expansion, you CANNOT expand from Kubernetes side
- "PV depends on the condition of backend storage"

**3. StorageClass Must Have `allowVolumeExpansion: true`:**
- In the StorageClass YAML, the parameter `allowVolumeExpansion` must be set to `true`
- If it's `false` (default), expansion is blocked
- This is the Kubernetes-level permission for expansion

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: expandable-storage
provisioner: ebs.csi.aws.com
allowVolumeExpansion: true    # THIS MUST BE TRUE
parameters:
  type: gp3
```

---

### Summary: Three Conditions for PV Expansion

| # | Condition | Why Needed |
|---|-----------|------------|
| 1 | **Dynamic Provisioning** | Static PVs don't support easy expansion |
| 2 | **Backend storage supports expansion** | Actual disk/volume must be expandable |
| 3 | **StorageClass `allowVolumeExpansion: true`** | Kubernetes-level permission |
