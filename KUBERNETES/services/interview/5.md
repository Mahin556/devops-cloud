## How Does External Load Balancer Solve NodePort Limitations?

**Solution:** Place an **External Load Balancer** in front of NodePort services.

**Architecture:**
```
Client → DNS → External LB IP → Worker Node IP:NodePort → Service → Pod
```

**Benefits:**
- Client uses **DNS name** (e.g., k.com), not IP
- Load balancer IP is exposed, not node IPs directly
- Node ports are hidden behind the load balancer
- If one node fails, LB redirects to another node

**But New Problems:**
- One service = One load balancer
- 50 applications = 50 external load balancers
- Very expensive in cloud environments
- Operational overhead: managing ports, firewall rules, LB configurations per service
