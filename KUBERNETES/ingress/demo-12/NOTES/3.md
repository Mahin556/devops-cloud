The `301 Moved Permanently` is **expected NGINX behavior** when the request maps to a directory.

When you request:

```bash
curl localhost/welcome
```

NGINX sees that `/welcome` is a directory and redirects to:

```text
/welcome/
```

because relative URLs (CSS, JS, images) inside the page work correctly only with the trailing slash.

### Option 1 (Recommended): Accept the redirect

Browsers automatically follow it.

With `curl`, use:

```bash
curl -L localhost/welcome
```

The `-L` flag follows the 301 redirect.

---

### Option 2: Serve both without a redirect

If you want both `/welcome` and `/welcome/` to return the page **without** a redirect, add an exact-match location:

```nginx
location = /welcome {
    try_files /welcome/index.html =404;
}

location /welcome/ {
    root /usr/share/nginx/html;
    index index.html;
    try_files $uri $uri/ /welcome/index.html;
}
```

or equivalently:

```nginx
location = /welcome {
    root /usr/share/nginx/html;
    rewrite ^ /welcome/index.html break;
}

location /welcome/ {
    root /usr/share/nginx/html;
    index index.html;
    try_files $uri $uri/ /welcome/index.html;
}
```

Now:

```text
GET /welcome   -> index.html
GET /welcome/  -> index.html
```

No 301 redirect is issued.

### Why NGINX redirects by default

If `welcome` is a directory:

```text
/usr/share/nginx/html/
└── welcome/
    ├── index.html
    ├── style.css
    └── app.js
```

and the HTML contains:

```html
<link rel="stylesheet" href="style.css">
```

then:

* Visiting `/welcome/` makes the browser request `/welcome/style.css` ✅
* Visiting `/welcome` would make the browser request `/style.css` ❌

The automatic redirect ensures relative asset paths resolve correctly, which is why it's the default behavior and generally the recommended one.
