## 1. Introduction to CIS Benchmarks

- **CIS** = Center for Internet Security.
- Provides **best practices for security configuration** of target systems.
- Covers more than 14 technology groups, not just Kubernetes.
- Benchmarks are developed through a **consensus-based process** involving cybersecurity professionals and subject matter experts worldwide.
- For Kubernetes, CIS benchmarks give **default security rules** that administrators can apply when setting up clusters (e.g., using kubeadm or Rancher).
- Cloud providers like **Google Cloud and AWS** use CIS benchmarks as a base, customize them, and publish which rules they enforce (transparency).
- Companies can also customize the benchmarks before applying them.

## 2. CIS Kubernetes Benchmark PDF

### Downloading
- Search for “CIS benchmarks kubernetes”.
- Go to `cisecurity.org` → Kubernetes benchmarks → download latest (free, requires email).
- The transcript uses **version 1.6.0** (valid for Kubernetes 1.16–1.18, but works for 1.19 with minor differences).
- The document assumes configuration done with **kubeadm**, which is used in CKS exam clusters and in this course.

### Structure
- Organized by components:
  - Section 1: Control Plane (Master node) components
  - Section 2: etcd
  - Section 4: Worker nodes
  - Each rule has:
    - **Description** – what to check
    - **Audit** – command to verify current state
    - **Remediation** – steps/commands to fix if non-compliant

### Example Rules (for familiarity)
- **Rule 1.1.1** (Master node): Ensure API server pod specification file permissions are set to `644` or more restrictive.
  - Audit: `stat -c %a /etc/kubernetes/manifests/kube-apiserver.yaml`
  - Remediation: `chmod 644 /etc/kubernetes/manifests/kube-apiserver.yaml`
- **Rule 4.2.10** (Worker node): Ensure `--tls-cert-file` and `--tls-private-key-file` arguments are set appropriately.
  - Audit: `ps -ef | grep kubelet`
  - Remediation: Edit kubelet config file, add arguments, restart kubelet.

> No need to memorise rules for the exam; just know how to read and apply them.

## 3. Using kube-bench

**kube-bench** is a tool that automates CIS benchmark checks for Kubernetes clusters.

### Installation & Running
- From the official GitHub repo (`aquasecurity/kube-bench`).
- Easiest method: run inside a Docker container.
- Example command (from README):
  ```bash
  docker run --rm -v /etc:/etc -v /var:/var -v /usr/bin:/usr/bin \
    aquasec/kube-bench:latest master --version 1.19
  ```
  - `master` checks the master node; use `node` for worker nodes.
  - `--version` specifies Kubernetes version.

### Interpreting Results
- Output shows a summary: e.g., `43 checks passed, 12 failed, 10 warnings`.
- Scroll up to see colored list: **FAIL** items indicate rules that did not pass.

### Hands-on Fix Example
- One failed rule: **1.1.2** – “Ensure that the etcd data directory ownership is set to etcd:etcd”.
- Audit command from PDF:
  ```bash
  stat -c %U:%G /var/lib/etcd
  ```
  Output was `root:root` (incorrect).
- Remediation:
  ```bash
  chown etcd:etcd /var/lib/etcd
  ```
- Verify with audit command again.
- Re-run kube-bench; now the rule passes, and total passed checks increase.

> In the CKS exam, you may be given kube-bench output or asked to fix a specific rule manually.

## 4. Additional Remarks

### Cloud Provider CIS Benchmarks
- **Google Cloud** publishes its GKE CIS benchmark compliance: which rules are passed/failed, and any customizations.
- AWS also follows similar practice.
- Useful for understanding managed Kubernetes security defaults.

### Other Tools
- **Docker Bench** – similar tool for checking Docker host configuration.
- Relevant because container runtime security affects Kubernetes security.
- Not a primary CKS exam topic but good to know.

---

## 5. Key Takeaways

- CIS benchmarks provide **standardised security rules** for Kubernetes.
- They are **vendor-neutral** and can be applied manually or with tools like kube-bench.
- The PDF document is **structured** with audit and remediation sections.
- **kube-bench** automates the checks and gives a clear pass/fail list.
- For the exam, you should be able to:
  - Read a CIS rule and understand what it asks.
  - Run the audit command to check current state.
  - Apply the remediation to fix the issue.
  - Re-run the check to verify.

- Always ensure your cluster components follow these best practices to maintain a secure Kubernetes environment.
