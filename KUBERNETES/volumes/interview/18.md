## How Does API Server Decide Which PV to Allocate to a PVC?

**Question:** PVC manifest doesn't mention PV name. How does the API server know which PV to bind?

**Answer:** The API server matches based on **two main factors**:

### Matching Criteria:

**1. Access Mode:**
- PVC requests a specific access mode (e.g., ReadWriteOnce)
- API server filters PVs that match this access mode

**2. Size:**
- PVC requests a minimum size (e.g., 50GB)
- API server finds PVs with size ≥ 50GB
- "At least" this much size - not exact match

**3. StorageClass Name (optional):**
- If PVC specifies a StorageClass, only PVs with matching StorageClass are considered
- This is an advanced filtering level

### Example Scenario:
- Cluster has 3 PVs: 1GB, 2GB, 3GB (all with same access mode)
- PVC requests 1GB
- API server could give ANY of the three (1GB, 2GB, or 3GB)
- All satisfy the condition: size ≥ 1GB

### Important:
- If all PVs are larger than requested, the best match (or any match) is given
- There's no way to say "give me exactly 1GB"
- PV cannot be split
