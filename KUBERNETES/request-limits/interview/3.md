## What is the difference between Actual Usage and Reservation (Allocated) in Kubernetes?

### Reservation (Allocated):
- **What it is:** Amount of hardware COMMITTED/RESERVED for pods
- **How to check:** `kubectl describe node <node-name>` shows allocated resources
- **Meaning:** Total of all requests from pods on that node
- **Example:** Node has 2 CPU (2000m), and 500m is allocated → 25% reserved

### Actual Usage:
- **What it is:** How much hardware is ACTUALLY being consumed right now
- **How to check:** Requires metrics server (Prometheus, metrics-server)
- **Meaning:** Real-time CPU/memory consumption
- **Example:** Pod requested 500m CPU but is currently using only 200m

### Key Difference:

| Feature | Reservation (Allocated) | Actual Usage |
|---------|------------------------|--------------|
| **Definition** | Committed/hardware promised | Current consumption |
| **Command** | `kubectl describe node` | `kubectl top node` / `kubectl top pod` |
| **Required** | Built-in | Metrics server needed |
| **Analogy** | Train seat booked | Space actually occupied on seat |

### Commands:
```bash
# Check allocated resources on nodes
kubectl describe node <node-name> | grep -A5 "Allocated resources"

# Check actual usage (requires metrics-server)
kubectl top node
kubectl top pod
```
