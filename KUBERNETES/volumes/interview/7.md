## What are the Status Types of PV? When you run `kubectl get pv`, what are the different status types a PV can have?

### Four PV Status Types:

**1. Available:**
- PV is created but NOT yet claimed by any PVC
- First state when PV is created
- Ready to be bound to a PVC

**2. Bound:**
- PV is claimed by a PVC in a namespace
- PV is attached and in use
- No other PVC can claim it

**3. Released:**
- The PVC that bound this PV has been deleted
- PV is NOT available for new claims yet
- Data is still on the volume (with Retain policy)
- Administrator must manually make it Available again

**4. Failed:**
- PV cannot be bound or mounted due to some error
- Reasons: Network connectivity issue to storage, storage backend problem, software-level failure
- When the issue is resolved, PV can recover

### PV State Transitions:

```
Available ──(PVC claims)──► Bound
Bound ──(PVC deleted, Recycle)──► Available (data scrubbed)
Bound ──(PVC deleted, Retain)──► Released (data preserved)
Released ──(Admin manual cleanup)──► Available
Bound/Available ──(Storage error)──► Failed
```

### Key Points from Transcript:

**When does PV go from Bound to Available?**
- When reclaim policy is **Recycle** and PVC is deleted
- Data is scrubbed, PV becomes available for new claims

**When does PV go from Bound to Released?**
- When reclaim policy is **Retain** and PVC is deleted
- Data is preserved, but PV is NOT available for new claims
- Admin must manually run commands to make it Available again

**When does Failed state occur?**
- Storage-side problems (network connectivity, storage backend issues)
- Software-level problems preventing mount
