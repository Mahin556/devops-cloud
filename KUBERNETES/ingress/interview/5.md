### All subdomains of `domain.com` should be handled by a single Ingress with HTTP redirected to HTTPS. TLS certificates managed within Kubernetes.

**Solution:**

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: wildcard-ingress
  annotations:
    # Force HTTPS redirect
    nginx.ingress.kubernetes.io/force-ssl-redirect: "true"
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
spec:
  ingressClassName: nginx
  tls:
  - hosts:
    - "*.domain.com"                  # Wildcard certificate
    secretName: domain-com-wildcard-tls
  rules:
  - host: "*.domain.com"              # Matches all subdomains
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: main-service
            port:
              number: 80
```

**Create Wildcard TLS Secret:**
```bash
kubectl create secret tls domain-com-wildcard-tls \
  --cert=wildcard.domain.com.crt \
  --key=wildcard.domain.com.key
```

**Traffic Flow:**
```
HTTP Request to app.domain.com     → 301 Redirect to HTTPS
HTTPS Request to app.domain.com    → main-service:80
HTTPS Request to admin.domain.com  → main-service:80
HTTPS Request to api.domain.com    → main-service:80
```

**Key Points:**
- Wildcard host `*.domain.com` matches all subdomains
- Single Ingress rule handles unlimited subdomains
- `force-ssl-redirect` annotation enforces HTTPS
- HTTP traffic automatically redirected to HTTPS (301)
- Wildcard TLS certificate covers all subdomains
- One TLS secret for all subdomains
- All subdomain traffic routed to same backend service
- Certificate managed entirely within Kubernetes
