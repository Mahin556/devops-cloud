Yes. These commands show the **complete Spin + Kubernetes installation flow** from the video. The most important thing is to understand **what each section changes** and how everything finally connects to `containerd`.

Think of the whole process as:

```text
Install Spin CLI
      ↓
Prepare Kubernetes for Spin
      ↓
Install Kwasm/node installer
      ↓
Install Spin RuntimeClass
      ↓
Install Spin Operator
      ↓
Install shim executor
      ↓
Deploy Spin application
```

And the final runtime path becomes:

```text
Pod
 ↓
runtimeClassName: spin
 ↓
RuntimeClass
 ↓
handler: spin
 ↓
containerd
 ↓
Spin shim
 ↓
Spin/Wasm runtime
 ↓
WebAssembly application
```

Let's go through **every command**.

---

# 1. Spin installation

```bash
curl -fsSL https://developer.fermyon.com/downloads/install.sh | bash
sudo mv spin /usr/local/bin/
```

## First command

```bash
curl -fsSL https://developer.fermyon.com/downloads/install.sh | bash
```

This downloads and executes the **Spin installation script**.

### What is Spin?

Spin is a platform/runtime for running **WebAssembly applications**.

In this tutorial, Spin is the application/runtime ecosystem that we want Kubernetes to run.

The important thing:

> **Installing the Spin CLI does NOT install the Kubernetes runtime on your nodes.**

It primarily gives you the `spin` command.

For example, after installation:

```bash
spin --help
```

can be used.

---

## Second command

```bash
sudo mv spin /usr/local/bin/
```

This moves the downloaded `spin` executable into:

```text
/usr/local/bin/
```

Because `/usr/local/bin` is normally in the system `PATH`, you can run:

```bash
spin
```

from anywhere.

So this part is:

```text
Your machine
    │
    └── spin CLI
```

It is **not yet**:

```text
Kubernetes node
    │
    └── Spin runtime
```

That's an important distinction.

# 5. What is Kwasm doing?

This is where the earlier `containerd` discussion becomes very important.

Remember your current configuration:

```text
containerd
    │
    └── runc
```

You want to add another execution path:

```text
containerd
    ├── runc
    │
    └── spin
```

Kwasm helps configure the Kubernetes nodes for WebAssembly runtimes.

The important idea is:

> **The Spin runtime/shim needs to be installed/configured on the nodes before a Pod can actually use the Spin RuntimeClass.**

---

# 6. Why the `installerImage` is important

Look at this:

```bash
--set kwasmOperator.installerImage=ghcr.io/spinkube/containerd-shim-spin/node-installer:v0.18.0
```

This tells the Kwasm operator which **node installer image** to use.

Here the installer is specifically associated with:

```text
containerd-shim-spin
```

So conceptually:

```text
Kwasm Operator
      ↓
Node installer
      ↓
Install/configure Spin runtime components
      ↓
containerd
```

This is the part that connects directly to the `containerd` configuration you showed earlier.

# 7. Annotating the nodes

```bash
kubectl annotate node --all kwasm.sh/kwasm-node=true
```

This adds an annotation to **all Kubernetes nodes**:

```text
kwasm.sh/kwasm-node=true
```

Why?

Because the Kwasm operator watches for these node annotations.

Conceptually:

```text
Node
  │
  └── annotation:
      kwasm.sh/kwasm-node=true
                │
                ▼
          Kwasm Operator
                │
                ▼
       Node installation
                │
                ▼
     Spin shim/runtime setup
```

So this is effectively telling Kwasm:

> "These nodes should be configured for WebAssembly."

Next:

```bash
kubectl apply -f https://github.com/spinkube/spin-operator/releases/download/v0.4.0/spin-operator.crds.yaml
```

# 11. First command — CRDs

```bash
kubectl apply -f .../spin-operator.crds.yaml
```

This installs the **CustomResourceDefinitions** used by SpinKube.

Remember:

```text
Kubernetes built-in resources
-----------------------------
Pod
Deployment
Service
ConfigMap
...
```

SpinKube wants to introduce its own Kubernetes API resources.

For example, a Spin application can be represented using a custom resource.

CRDs extend the Kubernetes API:

```text
Kubernetes API
      │
      ├── Pod
      ├── Deployment
      ├── Service
      │
      └── SpinApp       ← custom resource
```

---

# 12. What is a CRD?

CRD = **CustomResourceDefinition**

It allows you to teach Kubernetes about a new resource type.

For example:

```yaml
kind: SpinApp
```

normally Kubernetes doesn't know what `SpinApp` means.

After the CRD is installed:

```text
Kubernetes
     │
     └── knows about SpinApp
```

Then you can do:

```bash
kubectl get spinapp
```

depending on the installed API.

---

# 13. Second command — RuntimeClass

```bash
kubectl apply -f https://github.com/spinkube/spin-operator/releases/download/v0.4.0/spin-operator.runtime-class.yaml
```

This creates the RuntimeClass required by SpinKube.

This is **extremely important** for what we've been discussing.

Conceptually, it creates something like:

```yaml
apiVersion: node.k8s.io/v1

metadata:
  name: spin-v2

```

The exact manifest should be treated according to that specific SpinKube version, but the important relationship is:

```text
RuntimeClass
      │
      └── handler: spin
```

# 16. What is an Operator?

A Kubernetes Operator is software that watches Kubernetes resources and performs actions based on them.

Think:

```text
You create:
SpinApp
   │
   ▼
Spin Operator
   │
   ├── Deployment
   ├── Service
   └── other required resources
```

So instead of manually creating all the Kubernetes resources required by the Spin application, the operator handles that work.

---

# 17. Why `--namespace spin-operator`?

```bash
--namespace spin-operator
```

This installs the operator into:

```text
spin-operator
```

namespace.

---

# 18. Why `--create-namespace`?

```bash
--create-namespace
```

If the namespace doesn't exist, Helm creates it.

So you don't need:

```bash
kubectl create namespace spin-operator
```

separately.

---

# 19. Why `--version 0.4.0`?

```bash
--version 0.4.0
```

You are explicitly installing Spin Operator version `0.4.0`.

This is important because different versions can have different manifests, APIs, configuration, and compatibility.

---

# 20. Why `--wait`?

```bash
--wait
```

Helm waits for the resources to become ready rather than immediately returning after creating them.

So conceptually:

```text
helm install
     ↓
create resources
     ↓
wait for readiness
     ↓
return
```

---

# 21. Why `oci://`?

```text
oci://ghcr.io/spinkube/charts/spin-operator
```

This tells Helm that the chart is being retrieved through an **OCI registry**.

You don't need to confuse this with the earlier:

```bash
helm repo add
```

because they are two different mechanisms.

# 22. Shim executor

Next:

```bash
kubectl apply -f https://github.com/spinkube/spin-operator/releases/download/v0.4.0/spin-operator.shim-executor.yaml
```

This installs the **shim executor** configuration used by the Spin Operator setup.

This is directly related to the runtime architecture we've been discussing.

Remember:

```text
containerd
    ↓
shim
    ↓
runtime
```

The shim is the bridge between containerd and the specialized runtime.

So the setup needs to make sure the required shim functionality is available to the nodes.

---

# 23. Why do we need a shim?

Without the shim path:

```text
containerd
     ↓
????
```

containerd doesn't have the appropriate mechanism to invoke the Spin/WebAssembly runtime.

With the shim:

```text
containerd
     ↓
Spin shim
     ↓
Wasm runtime
```

That's why your earlier question:

> "Do we need to change the shim and low-level runtime?"

was close, but the better understanding is:

**We add/configure another shim/runtime path; we don't replace the existing runc path.**

# 28. What each component is responsible for

This is probably the **best table for your notes**:

| Component           | Main job                                                              |
| ------------------- | --------------------------------------------------------------------- |
| **Spin CLI**        | Command-line tool for creating/managing Spin applications             |
| **Spin**            | WebAssembly application/runtime ecosystem                             |
| **Kwasm Operator**  | Helps prepare Kubernetes nodes for WebAssembly runtimes               |
| **Node installer**  | Installs/configures required runtime components on nodes              |
| **containerd**      | High-level container runtime on the node                              |
| **runc**            | Default runtime path for normal containers                            |
| **Spin shim**       | Connects containerd to the Spin/Wasm runtime                          |
| **RuntimeClass**    | Kubernetes mechanism for selecting a runtime handler                  |
| **`handler: spin`** | Connects RuntimeClass to the `spin` runtime handler                   |
| **Spin Operator**   | Converts/manages Spin application resources into Kubernetes workloads |
| **CRD**             | Extends Kubernetes API with Spin-specific resources                   |
| **cert-manager**    | Certificate management                                                |
| **shim executor**   | Supports execution of the required shim/runtime setup                 |
| **Service**         | Provides network access to the application                            |
| **port-forward**    | Temporarily exposes the Service through your local machine            |

# 29. Most important distinction: three different layers

Don't mix these three.

## Layer 1 — Kubernetes API

```text
SpinApp
RuntimeClass
Pod
Deployment
Service
```

## Layer 2 — Container runtime

```text
containerd
    │
    ├── runc handler
    │
    └── spin handler
```

## Layer 3 — Actual execution

```text
runc handler
     ↓
runc
     ↓
Linux container
```

or:

```text
spin handler
     ↓
Spin shim
     ↓
Wasm runtime
     ↓
Wasm application
```

Your original screenshot showed:

```toml
default_runtime_name = "runc"
```

and:

```toml
[plugins."io.containerd.grpc.v1.cri".containerd.runtimes.runc]
```

```text
Spin shim
      ↓
Wasm runtime
```

That is the **entire reason RuntimeClass is needed in this example**.
