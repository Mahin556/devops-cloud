# Complete End-to-End Tutorial: Modifying Cluster DNS and Recreating Core Services in New CIDR

This tutorial walks through changing the service CIDR of a Kubernetes cluster, updating DNS, recreating core services, and ensuring everything works correctly.

## Prerequisites
- Kubernetes cluster (kubeadm installed)
- Root/sudo access to controlplane node
- Basic understanding of Kubernetes networking

## Step 1: Initial State Verification

Check current services and their IPs:

```bash
# Check all services in the cluster
kubectl get svc -A

# Check current service CIDRs
kubectl get servicecidrs

# Check CoreDNS deployment status
kubectl get pods -n kube-system | grep coredns

# Note the current kubernetes service IP (usually 10.96.0.1)
kubectl get svc -n default kubernetes
```

## Step 2: Modify API Server to Use New Service CIDR

Edit the kube-apiserver manifest to change the service-cluster-ip-range:

```bash
# Backup the current manifest
cp /etc/kubernetes/manifests/kube-apiserver.yaml /etc/kubernetes/manifests/kube-apiserver.yaml.bak

# Edit the manifest
vi /etc/kubernetes/manifests/kube-apiserver.yaml
```

Find and modify the `--service-cluster-ip-range` flag:
```yaml
spec:
  containers:
  - command:
    - kube-apiserver
    - --service-cluster-ip-range=100.96.0.0/12    # Change from 10.96.0.0/12 to new range
```

Save the file. The API server will automatically restart.

## Step 3: Verify API Server Restart

```bash
# Watch the API server pod restart
kubectl get pods -n kube-system -w | grep kube-apiserver

# Check API server is running
kubectl get pods -n kube-system | grep kube-apiserver

# Verify new service CIDR is active
kubectl cluster-info dump | grep service-cluster-ip-range
```

## Step 4: Delete Existing Core Services

Now remove services that have old IPs from the previous CIDR:

```bash
# Delete the kube-dns service (CoreDNS)
kubectl -n kube-system delete svc kube-dns

# Delete the default kubernetes service
kubectl -n default delete svc kubernetes

# Verify they're deleted
kubectl get svc -A | grep -E "kube-dns|kubernetes"
```

## Step 5: Remove and Recreate ServiceCIDR Object

```bash
# Check existing servicecidrs
kubectl get servicecidrs

# Delete the kubernetes servicecidr object
kubectl delete servicecidrs kubernetes

# Verify it's gone
kubectl get servicecidrs

# Wait a few seconds for the API server to recreate it with new CIDR
sleep 5

# Check the recreated servicecidr
kubectl get servicecidrs kubernetes -o yaml
```

## Step 6: Recreate kube-dns Service

Create the CoreDNS service with a fresh ClusterIP from the new CIDR:

```bash
cat <<'EOF' | kubectl create -f -
apiVersion: v1
kind: Service
metadata:
  labels:
    k8s-app: kube-dns
    kubernetes.io/cluster-service: "true"
    kubernetes.io/name: CoreDNS
  name: kube-dns
  namespace: kube-system
spec:
  ports:
  - name: dns
    port: 53
    protocol: UDP
    targetPort: 53
  - name: dns-tcp
    port: 53
    protocol: TCP
    targetPort: 53
  - name: metrics
    port: 9153
    protocol: TCP
    targetPort: 9153
  selector:
    k8s-app: kube-dns
  type: ClusterIP
EOF
```

## Step 7: Verify Services Got New IPs

```bash
# Check both services now have IPs in the new range (100.96.0.0/12)
kubectl get svc -A

# Expected output similar to:
# NAMESPACE     NAME         TYPE        CLUSTER-IP       EXTERNAL-IP   PORT(S)
# default       kubernetes   ClusterIP   100.96.0.1       <none>        443/TCP
# kube-system   kube-dns     ClusterIP   100.96.x.x       <none>        53/UDP,53/TCP,9153/TCP
```

## Step 8: Capture New Service IPs

```bash
# Capture the new kubernetes service IP
NEW_SERVICE_IP=$(kubectl -n default get svc kubernetes -o jsonpath='{.spec.clusterIP}')
echo "New kubernetes service IP: ${NEW_SERVICE_IP}"

# Get the old service IP from backup (if needed)
OLD_SERVICE_IP="10.96.0.1"

# Get the API server advertise address
APISERVER_IP=$(grep -oP '(?<=--advertise-address=)[^\", ]+' /etc/kubernetes/manifests/kube-apiserver.yaml | head -n1)
echo "API server advertise address: ${APISERVER_IP}"
```

## Step 9: Regenerate API Server Certificate

The certificate needs to include the new service IP as a Subject Alternative Name (SAN):

```bash
# Backup existing certificates
cp /etc/kubernetes/pki/apiserver.crt /etc/kubernetes/pki/apiserver.crt.bak
cp /etc/kubernetes/pki/apiserver.key /etc/kubernetes/pki/apiserver.key.bak

# Remove old certificates
rm /etc/kubernetes/pki/apiserver.crt /etc/kubernetes/pki/apiserver.key

# Regenerate apiserver certificate with new SANs
kubeadm init phase certs apiserver \
  --apiserver-advertise-address="${APISERVER_IP}" \
  --apiserver-cert-extra-sans="${APISERVER_IP},${OLD_SERVICE_IP},${NEW_SERVICE_IP}"

# Verify the new certificate includes the new IP
openssl x509 -in /etc/kubernetes/pki/apiserver.crt -text -noout | grep -A1 "X509v3 Subject Alternative Name"
```

## Step 10: Verify API Server Restart with New Certificate

```bash
# Check API server pod status
kubectl get pods -n kube-system | grep kube-apiserver

# Watch for restart (may take a minute)
kubectl get pods -n kube-system -w | grep kube-apiserver

# Verify API server is healthy
kubectl get nodes
```

## Step 11: Restart CNI Plugin (Canal)

```bash
# Restart Canal daemonset to pick up new kubernetes service IP
kubectl -n kube-system rollout restart daemonset/canal

# Watch rollout status
kubectl -n kube-system rollout status daemonset/canal

# Verify Canal pods are running
kubectl get pods -n kube-system | grep canal
```

## Step 12: Restart CoreDNS

```bash
# Restart CoreDNS deployment
kubectl -n kube-system rollout restart deployment/coredns

# Watch rollout status
kubectl -n kube-system rollout status deployment/coredns

# Verify CoreDNS pods are running
kubectl get pods -n kube-system | grep coredns
```

## Step 13: Validate DNS Resolution

Create a test pod to verify DNS is working:

```bash
# Create a test pod
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: dns-test
spec:
  containers:
  - name: busybox
    image: busybox:1.28
    command: ['sh', '-c', 'echo "DNS test pod running"; sleep 3600']
  restartPolicy: Never
EOF

# Wait for pod to run
kubectl wait --for=condition=ready pod/dns-test --timeout=60s

# Test DNS resolution
kubectl exec dns-test -- nslookup kubernetes.default
kubectl exec dns-test -- nslookup google.com
kubectl exec dns-test -- cat /etc/resolv.conf

# Clean up test pod
kubectl delete pod dns-test
```

## Step 14: Test API Server Connectivity

```bash
# Test from within a pod
kubectl run curl-test --image=curlimages/curl --rm -it --restart=Never -- \
  curl -k https://kubernetes.default.svc.cluster.local

# Check kube-proxy is working
kubectl get pods -n kube-system | grep kube-proxy
kubectl -n kube-system rollout restart daemonset/kube-proxy
```

## Step 15: Final Verification

```bash
# Get all services with their new IPs
kubectl get svc -A -o wide

# Check endpoints are populated
kubectl get endpoints -A

# Verify CoreDNS config
kubectl get configmap -n kube-system coredns -o yaml

# Check DNS logs
kubectl logs -n kube-system -l k8s-app=kube-dns --tail=20

# Run a comprehensive DNS test
cat <<EOF | kubectl run -it --rm dns-utils --image=registry.k8s.io/e2e-test-images/jessie-dnsutils:1.3 --restart=Never -- /bin/bash -c "cat /etc/resolv.conf; nslookup kubernetes.default; nslookup google.com"
EOF
```

## Troubleshooting Common Issues

### If pods can't resolve DNS:

```bash
# Check CoreDNS logs
kubectl logs -n kube-system -l k8s-app=kube-dns

# Check if kube-dns service has endpoints
kubectl get endpoints -n kube-system kube-dns

# Restart CoreDNS again
kubectl -n kube-system delete pods -l k8s-app=kube-dns
```

### If API server certificate errors occur:

```bash
# Verify certificate SANs
openssl x509 -in /etc/kubernetes/pki/apiserver.crt -text | grep -A1 "Subject Alternative Name"

# Check API server logs
kubectl logs -n kube-system kube-apiserver-controlplane --tail=50
```

### If services don't get IPs from new range:

```bash
# Check servicecidr object
kubectl get servicecidrs kubernetes -o yaml

# Manually edit if needed
kubectl edit servicecidrs kubernetes
```

## Clean Up (if needed)

To revert to original configuration:

```bash
# Restore original API server manifest
cp /etc/kubernetes/manifests/kube-apiserver.yaml.bak /etc/kubernetes/manifests/kube-apiserver.yaml

# Restore original certificates
cp /etc/kubernetes/pki/apiserver.crt.bak /etc/kubernetes/pki/apiserver.crt
cp /etc/kubernetes/pki/apiserver.key.bak /etc/kubernetes/pki/apiserver.key

# Delete and let services recreate with old CIDR
kubectl -n kube-system delete svc kube-dns
kubectl -n default delete svc kubernetes
kubectl delete servicecidrs kubernetes

# Restart components
kubectl -n kube-system rollout restart daemonset/canal
kubectl -n kube-system rollout restart deployment/coredns
```

## Summary

You've successfully:
1. Changed the cluster's service CIDR range
2. Recreated core services (kubernetes and kube-dns) with new IPs
3. Regenerated API server certificates to include new service IPs
4. Restarted CNI plugin and CoreDNS to use the new configuration
5. Verified DNS resolution is working correctly

The cluster should now be fully functional with the new service CIDR range!
