## Hands-On Exercise (Test it yourself!)

We will deploy a test pod, apply the policy, and prove that it can browse the internet but **cannot** reach internal cluster resources.

### Step 1: Setup the environment
```bash
# Create the test namespace
kubectl create namespace internet-test

# Label it (just for good practice, though not strictly needed)
kubectl label namespace internet-test kubernetes.io/metadata.name=internet-test

# Deploy a dummy "internal" Nginx service (to simulate a database/microservice)
kubectl create deployment internal-app -n internet-test --image=nginx --port=80
kubectl expose deployment internal-app -n internet-test --port=80 --target-port=80 --name=internal-service

# Deploy the TEST pod (this is the one we will apply the policy to)
kubectl run client-pod -n internet-test --image=busybox:latest --labels="app=external-client" --rm -it --restart=Never -- /bin/sh
# (This will drop you into a shell. Keep this terminal open. If it exits, re-run without --rm)
```
**Wait!** To keep it running in the background for testing, run this instead:
```bash
kubectl run client-pod -n internet-test --image=busybox:latest --labels="app=external-client" -- sleep infinity
kubectl exec -it client-pod -n internet-test -- /bin/sh
```

### Step 2: Apply the NetworkPolicy
In a **new terminal** (while your `client-pod` shell is open):
```bash
kubectl apply -f internet-only-policy.yaml
```

### Step 3: Run the Tests from inside `client-pod`

Inside the `client-pod` shell (`/bin/sh`), run the following commands:

| Test Command | Expected Result | Why? |
| :--- | :--- | :--- |
| `nslookup google.com` | ✅ **Success** (returns IP) | **Rule 1** allows DNS to CoreDNS. |
| `wget -O- http://google.com` | ✅ **Success** (downloads HTML) | Public IP (8.8.8.8) + Port 80 matches **Rule 2**. |
| `wget -O- https://cloudflare.com` | ✅ **Success** (downloads HTML) | Public IP + Port 443 matches **Rule 2**. |
| `wget -O- http://internal-service:80` | ❌ **Fails** (Connection timed out) | ClusterIP (e.g., `10.96.x.x`) is in `10.0.0.0/8`, which is **excluded** by Rule 2. |
| `wget -O- http://<pod-ip-of-internal-app>:80` | ❌ **Fails** (e.g., `10.244.1.5` is blocked) | Same reason – Pod IPs are in the excluded `10.0.0.0/8` range. |
| `wget -O- https://kubernetes.default.svc:443` | ❌ **Fails** (Connection timed out) | API Server ClusterIP (`10.96.0.1`) is excluded. |

## Part 3: Bonus Exercise – Allow External Traffic *INTO* the Pod

Your earlier quote mentioned the `ingress` rule. Let's add that to your YAML (only if you want external clients to connect *to* this pod on port 80).

**Updated YAML** (adds an `ingress` section):
```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: internet-only-egress
  namespace: internet-test
spec:
  podSelector:
    matchLabels:
      app: external-client
  policyTypes:
  - Egress
  - Ingress                      # <-- ADD THIS
  ingress:
  - from:
    - ipBlock:
        cidr: 0.0.0.0/0          # Allows ANY external IPv4 to connect
    ports:
    - protocol: TCP
      port: 80                   # Only port 80 is open to the world
  egress:
  # ... (keep the egress rules exactly as above)
```

**Test it:**
1. Apply the updated policy: `kubectl apply -f internet-only-policy.yaml`
2. In a separate terminal, port-forward to your pod:
   ```bash
   kubectl port-forward pod/client-pod -n internet-test 8080:80
   ```
3. Open your browser or use `curl` from your host machine:
   ```bash
   curl http://localhost:8080
   ```
   Since the pod is running `busybox` (which doesn't have a web server), this will likely *fail* with `connection refused` **unless** you install an HTTP server inside. 
   **Better test**: Change your test pod to `nginx`:
   ```bash
   kubectl delete pod client-pod -n internet-test
   kubectl run client-pod -n internet-test --image=nginx --labels="app=external-client" --port=80
   kubectl port-forward pod/client-pod -n internet-test 8080:80
   ```
   Now `curl http://localhost:8080` will show the Nginx welcome page, proving the `ingress` rule allowed the traffic from your host (which is an external IPv4 address) to reach the pod.
