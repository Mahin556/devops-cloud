# Trivy — Scanning a Git Repository

## Two Ways to Scan a Git Repo

| Method | Command | Use case |
|--------|---------|----------|
| **Remote URL** | `trivy repo https://github.com/user/repo` | Scan any public/private remote repo |
| **Local clone** | `trivy fs .` | Scan already cloned repo on disk |

---

## Remote Repo Scan

```bash
# Scan a public GitHub repo
trivy repo https://github.com/user/repo-name

# Scan a specific branch
trivy repo --branch main https://github.com/user/repo-name

# Scan a specific tag
trivy repo --tag v1.2.0 https://github.com/user/repo-name

# Scan a specific commit
trivy repo --commit a1b2c3d https://github.com/user/repo-name
```

## What Trivy Scans in a Repo

```
your-repo/
├── app/
│   ├── config.py          ← secrets (hardcoded API keys, passwords)
│   └── settings.json      ← secrets (tokens, credentials)
├── .env                   ← secrets (DB_PASSWORD, AWS_SECRET)
├── requirements.txt       ← vuln (pip dependency versions)
├── package.json           ← vuln (npm dependency versions)
├── go.mod                 ← vuln (Go module versions)
├── pom.xml                ← vuln (Maven dependency versions)
├── Dockerfile             ← misconfig (bad practices)
├── k8s/
│   └── deployment.yaml    ← misconfig (privileged containers, etc.)
└── terraform/
    └── main.tf            ← misconfig (open S3 buckets, no encryption)
```

## Scanners — What to Enable

```bash
# Default — vulnerabilities only
trivy repo https://github.com/user/repo

# Secrets only (fastest)
trivy repo --scanners secret https://github.com/user/repo

# Vulns + Secrets (recommended baseline)
trivy repo --scanners vuln,secret https://github.com/user/repo

# Full scan — everything
trivy repo --scanners vuln,secret,misconfig,license https://github.com/user/repo
```

## Private Repo — Authentication

### GitHub (HTTPS with token)

```bash
# Set token as env variable
export GITHUB_TOKEN=ghp_yourPersonalAccessToken

trivy repo https://github.com/your-org/private-repo
```

### GitHub (SSH)

```bash
# Trivy uses your existing SSH config automatically
trivy repo git@github.com:your-org/private-repo.git
```

### GitLab

```bash
export GITLAB_TOKEN=glpat_yourToken

trivy repo https://gitlab.com/your-org/private-repo
```

### Bitbucket

```bash
export BITBUCKET_USERNAME=your-username
export BITBUCKET_PASSWORD=your-app-password

trivy repo https://bitbucket.org/your-org/private-repo
```

## Output Formats

```bash
# Table (default — human readable)
trivy repo --format table https://github.com/user/repo

# JSON — pipe into other tools
trivy repo --format json --output report.json https://github.com/user/repo

# SARIF — upload to GitHub Code Scanning
trivy repo --format sarif --output trivy.sarif https://github.com/user/repo

# Filter by severity
trivy repo --severity HIGH,CRITICAL https://github.com/user/repo

# Exit code 1 if CRITICAL found — use in CI gates
trivy repo --exit-code 1 --severity CRITICAL https://github.com/user/repo
```

## Skip / Ignore

```bash
# Skip directories (vendor, test data, node_modules)
trivy repo --skip-dirs vendor,node_modules,tests/fixtures \
  https://github.com/user/repo

# Skip specific files
trivy repo --skip-files "*.test.js,mock_creds.json" \
  https://github.com/user/repo

# Use .trivyignore to suppress known false positives
# Create a .trivyignore in your repo root:
# CVE-2023-1234
# aws-access-key  ← suppress a whole rule
trivy repo --ignorefile .trivyignore https://github.com/user/repo
```

## GitHub Actions — CI/CD Integration

```yaml
# .github/workflows/trivy.yml

name: Trivy security scan

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  trivy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Run Trivy repo scan
        uses: aquasecurity/trivy-action@master
        with:
          scan-type: fs
          scan-ref: .
          scanners: vuln,secret,misconfig
          severity: HIGH,CRITICAL
          format: sarif
          output: trivy-results.sarif
          exit-code: 1

      - name: Upload SARIF to GitHub Security tab
        uses: github/codeql-action/upload-sarif@v3
        if: always()
        with:
          sarif_file: trivy-results.sarif
```

> Results appear in **GitHub → Security → Code Scanning** tab automatically.

## `trivy repo` vs `trivy fs` vs `trivy image`

| | `trivy repo` | `trivy fs` | `trivy image` |
|--|--------------|------------|---------------|
| **Input** | Remote Git URL | Local directory | Docker image |
| **Clones repo** | Yes — automatically | No (already local) | No |
| **Branch / tag support** | Yes | No | Via image tag |
| **Secret detection** | Yes | Yes | Yes (baked-in secrets) |
| **IaC scanning** | Yes | Yes | No |
| **Vuln scanning** | Yes | Yes | Yes |
| **Best for** | Auditing any repo | Pre-commit / local dev | Post-build gate |

## Quick Reference

```bash
# Scan remote repo — all scanners
trivy repo --scanners vuln,secret,misconfig \
  https://github.com/user/repo

# Scan private repo with token
GITHUB_TOKEN=ghp_xxx trivy repo \
  --scanners vuln,secret \
  https://github.com/your-org/private-repo

# Scan specific branch, critical only
trivy repo --branch develop \
  --severity CRITICAL \
  --exit-code 1 \
  https://github.com/user/repo

# Full scan with JSON report
trivy repo --scanners vuln,secret,misconfig \
  --format json \
  --output report.json \
  https://github.com/user/repo
```
