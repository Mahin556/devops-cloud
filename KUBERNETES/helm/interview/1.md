### How to configure a microservice differently in dev and prod without duplicating the deployment YAML file.

**Challenge:** Different environments need different configurations (log levels, DB URLs), but you want to maintain a single deployment YAML, not separate files.

**Solution - Helm Templating:**

**Step 1 - Create values.yaml with environment-specific settings:**
```yaml
# values.yaml
environments:
  dev:
    LOG_LEVEL: "debug"
    DB_URL: "dev-db.example.com"
    REPLICAS: 1
  prod:
    LOG_LEVEL: "error"
    DB_URL: "prod-db.example.com"
    REPLICAS: 3
```

**Step 2 - Use Helm variables in deployment YAML:**
```yaml
# templates/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-microservice
spec:
  replicas: {{ .Values.replicas }}
  selector:
    matchLabels:
      app: my-microservice
  template:
    metadata:
      labels:
        app: my-microservice
    spec:
      containers:
      - name: app
        image: myapp:latest
        env:
        - name: LOG_LEVEL
          value: {{ .Values.LOG_LEVEL }}
        - name: DB_URL
          value: {{ .Values.DB_URL }}
```

**Step 3 - Deploy with environment context in CD pipeline:**
```bash
# For dev
helm install my-app ./chart --set environment=dev

# For prod
helm install my-app ./chart --set environment=prod
```

**Key Points:**
- **Helm templating** is the feature for managing environment-specific configurations
- Single deployment template, different values per environment
- No hardcoding of environment-specific values
- Values auto-fill based on deployment context
- Easy integration with CI/CD pipelines
