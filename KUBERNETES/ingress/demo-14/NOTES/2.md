Regular Expressions (**Regex**) are a language used to **describe patterns in text** rather than exact text.

Instead of saying:

> Match exactly `/api/users`

you can say:

> Match **any** URL that starts with `/api/` and has anything after it.

Regex is widely used in:

* Kubernetes Ingress (NGINX)
* NGINX
* Linux (`grep`, `sed`, `awk`)
* Python, Go, JavaScript, Java
* Log processing
* Input validation
* Search and replace

---

# Why use Regex?

Suppose you have these URLs:

```text
/api/user
/api/admin
/api/payment
/api/order
/api/profile
```

Without regex, you'd need five separate rules:

```text
/api/user
/api/admin
/api/payment
...
```

With regex, one rule can match all of them.

```regex
/api/.*
```

---

# How regex works

Regex is read from left to right.

Example:

```regex
abc
```

matches only

```text
abc
```

# Special Characters

These are the building blocks of regex.

---

## `.` (Dot)

Means

> Match **any single character**

Regex

```regex
a.c
```

Matches

```text
abc
axc
a1c
a-c
```

Does NOT match

```text
ac
abbc
```

---

## `*` (Zero or more)

Means

> Repeat the previous character zero or more times

Regex

```regex
ab*c
```

Matches

```text
ac
abc
abbc
abbbc
abbbbbbbbbc
```

Does NOT match

```text
abdc
```

---

## `+` (One or more)

Regex

```regex
ab+c
```

Matches

```text
abc
abbc
abbbc
```

Does NOT match

```text
ac
```

Difference:

```text
*  → 0 or more
+  → 1 or more
```

---

## `?` (Optional)

Regex

```regex
colou?r
```

Matches

```text
color
colour
```

---

## Character Classes `[ ]`

Match one character from a set.

Regex

```regex
[abc]
```

Matches

```text
a
b
c
```

Not

```text
d
```

---

### Range

```regex
[a-z]
```

Matches

```text
a
b
c
...
z
```

---

```regex
[A-Z]
```

Uppercase letters

---

```regex
[0-9]
```

Digits

---

Example

```regex
[a-z][0-9]
```

Matches

```text
a1
x5
k9
```

---

## Negation

```regex
[^0-9]
```

Means

> NOT a digit

Matches

```text
a
X
@
_
```

# Anchors

---

## `^`

Beginning of string

Regex

```regex
^hello
```

Matches

```text
hello world
```

Not

```text
say hello
```

---

## `$`

End of string

Regex

```regex
world$
```

Matches

```text
hello world
```

Not

```text
world hello
```

---

Both together

```regex
^hello$
```

Matches ONLY

```text
hello
```

Nothing else.

---

# Groups `( )`

Example

```regex
(cat|dog)
```

Matches

```text
cat
dog
```

---

Example

```regex
/(login|signup)
```

Matches

```text
/login
/signup
```

---

# OR `|`

Regex

```regex
red|blue
```

Matches

```text
red
blue
```

---

# Quantifiers

Exactly 3

```regex
[0-9]{3}
```

Matches

```text
123
999
```

---

Between 2 and 5

```regex
[a-z]{2,5}
```

Matches

```text
ab
abc
hello
```

---

At least 3

```regex
[a-z]{3,}
```

---

# Escape `\`

Suppose you want

```text
.
```

instead of

> any character

Use

```regex
\.
```

Similarly

```regex
\+
\*
\?
\$
```

# `.*`

Most important pattern.

```
.
```

means

> any character

```
*
```

means

> any number

Together

```regex
.*
```

means

> anything

Examples

```text
abc
123
hello
abc123xyz
```

Everything matches.

# URL Examples

Regex

```regex
/api/.*
```

Matches

```text
/api/
/api/user
/api/orders
/api/v1/products
```

---

Regex

```regex
/images/.*\.jpg
```

Matches

```text
/images/a.jpg
/images/b.jpg
/images/photo.jpg
```

Not

```text
/images/a.png
```

# Kubernetes Ingress

Example

```yaml
annotations:
  nginx.ingress.kubernetes.io/use-regex: "true"

paths:
- path: /api/.*
  pathType: ImplementationSpecific
```

Requests

```text
/api
/api/
/api/users
/api/orders
/api/v1
```

All go to the same backend.

---

Another example

```regex
/v[0-9]+
```

Matches

```text
/v1
/v2
/v99
```

Not

```text
/version
```

# Email Regex

Simplified

```regex
^[a-zA-Z0-9._]+@[a-zA-Z]+\.[a-z]+$
```

Matches

```text
john@gmail.com
abc123@yahoo.com
```

# IP Address (simple)

```regex
^[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+$
```

Matches

```text
192.168.1.1
```

# Common Regex Cheat Sheet

| Pattern  | Meaning                      | Example Match                 |          |      |
| -------- | ---------------------------- | ----------------------------- | -------- | ---- |
| `.`      | Any single character         | `a`, `1`, `_`                 |          |      |
| `*`      | Zero or more of previous     | `ab*c` → `ac`, `abc`, `abbc`  |          |      |
| `+`      | One or more of previous      | `ab+c` → `abc`, `abbc`        |          |      |
| `?`      | Zero or one of previous      | `colou?r` → `color`, `colour` |          |      |
| `[abc]`  | One of `a`, `b`, or `c`      | `a`                           |          |      |
| `[a-z]`  | Lowercase letter             | `m`                           |          |      |
| `[0-9]`  | Digit                        | `7`                           |          |      |
| `[^a-z]` | Not a lowercase letter       | `A`, `5`                      |          |      |
| `^`      | Start of string              | `^api` matches `api/v1`       |          |      |
| `$`      | End of string                | `log$` matches `error.log`    |          |      |
| `        | `                            | OR                            | `cat     | dog` |
| `( )`    | Group expressions            | `(login                       | signup)` |      |
| `{n}`    | Exactly `n` times            | `[0-9]{4}`                    |          |      |
| `{m,n}`  | Between `m` and `n` times    | `[a-z]{2,5}`                  |          |      |
| `\.`     | Literal dot                  | `file\.txt`                   |          |      |
| `.*`     | Any number of any characters | `/api/.*`                     |          |      |

### Regex in ingress-nginx

When using `pathType: ImplementationSpecific` with:

```yaml
annotations:
  nginx.ingress.kubernetes.io/use-regex: "true"
```

the `path` field is interpreted as a regular expression by NGINX. For example:

```yaml
path: /api/v[0-9]+/.*
```

matches:

```text
/api/v1/users
/api/v2/orders
/api/v10/products
```

but does **not** match:

```text
/api/version/users
/api/v/users
```

This lets you route groups of related URLs with a single Ingress rule instead of creating many individual path entries.
