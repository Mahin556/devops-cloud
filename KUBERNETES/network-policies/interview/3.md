## 26. What is a Network Policy in Kubernetes?

A Network Policy in Kubernetes is a security mechanism that controls how Pods communicate with:
  * Other Pods
  * Namespaces
  * External network endpoints

It acts like a:
  * Firewall for Pods at:
    * Layer 3 (IP)
    * Layer 4 (Port)

---

# Why Network Policies Are Needed

By default in Kubernetes:

* All Pods can communicate with each other freely.

This is not secure for production environments.

Network Policies help implement:

* Zero Trust Networking

by restricting traffic only to allowed communication paths.

---

# What Network Policies Control

Network Policies can define:

| Traffic Type | Purpose                    |
| ------------ | -------------------------- |
| Ingress      | Incoming traffic to Pods   |
| Egress       | Outgoing traffic from Pods |

---

# Example Use Case

Suppose:

* Frontend Pods should talk to Backend Pods
* Backend Pods should talk to Database Pods
* Frontend should NOT directly access Database

Network Policies enforce these communication boundaries.

---

# Basic Example

## Allow Only Frontend Pods to Access Backend

```yaml id="5m2p8"
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy

metadata:
  name: allow-frontend

spec:
  podSelector:
    matchLabels:
      app: backend

  policyTypes:
  - Ingress

  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: frontend
```

---

# How This Works

```text id="8k1n4"
Frontend Pod  → Backend Pod ✅

Other Pods    → Backend Pod ❌
```

Only Pods with:

* `app=frontend`

can access:

* Backend Pods

---

# Important Components

| Field         | Purpose                  |
| ------------- | ------------------------ |
| `podSelector` | Select target Pods       |
| `ingress`     | Allowed incoming traffic |
| `egress`      | Allowed outgoing traffic |
| `policyTypes` | Traffic direction        |

---

# Ingress vs Egress

| Type    | Controls         |
| ------- | ---------------- |
| Ingress | Incoming traffic |
| Egress  | Outgoing traffic |

---

# Important Behavior

Once a Network Policy selects a Pod:

* All other traffic becomes denied by default
* Unless explicitly allowed

This creates:

* Default deny behavior

---

# Real-World Examples

## Restrict Database Access

Allow only backend Pods to connect to database Pods.

---

## Namespace Isolation

Prevent communication between different teams/projects.

---

## Internet Access Restrictions

Block Pods from accessing external internet services.

---

# Dependency on CNI Plugin

Network Policies require a CNI plugin that supports them.

Examples:

* Calico
* Cilium
* Weave Net

Not all CNIs support Network Policies.

---

# Relationship with Other Kubernetes Networking Components

| Component      | Purpose                         |
| -------------- | ------------------------------- |
| Service        | Connectivity and load balancing |
| Ingress        | HTTP/HTTPS routing              |
| Network Policy | Security filtering              |

# High-Level Traffic Flow

```text id="3x7q2"
Request

   ↓

   ↓
Allowed or Denied
```

# Benefits of Network Policies

* Improved security

# Interview-Ready Answer

“A Network Policy in Kubernetes is a security resource that controls how Pods communicate with each other and with external endpoints. It works like a firewall at the IP and port level, defining ingress and egress traffic rules for selected Pods. By default, Pods can communicate freely, but Network Policies help implement a zero-trust model by allowing only explicitly permitted traffic.”
