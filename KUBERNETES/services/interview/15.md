### Frontend needs to communicate with backend using a stable internal DNS name. Backend should not be exposed outside the cluster.

**Solution:**

**Backend Deployment:**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: backend-deployment
spec:
  replicas: 2
  selector:
    matchLabels:
      app: backend
  template:
    metadata:
      labels:
        app: backend
    spec:
      containers:
      - name: backend
        image: nodejs-backend:latest
        ports:
        - containerPort: 8080
```

**Backend ClusterIP Service:**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: backend-service                # DNS: backend-service.<namespace>.svc.cluster.local
spec:
  type: ClusterIP                      # Internal only, no external exposure
  selector:
    app: backend
  ports:
  - port: 80                           # Service port
    targetPort: 8080                   # Container port
    protocol: TCP
```

**Frontend Deployment:**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: frontend-deployment
spec:
  replicas: 2
  selector:
    matchLabels:
      app: frontend
  template:
    metadata:
      labels:
        app: frontend
    spec:
      containers:
      - name: frontend
        image: nginx:latest
        ports:
        - containerPort: 80
        env:
        - name: BACKEND_URL
          value: "http://backend-service"   # Internal DNS name
```

**Key Points:**
- **ClusterIP Service** (default type) provides internal-only access
- Stable DNS name: `backend-service` (or fully qualified: `backend-service.default.svc.cluster.local`)
- Service selector (`app: backend`) automatically discovers backend pods
- Service provides built-in load balancing across backend replicas
- Frontend uses `BACKEND_URL` environment variable to connect
- Even if backend pods restart or change IPs, DNS name remains stable
- Backend is NOT accessible from outside the cluster
