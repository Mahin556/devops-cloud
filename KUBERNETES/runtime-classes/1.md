# Kubernetes RuntimeClass — Complete Detailed Explanation

## 1. What is RuntimeClass?

The main topic is the Kubernetes **`RuntimeClass`** concept.

At a high level:

> **RuntimeClass allows you to select which container runtime configuration should be used to run a particular Pod.**

This is useful because different workloads may need different runtime implementations.

For example:

* Normal Linux containers
* Workloads requiring stronger isolation
* WebAssembly workloads
* Sandboxed workloads
* Different container runtime technologies

The key idea is:

```text
Pod
 ↓
RuntimeClass
 ↓
Container runtime configuration
 ↓
Specific runtime handler
 ↓
Container runtime / shim
 ↓
Workload
```

The video emphasizes that **understanding why RuntimeClass exists is more important than memorizing only how to create one**.

You might initially think:

Because **different workloads can have different requirements**.


# 53. RuntimeClass vs container runtime — memorize this table

| Concept            | Meaning                                                            |
| ------------------ | ------------------------------------------------------------------ |
| Container runtime  | Software responsible for running containers/workloads              |
| containerd         | High-level container runtime/manager                               |

| runc               | Common low-level OCI runtime                                       |
| Runtime handler    | Named runtime configuration used by containerd                     |
| RuntimeClass       | Kubernetes object used to select a runtime handler                 |
| `runtimeClassName` | Pod field specifying which RuntimeClass to use                     |
| Spin               | Example WebAssembly runtime ecosystem                              |
| Spin shim          | Shim allowing containerd/Kubernetes to reach the Spin/Wasm runtime |

# 57. Final summary

The entire video can be reduced to this:

```text
Kubernetes Pod
      │
      │ runtimeClassName
      ▼
 RuntimeClass
      │
      │ handler
      ▼
   containerd

      │
      ▼
```

**Why?**

Because Kubernetes may need to run different workloads using different runtime technologies or isolation mechanisms.

The **RuntimeClass provides a Kubernetes-level way to select the desired runtime handler**.

The handler must correspond to a runtime configuration available on the node.

The video uses **WebAssembly + Spin** to demonstrate this:

```text
Pod
 ↓
RuntimeClass: spin-v2
 ↓
handler: spin
 ↓
containerd
 ↓
Spin shim
 ↓
WebAssembly runtime
 ↓
WebAssembly application
```

And the most important CKS takeaway is:

> **`runtimeClassName` selects a RuntimeClass; the RuntimeClass specifies a `handler`; the handler maps to a runtime configuration on the node, which ultimately determines how the workload is executed.**
