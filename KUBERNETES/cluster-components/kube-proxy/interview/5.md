## 27. Describe the Role of kube-proxy in a Kubernetes Cluster

`kube-proxy` is a network component in Kubernetes that runs on every node in the cluster.

Its main responsibility is:

* Managing network communication between Services and Pods.

It ensures traffic is:

* Properly routed
* Load balanced
* Accessible across the cluster

---

# Main Responsibilities of kube-proxy

## 1. Service Discovery and Routing

In Kubernetes:

* Pods are temporary
* Pod IPs can change

Applications access Pods using:

* Kubernetes Services

`kube-proxy` maintains the networking rules required to forward traffic from:

* Service IPs
* Cluster IPs

to the correct backend Pods.

---

# Example Flow

```text id="5m2p8"
Client Request
      ↓
Kubernetes Service
      ↓
kube-proxy
      ↓
Backend Pod
```

---

# 2. Load Balancing

If multiple Pods exist behind a Service:

* kube-proxy distributes traffic across them.

Example:

```text id="8k1n4"
Service → Pod1
        → Pod2
        → Pod3
```

This provides:

* Internal load balancing
* High availability

---

# 3. Protocol Handling

kube-proxy supports:

* TCP
* UDP
* SCTP

traffic forwarding.

---

# How kube-proxy Works Internally

kube-proxy watches:

* Services
* Endpoints

through the Kubernetes API Server.

When changes happen:

* New Pods added
* Pods removed

kube-proxy updates:

* iptables
* IPVS rules

on the node.

---

# Networking Modes

## 1. iptables Mode (Most Common)

Uses Linux:

* iptables NAT rules

for:

* Traffic forwarding
* Load balancing

---

## 2. IPVS Mode (High Performance)

Uses Linux:

* IP Virtual Server (IPVS)

Benefits:

* Better scalability
* Faster performance
* Efficient load balancing

Recommended for:

* Large clusters

---

# Example — Service Access

Suppose:

```text id="3x7q2"
Service IP = 10.96.0.10
```

kube-proxy creates rules like:

```text id="6v1m5"
10.96.0.10 → Pod A
           → Pod B
```

Traffic automatically reaches healthy Pods.

---

# Important Clarification

kube-proxy:

* Does NOT directly proxy traffic in userspace anymore (mostly)
* Primarily manages kernel networking rules

using:

* iptables
* IPVS

---

# Benefits of kube-proxy

* Stable Service networking

# Interview-Ready Answer

“kube-proxy is a Kubernetes networking component that runs on every node and manages communication between Services and Pods. It watches the Kubernetes API for Service and Endpoint changes and configures networking rules using iptables or IPVS. Its main responsibilities include service discovery, traffic routing, and load balancing traffic across backend Pods.”
