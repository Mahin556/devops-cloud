### Content Management System with multiple replicas. All replicas must access the same uploaded files. Pods may run on different nodes. Files must survive pod deletion.

**Solution:**

**PersistentVolume with ReadWriteMany:**
```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: cms-shared-pv
spec:
  capacity:
    storage: 50Gi
  volumeMode: Filesystem
  accessModes:
  - ReadWriteMany                      # Multiple pods can read/write
  persistentVolumeReclaimPolicy: Retain
  storageClassName: shared-storage
  nfs:                                 # NFS supports ReadWriteMany
    server: nfs-server.example.com
    path: /exports/cms
  # Alternative: Azure Files, AWS EFS, GCP Filestore
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: cms-shared-pvc
spec:
  accessModes:
  - ReadWriteMany                      # Must match PV
  resources:
    requests:
      storage: 50Gi
  storageClassName: shared-storage
```

**CMS Deployment with Shared Volume:**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: cms-app
spec:
  replicas: 3                          # Multiple replicas sharing same volume
  selector:
    matchLabels:
      app: cms
  template:
    metadata:
      labels:
        app: cms
    spec:
      containers:
      - name: cms
        image: wordpress:latest
        ports:
        - containerPort: 80
        volumeMounts:
        - name: shared-uploads
          mountPath: /var/www/html/wp-content/uploads
      volumes:
      - name: shared-uploads
        persistentVolumeClaim:
          claimName: cms-shared-pvc
```

**How Shared Storage Works:**
```
Architecture:
  cms-app-pod-1 (Node-A) ─┐
  cms-app-pod-2 (Node-B) ─┼─ Mount same PVC → NFS Server /exports/cms
  cms-app-pod-3 (Node-C) ─┘

All pods read/write to the same NFS share:
  - User uploads image via pod-1 → saved to NFS
  - Pod-2 and Pod-3 can immediately access the uploaded image
  - Any pod can serve any uploaded file
```

**Key Points:**
- `accessModes: ReadWriteMany` (RWX) allows multiple writers across nodes
- Requires shared storage backend: NFS, Azure Files, AWS EFS, GCP Filestore
- All replicas access the same uploaded files
- Pods can run on different nodes - storage is network-attached
- `persistentVolumeReclaimPolicy: Retain` prevents accidental data loss
- PVC abstracts storage details from application
- Essential for CMS, shared file systems, and multi-writer workloads
