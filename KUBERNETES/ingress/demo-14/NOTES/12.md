These annotations customize how **NGINX Ingress** communicates with your backend services. They do **not** configure your application—they configure the NGINX proxy in front of it.

---

# Request Flow

```text
Client
   │
   ▼
NGINX Ingress
   │
   ▼
Backend Service
   │
   ▼
Pod
```

These timeout settings apply to the **NGINX ↔ Backend** connection.

---

# 1. proxy-connect-timeout

```yaml
nginx.ingress.kubernetes.io/proxy-connect-timeout: "5"
```

## Meaning

Maximum time NGINX waits to **establish a TCP connection** with the backend.

```text
NGINX  -----------TCP Handshake-----------> Backend
             ^
             |
        proxy-connect-timeout
```

If the backend doesn't accept the connection within 5 seconds:

```text
504 Gateway Timeout
```

---

### Example

Backend is down:

```text
Client
    │
    ▼
NGINX
    │
    │ trying to connect...
    │
    │ 5 seconds
    ▼
Timeout
```

Client receives

```text
504 Gateway Timeout
```

---

## Common Uses

* Backend is overloaded
* Pod not responding
* Service IP unreachable
* Network issue

---

# 2. proxy-send-timeout

```yaml
nginx.ingress.kubernetes.io/proxy-send-timeout: "10"
```

This is **not** how long the whole request can take.

It is:

> Maximum time NGINX waits while **sending the request** to the backend.

---

Example

Client uploads

```text
5 GB file
```

Flow

```text
Client
      │
      ▼
NGINX
      │
      │ sending request body
      ▼
Backend
```

Suppose backend stops reading.

NGINX keeps trying to send.

If sending stalls for 10 seconds:

```text
504 Gateway Timeout
```

---

Used mainly for

* Uploads
* POST requests
* PUT requests

---

# 3. proxy-read-timeout

```yaml
nginx.ingress.kubernetes.io/proxy-read-timeout: "20"
```

This is the most commonly changed timeout.

Meaning

> Maximum time NGINX waits for the backend to send data.

---

Flow

```text
Client
     │
     ▼
NGINX
     │
     ▼
Backend
```

Backend starts processing.

```text
Sleep 30 seconds
```

NGINX waits.

After

```text
20 seconds
```

↓

```text
504 Gateway Timeout
```

---

Example

Backend API

```python
time.sleep(30)
return "Done"
```

Ingress

```yaml
proxy-read-timeout: "20"
```

Result

```text
504 Gateway Timeout
```

Increase it to

```yaml
proxy-read-timeout: "40"
```

↓

Now succeeds.

---

# Complete Example

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: app-ingress

  annotations:

    nginx.ingress.kubernetes.io/proxy-connect-timeout: "5"

    nginx.ingress.kubernetes.io/proxy-send-timeout: "10"

    nginx.ingress.kubernetes.io/proxy-read-timeout: "20"

spec:
  ingressClassName: nginx

  rules:
  - host: app.example.com

    http:
      paths:

      - path: /

        pathType: Prefix

        backend:

          service:

            name: frontend-service

            port:

              number: 80
```

# Other Useful Customization Annotations

## Upload Size

Default upload size is usually **1 MB**.

```yaml
nginx.ingress.kubernetes.io/proxy-body-size: "100m"
```

Allows

```text
100 MB uploads
```

---

## Rate Limiting

```yaml
nginx.ingress.kubernetes.io/limit-rps: "20"
```

20 requests per second.

---

## Concurrent Connections

```yaml
nginx.ingress.kubernetes.io/limit-connections: "50"
```

Only

```text
50 simultaneous connections
```

per client.

---

## Buffer Size

```yaml
nginx.ingress.kubernetes.io/proxy-buffer-size: "16k"
```

Useful for large headers.

---

## Enable CORS

```yaml
nginx.ingress.kubernetes.io/enable-cors: "true"
```

---

## Session Affinity

```yaml
nginx.ingress.kubernetes.io/affinity: "cookie"
```

Keeps users on the same backend pod.

---

## Rewrite URL

```yaml
nginx.ingress.kubernetes.io/rewrite-target: /
```

---

## SSL Redirect

```yaml
nginx.ingress.kubernetes.io/ssl-redirect: "true"
```

# Real-World Example

Suppose you have:

* **Frontend** (fast)
* **Reports API** (takes 2–3 minutes)
* **File Upload API**

```text
                    Ingress

           ┌──────────┴──────────┐
           │                     │
      Frontend             Reports API
      timeout=20s          timeout=180s
```

Ingress:

```yaml
metadata:
  annotations:
    nginx.ingress.kubernetes.io/proxy-read-timeout: "180"
    nginx.ingress.kubernetes.io/proxy-send-timeout: "180"
    nginx.ingress.kubernetes.io/proxy-body-size: "500m"
```

This allows:

* Long-running report generation
* Large file uploads
* Slower backend responses

without NGINX timing out.

# Summary

| Annotation              | What it controls                                                | Typical use case                                |
| ----------------------- | --------------------------------------------------------------- | ----------------------------------------------- |
| `proxy-connect-timeout` | Time to establish a connection to the backend                   | Slow or overloaded backend startup              |
| `proxy-send-timeout`    | Maximum idle time while NGINX sends the request to the backend  | Large uploads or slow-reading backends          |
| `proxy-read-timeout`    | Maximum idle time waiting for the backend to send response data | Long-running APIs, report generation, streaming |
| `proxy-body-size`       | Maximum allowed request body size                               | File uploads                                    |
| `limit-rps`             | Requests per second per client                                  | Rate limiting                                   |
| `limit-connections`     | Simultaneous connections per client                             | Prevent connection abuse                        |
| `affinity`              | Keep a client on the same backend pod                           | Sticky sessions                                 |
| `ssl-redirect`          | Redirect HTTP to HTTPS                                          | Secure access                                   |
| `rewrite-target`        | Rewrite the request path before sending it to the backend       | URL restructuring                               |

**Note on timeouts:** `proxy-connect-timeout`, `proxy-send-timeout`, and `proxy-read-timeout` measure **idle time** for those operations, not the total lifetime of the request. For example, `proxy-read-timeout: "20"` means NGINX expects to receive some data from the backend at least every 20 seconds; if no data arrives during that period, it times out.
