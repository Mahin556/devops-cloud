### Running Kubernetes in own data center without cloud load balancer. Need external access to web application.

**Solution:**

**Web Application Deployment:**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-deployment
spec:
  replicas: 2
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: web
        image: nginx:latest
        ports:
        - containerPort: 80
```

**NodePort Service for On-Prem:**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: web-service
spec:
  type: NodePort                       # No cloud LB available
  selector:
    app: web
  ports:
  - port: 80
    targetPort: 80
    nodePort: 30080                    # Mapped to each node's IP
```

**Access Methods:**
```bash
# Method 1: Direct NodePort access
kubectl get nodes -o wide
# Access: http://<any-node-ip>:30080

# Method 2: Use external load balancer (HAProxy/Nginx) in front
# Configure HAProxy to forward traffic to node IPs on port 30080

# Method 3: MetalLB for bare-metal load balancing
# Install MetalLB and use LoadBalancer service type

# Method 4: Ingress Controller with NodePort
# Install ingress-nginx and create Ingress resource
```

**Key Points:**
- **NodePort Service** is the go-to for on-premises clusters
- No cloud load balancer available in data center
- Each node exposes the app on port 30080
- Traffic to any node on 30080 gets forwarded to web pods
- For production: put external load balancer (HAProxy, Nginx, F5) in front
- Alternatives: MetalLB for bare-metal LB, Ingress Controller
- DNS can point to node IPs or external LB
