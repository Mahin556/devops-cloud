Absolutely. Let's do a **complete practical of Helm `charts/` / subcharts**, from creating the charts to installing and passing values.

We’ll build a real example:

```text
myapp
├── frontend
└── backend
```

The parent `myapp` chart will depend on both `frontend` and `backend`.

---

# 1. Create the parent Helm chart

First create a working directory:

```bash
mkdir helm-practice
cd helm-practice
```

Create the parent chart:

```bash
helm create myapp
```

You now have:

```text
myapp/
├── Chart.yaml
├── values.yaml
├── charts/
├── templates/
└── ...
```

The important part is:

```text
myapp/
└── charts/
```

This directory will contain our subcharts.

---

# 2. Create the frontend chart

Go inside `myapp/charts`:

```bash
cd myapp/charts
```

Create a frontend chart:

```bash
helm create frontend
```

Now:

```text
myapp/
├── Chart.yaml
├── values.yaml
├── charts/
│   └── frontend/
│       ├── Chart.yaml
│       ├── values.yaml
│       ├── templates/
│       └── charts/
└── templates/
```

---

# 3. Create the backend chart

Still inside `charts/`:

```bash
helm create backend
```

Now:

```text
myapp/
├── Chart.yaml
├── values.yaml
├── charts/
│   ├── frontend/
│   └── backend/
└── templates/
```

So:

```text
myapp
│
├── charts/
│   ├── frontend/
│   └── backend/
│
├── templates/
├── values.yaml
└── Chart.yaml
```

Here:

```text
myapp       → Parent chart
frontend    → Subchart
backend     → Subchart
```

# 4. Understand the relationship

The important concept is:

```text
                myapp
                  │
        ┌─────────┴─────────┐
        │                   │
     frontend            backend
      chart                chart
```

When you install `myapp`, Helm can install:

```text
myapp
frontend
backend
```

as one application.

---

# 5. Configure the frontend

Open:

```text
myapp/charts/frontend/values.yaml
```

For practice, replace its contents with:

```yaml
replicaCount: 2

image:
  repository: nginx
  tag: "1.27"
  pullPolicy: IfNotPresent

service:
  type: ClusterIP
  port: 80
```

Now edit:

```text
myapp/charts/frontend/templates/deployment.yaml
```

You can use the deployment generated by `helm create`, or simplify it to:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ .Release.Name }}-frontend
spec:
  replicas: {{ .Values.replicaCount }}
  selector:
    matchLabels:
      app: frontend
  template:
    metadata:
      labels:
        app: frontend
    spec:
      containers:
        - name: frontend
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
          ports:
            - containerPort: 80
```

Then create:

```text
myapp/charts/frontend/templates/service.yaml
```

with:

```yaml
apiVersion: v1
kind: Service
metadata:
  name: {{ .Release.Name }}-frontend
spec:
  selector:
    app: frontend
  ports:
    - port: 80
      targetPort: 80
```

# 7. Now the important part — `Chart.yaml`

Go to:

```text
myapp/Chart.yaml
```

You can declare your subcharts as dependencies:

```yaml
apiVersion: v2
name: myapp
description: My application
type: application
version: 1.0.0

dependencies:
  - name: frontend
    version: 1.0.0
    repository: "file://charts/frontend"

  - name: backend
    version: 1.0.0
    repository: "file://charts/backend"
```

This tells Helm:

> My `myapp` chart depends on the `frontend` and `backend` charts.

# 13. Now understand values inheritance

This is one of the **most important concepts with subcharts**.

Suppose the parent:

```text
myapp/values.yaml
```

contains:

```yaml
frontend:
  replicaCount: 3

backend:
  replicaCount: 2
```

These values are passed to the respective subcharts.

So:

```text
myapp
 │
 ├── frontend
 │     └── replicaCount = 3
 │
 └── backend
       └── replicaCount = 2
```

The parent can therefore control configuration of its dependencies.

```yaml
  replicaCount: 2
```

Then run:

```bash
helm upgrade myapp .
```

Check:

```bash
kubectl get pods
```

You should now have approximately:

```text
frontend → 3 pods
backend  → 2 pods
```

# 15. Why does `frontend:` work?

This:

```yaml
frontend:
  replicaCount: 3
```

corresponds to the subchart:

```text
charts/frontend
```

And:

```yaml
backend:
  replicaCount: 2
```

corresponds to:

```text
charts/backend
```

So the parent values are effectively structured like:

```text
myapp values
│
├── frontend
│   └── replicaCount
│
└── backend
    └── replicaCount
```

This is how a parent chart configures its subcharts.

# 18. External charts are also commonly dependencies

You don't have to keep every subchart manually inside:

```text
charts/
```

For example, you could use an external Redis chart.

Your `Chart.yaml` could contain:

```yaml
dependencies:
  - name: redis
    version: "..."
    repository: "..."
```

Then:

```bash
helm dependency update
```

downloads the dependency.

It gets placed under:

```text
charts/
```

This is one of the most common purposes of the `charts/` directory.

---

# 19. `charts/` vs `templates/`

This distinction is very important.

### `templates/`

Contains Kubernetes manifests for **the current chart**.

Example:

```text
templates/
├── deployment.yaml
├── service.yaml
├── ingress.yaml
└── configmap.yaml
```

### `charts/`

Contains **other charts that this chart depends on**.

Example:

```text
charts/
├── redis/
├── frontend/
└── backend/
```

Think:

```text
templates/ → Kubernetes resources
charts/    → Helm charts
```

# 20. Complete practical architecture

At the end, your structure can look like:

```text
myapp/
│
├── Chart.yaml
│
├── values.yaml
│
├── charts/
│   │
│   ├── frontend/
│   │   ├── Chart.yaml
│   │   ├── values.yaml
│   │   └── templates/
│   │       ├── deployment.yaml
│   │       └── service.yaml
│   │
│   └── backend/
│       ├── Chart.yaml
│       ├── values.yaml
│       └── templates/
│           ├── deployment.yaml
│           └── service.yaml
│
└── templates/
```

The flow is:

```text
                helm install myapp .
                         │
                         ▼
                    Parent Chart
                      myapp
                         │
             ┌───────────┴───────────┐
             ▼                       ▼
         frontend                  backend
         subchart                  subchart
             │                       │
             ▼                       ▼
        Deployment                Deployment
        Service                   Service
```

### The commands you should remember

```bash
# Create parent
helm create myapp

# Create subcharts
helm create charts/frontend
helm create charts/backend

# Define dependencies
vim Chart.yaml

# Download/update dependencies
helm dependency update

# Validate
helm lint .

# See generated YAML without installing
helm template myapp .

# Install
helm install myapp .

# Check
helm list
kubectl get pods
kubectl get svc

# Change values and redeploy
helm upgrade myapp .
```

**The key idea:** `charts/` is useful when your Helm application is made from **multiple smaller Helm charts**. The parent chart acts as the coordinator, while each subchart encapsulates one component.
