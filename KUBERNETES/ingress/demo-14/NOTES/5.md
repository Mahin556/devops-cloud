`rewrite-target` tells the Ingress controller to **change the URL before forwarding it to your backend service**.

Without it:

```text
Client ---> Ingress ---> Backend
           /api/users      /api/users
```

With:

```yaml
nginx.ingress.kubernetes.io/rewrite-target: /$2
```

the backend receives a **different path**.

---

## Example

Ingress:

```yaml
annotations:
  nginx.ingress.kubernetes.io/use-regex: "true"
  nginx.ingress.kubernetes.io/rewrite-target: /$2

paths:
- path: /api(/|$)(.*)
  pathType: ImplementationSpecific
```

---

## Step 1: Regex Matching

For the request:

```text
/api/users
```

Regex:

```regex
/api(/|$)(.*)
```

Breakdown:

| Part   | Matches |     |
| ------ | ------- | --- |
| `/api` | `/api`  |     |
| `(/    | $)`     | `/` |
| `(.*)` | `users` |     |

Captured groups:

| Group | Value   |
| ----- | ------- |
| `$1`  | `/`     |
| `$2`  | `users` |

---

## Step 2: Rewrite

The annotation says:

```yaml
rewrite-target: /$2
```

So:

```text
/$2
```

becomes:

```text
/users
```

The backend service receives:

```text
/users
```

instead of:

```text
/api/users
```

---

## More examples

| Incoming URL     | `$1`          | `$2`        | Rewritten URL |
| ---------------- | ------------- | ----------- | ------------- |
| `/api`           | *(empty/end)* | *(empty)*   | `/`           |
| `/api/`          | `/`           | *(empty)*   | `/`           |
| `/api/users`     | `/`           | `users`     | `/users`      |
| `/api/users/1`   | `/`           | `users/1`   | `/users/1`    |
| `/api/v1/orders` | `/`           | `v1/orders` | `/v1/orders`  |

## Why use it?

Imagine your backend application serves:

```text
/users
/orders
/products
```

but you want users to access it through:

```text
/api/users
/api/orders
/api/products
```

The ingress removes the `/api` prefix before forwarding.

```
Browser                Backend

/api/users   ───────►  /users
/api/orders  ───────►  /orders
```

The backend doesn't need to know about the `/api` prefix.

---

## Without `rewrite-target`

Configuration:

```yaml
path: /api
pathType: Prefix
```

Request:

```text
GET /api/users
```

Backend receives:

```text
GET /api/users
```

---

## With `rewrite-target: /$2`

Configuration:

```yaml
path: /api(/|$)(.*)
rewrite-target: /$2
```

Request:

```text
GET /api/users
```

Backend receives:

```text
GET /users
```

---

## Why `$2` and not `$1`?

The regex has **two capturing groups**:

```regex
/api(/|$)(.*)
     ^    ^
     |    |
    $1   $2
```

* **`$1`** = either `/` or the end of the string (`$`), which isn't useful as the path.
* **`$2`** = everything after `/api/`, which is the part you usually want to forward.

That's why the common annotation is:

```yaml
nginx.ingress.kubernetes.io/rewrite-target: /$2
```

It strips the `/api` prefix while preserving the rest of the URL.
