## How Services Handle Pod IP Changes

### The Problem:
- Pods are ephemeral - they get created and deleted automatically by controllers
- Pod IPs change when pods restart or move between nodes
- Applications can't keep track of changing IPs

### The Solution:
- Service provides a **stable virtual IP**
- kube-proxy maintains the mapping between Service IP and current Pod IPs
- Applications use the Service IP (which never changes)
- kube-proxy handles the redirection to the correct pod

### Summary Flow:
```
Application → Service IP (stable) → kube-proxy → Pod IP (dynamic)
```
