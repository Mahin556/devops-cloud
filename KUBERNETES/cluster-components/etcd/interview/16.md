## How to Take a Backup of a Kubernetes Cluster?

There are two types of backups:

1.  **etcd Backup:** Since all cluster information (instructions, state, configurations) is stored in etcd, backing up etcd is the primary way to back up the cluster. If etcd is corrupted, you can restore the entire cluster from this backup.
2.  **Manifest Backup:** All deployment manifests (YAML files for deployments, services, PV, PVC, etc.) should be stored in a centralized version control system like Git. If individual deployments are lost, they can be recreated. Tools like Helm Charts package these manifests, making redeployment easier.

**Commands for etcd Backup:**

1.  **Install etcdctl Client (if not installed):**
    ```bash
    apt install etcd-client
    ```

2.  **Take the Backup:** You need to provide the etcd endpoint (where etcd is running) and the TLS certificates.
    ```bash
    etcdctl --endpoints=https://127.0.0.1:2379 \
      --cacert=/etc/kubernetes/pki/etcd/ca.crt \
      --cert=/etc/kubernetes/pki/etcd/server.crt \
      --key=/etc/kubernetes/pki/etcd/server.key \
      snapshot save /root/etcd-backup
    ```

**Key Points:**
-   etcd listens on port `2379` for client interaction and `2380` for internal peer communication.
-   The backup can be taken from any remote machine that has network access to the etcd node and the required certificates.
