**No.** An Ingress can have **only one default backend**.

There are two concepts that are often confused:

## 1. Default backend (only one)

The default backend handles requests that **don't match any host or path rule**.

Example:

```yaml
spec:
  defaultBackend:
    service:
      name: default-service
      port:
        number: 80
```

There can be **only one** `defaultBackend` in a single Ingress.

---

## 2. Catch-all path (`/`)

In your Ingress, you have:

```yaml
- path: /
  pathType: Prefix
  backend:
    service:
      name: default-service
      port:
        number: 80
```

This is **not** the same as `spec.defaultBackend`.

It is simply a path rule that matches everything under the specified host.

For example:

```yaml
rules:
- host: demo.local
  http:
    paths:
    - path: /
      pathType: Prefix
      backend:
        service:
          name: default-service
```

This means:

* `demo.local/abc` → `default-service`
* `demo.local/test` → `default-service`

but only for the `demo.local` host.

---

## Can you have multiple `defaultBackend`s?

### ❌ In one Ingress

No.

This is invalid:

```yaml
spec:
  defaultBackend:
    service:
      name: service1

  defaultBackend:
    service:
      name: service2
```

---

### ✅ Multiple hosts with their own catch-all paths

Yes.

```yaml
rules:
- host: app1.example.com
  http:
    paths:
    - path: /
      pathType: Prefix
      backend:
        service:
          name: app1

- host: app2.example.com
  http:
    paths:
    - path: /
      pathType: Prefix
      backend:
        service:
          name: app2
```

Behavior:

| Host               | Path        | Backend |
| ------------------ | ----------- | ------- |
| `app1.example.com` | `/anything` | `app1`  |
| `app2.example.com` | `/anything` | `app2`  |

Each host has its own "default" path because of the `/` rule.

---

### ✅ Multiple Ingress resources

You can also have multiple Ingress resources:

```text
Ingress A
------------
host: app1.com
path: /

Ingress B
------------
host: app2.com
path: /
```

Each routes to a different backend.

---

## Matching order

Suppose you have:

```yaml
paths:
- path: /api
- path: /images
- path: /
```

Requests are matched like this:

| Request            | Backend           |
| ------------------ | ----------------- |
| `/api/users`       | `api-service`     |
| `/images/logo.png` | `image-service`   |
| `/about`           | `default-service` |
| `/`                | `default-service` |

The Ingress controller chooses the **most specific matching path**, so `/api` is preferred over `/`.

---

### Summary

* ✅ One `spec.defaultBackend` per Ingress.
* ✅ One catch-all `/` path per host (typically).
* ✅ Multiple hosts can each have their own `/` catch-all.
* ✅ Multiple Ingress resources can each define their own rules and catch-all paths.
