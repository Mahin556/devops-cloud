# 1. IngressClass

```yaml
apiVersion: networking.k8s.io/v1
kind: IngressClass
metadata:
  name: my-ingress-nginx
spec:
  controller: k8s.io/ingress-nginx
```

This tells Kubernetes:

> "Whenever an Ingress has"

```yaml
ingressClassName: my-ingress-nginx
```

it should be handled by the NGINX Ingress Controller.

Your Ingress correctly uses:

```yaml
spec:
  ingressClassName: my-ingress-nginx
```

so this part is correct.

# Problem #1

You have

```yaml
rewrite-target: /
```

Suppose the client requests

```
GET /myblogging/index.html
```

NGINX rewrites

```
/myblogging/index.html
```

to

```
/
```

because

```yaml
rewrite-target: /
```

always replaces the path with `/`.

Therefore the backend receives

```
GET /
```

instead of

```
GET /index.html
```

---

## Better Option

If you want

```
/myblogging/index.html

↓

/index.html
```

use regex.

```yaml
metadata:
  annotations:
    nginx.ingress.kubernetes.io/use-regex: "true"
    nginx.ingress.kubernetes.io/rewrite-target: /$2
```

Path

```yaml
path: /myblogging(/|$)(.*)

pathType: ImplementationSpecific
```

Now

```
Client

GET

/myblogging/images/logo.png
```

Regex

```
/myblogging(/|$)(.*)
```

captures

```
$2 = images/logo.png
```

Rewrite

```
/images/logo.png
```

Backend receives

```
GET /images/logo.png
```

## Recommended Manifest

If your backend application **already serves content at the root path (`/`)**, the recommended configuration is:

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: blogging-ingress
  annotations:
    nginx.ingress.kubernetes.io/use-regex: "true"
    nginx.ingress.kubernetes.io/rewrite-target: /$2
spec:
  ingressClassName: my-ingress-nginx
  rules:
  - http:
      paths:
      - path: /myblogging(/|$)(.*)
        pathType: ImplementationSpecific
        backend:
          service:
            name: blogging-svc
            port:
              number: 80
```

This preserves everything after `/myblogging` and forwards it correctly to the backend application.
