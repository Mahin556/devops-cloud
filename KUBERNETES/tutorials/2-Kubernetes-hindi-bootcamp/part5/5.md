A `PriorityClass` in Kubernetes is a cluster-scoped API object that assigns a numerical priority value to Pods, indicating their relative importance to the scheduler. When cluster resources are scarce, this priority system dictates which Pods get scheduled first and which might be evicted to make room for more critical workloads.

### How PriorityClass Works: Scheduling and Preemption

The scheduler uses the priority value to make two key decisions:

1.  **Scheduling Order**: Pods with a higher numerical priority are scheduled before those with a lower priority.
2.  **Preemption (Eviction)**: If a high-priority Pod cannot be scheduled due to a lack of resources, the scheduler can **preempt** (evict) one or more lower-priority Pods to free up the necessary resources.

### Defining a PriorityClass

A `PriorityClass` is defined using the `scheduling.k8s.io/v1` API group.

**Key Fields**:
*   `name`: The name of the PriorityClass, used in the Pod spec.
*   `value`: The 32-bit integer priority value. **Higher numbers mean higher priority**. The value must be between `-2147483648` and `1000000000` (1 billion).
*   `globalDefault`: An optional boolean. If set to `true`, this PriorityClass is assigned to any Pod that doesn't specify one. Only one PriorityClass can have this set to `true`.
*   `description`: An optional arbitrary string to provide context for users.
*   `preemptionPolicy`: An optional field (e.g., `Never`) to control if Pods of this class can preempt others.

**Example YAML**:
```yaml
apiVersion: scheduling.k8s.io/v1
kind: PriorityClass
metadata:
  name: high-priority
value: 10000
globalDefault: false
description: "Priority class for high-priority workloads"
```


### Using a PriorityClass in a Pod

Once created, you can assign a `PriorityClass` to a Pod by setting the `priorityClassName` field in its spec.

**Example Pod YAML**:
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx
spec:
  containers:
  - name: nginx
    image: nginx
  priorityClassName: high-priority
```


### Built-in PriorityClasses

Kubernetes comes with two high-priority classes built-in for critical system components:
*   `system-node-critical`: The highest possible priority, used for components vital to the node (e.g., `kube-proxy`).
*   `system-cluster-critical`: Used for components critical to the entire cluster (e.g., `CoreDNS`).
> **Note**: These class names are prefixed with `system-` and are reserved.

### Use Cases and Best Practices

PriorityClass is a powerful tool for managing workloads in resource-constrained clusters.

**Common Use Cases:**
*   **Protecting Critical Workloads**: Ensuring that mission-critical applications (e.g., databases, core APIs) are scheduled and not evicted in favor of less important ones.
*   **Workload Tiering**: Separating Pods into tiers like `prod`, `preprod`, and `dev` with decreasing priorities.
*   **Node Over-Provisioning**: Creating low-priority "placeholder" Pods to reserve capacity. When a real, higher-priority Pod needs resources, the placeholder is preempted, allowing the new Pod to start quickly while the cluster scales up.

**Best Practices:**
*   **Use a Wide Value Range**: Space out priority values (e.g., 1000, 10000, 100000) to allow for future flexibility.
*   **Reserve High Priority**: Avoid making all workloads high-priority; reserve it for truly critical Pods.
*   **Control with ResourceQuota**: Use `ResourceQuota` to prevent users from creating Pods with excessively high priorities.

### Summary

A `PriorityClass` sets a Pod's importance via an integer value. This influences the order in which Pods are scheduled and allows higher-priority Pods to preempt lower-priority ones when resources are scarce. It's a crucial tool for ensuring critical applications remain available during resource contention.
