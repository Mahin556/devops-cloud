## 1. Paths like `/iphone` and `/android` are Just Examples

* The instructor uses paths like:

  ```
  /iphone
  /android
  /desktop
  ```

  only to **teach how Ingress routing works**.
* In real apps, users **don’t manually type these paths**.

👉 Purpose:
To show how an **Ingress can route different requests to different services**.

Example concept:

```
/iphone   → iphone-service
/android  → android-service
/         → desktop-service
```

---

## 2. Real Apps Don’t Work Like This

In real life:

* iPhone users install an app → app already knows the backend URL
* Android users install an app → URL is built into the app
* Users don’t type:

  ```
  myapp.com/iphone
  myapp.com/android
  ```

Instead:

```
Mobile App → API URL → Ingress → Service → Pod
Browser    → myapp.com → Ingress → Desktop Service
```

---

## 3. Default Route for Desktop Users

If someone visits:

```
myapp.com
```

They usually come from a browser (desktop/laptop).

So Ingress can route:

```
/ → desktop-service
```

This is called the **default route**.

---

## 4. What Ingress is Teaching Here

The main goal is to show that **Ingress routes traffic based on rules**, like:

* Path
* Hostname
* Headers (sometimes)

Example:

```yaml
rules:
  - http:
      paths:
      - path: /iphone
        backend: iphone-service
      - path: /android
        backend: android-service
      - path: /
        backend: desktop-service
```

---

## 5. Real-World Equivalent

In real production apps, routing might be based on:

* Different domains:

  ```
  api.myapp.com
  www.myapp.com
  mobile.myapp.com
  ```

* Or headers:

  ```
  User-Agent: iPhone
  User-Agent: Android
  ```

---

## 6. Core Concept (Most Important)

The **main idea** is:

> Ingress routes requests to different services based on rules, not based on who the user is manually typing.

So:

* `/iphone` → just for learning
* `/android` → just for learning
* `/` → real default route
