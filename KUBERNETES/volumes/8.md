* Storing data **inside a Pod** is not safe because if the Pod crashes or is deleted, the data is lost
* Storing data on a **node’s local storage** is also unreliable in multi-node clusters because Pods can move to different nodes, causing data to be split or unavailable
* Therefore, application data should be stored on **external persistent storage** (like cloud storage or storage servers), not inside Pods or nodes
* **Persistent Volume (PV)**
  * Created by the cluster administrator
  * Represents real storage available to the cluster
  * Defines storage size, access modes, reclaim policy, and backend type (EBS, NFS, etc.)

* **Persistent Volume Claim (PVC)**
  * Created by users
  * A request for storage based on Pod requirements (size + access mode)
  * Kubernetes binds PVC to a matching PV

* **Binding between PV and PVC** happens based on:
  * Storage size
  * Access modes

* **Access Modes**
  * RWO: One Pod can read/write
  * ROX: Many Pods can read only
  * RWX: Many Pods can read/write

* **Reclaim Policy (on PV)**
  * Retain → Data kept after PVC deletion
  * Delete → Storage deleted automatically

* One PV can bind to **only one PVC**. Extra unused space in that PV cannot be shared
* If no matching PV exists, the PVC stays in **Pending** state

* **Static Provisioning**
  * Admin manually creates storage and PVs
  * Users create PVCs to use those PVs

* **Dynamic Provisioning**
  * Admin creates **StorageClasses**
  * StorageClass automatically creates storage and PV when PVC is created

* **StorageClass** defines
  * Provisioner (cloud/storage type)
  * Storage parameters (disk type, etc.)
  * Reclaim policy

* Overall flow:
  **Pod → PVC → PV → Actual Storage**

##### Static Provisioning (NFS PV)

```bash
kubectl apply -f - <<EOF
apiVersion: v1
kind: PersistentVolume
metadata:
  name: nfs-pv
spec:
  capacity:
    storage: 5Gi
  accessModes:
    - ReadWriteMany
  persistentVolumeReclaimPolicy: Retain
  nfs:
    path: /data/nfs-share
    server: 192.168.1.100
EOF
```

##### NFS PVC

```bash
kubectl apply -f - <<EOF
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: nfs-pvc
spec:
  accessModes:
    - ReadWriteMany
  resources:
    requests:
      storage: 5Gi
EOF
```

##### Pod Using NFS PVC

```bash
kubectl apply -f - <<EOF
apiVersion: v1
kind: Pod
metadata:
  name: app-pod
spec:
  containers:
  - name: app
    image: nginx
    volumeMounts:
    - mountPath: /usr/share/nginx/html
      name: storage
  volumes:
  - name: storage
    persistentVolumeClaim:
      claimName: nfs-pvc
EOF
```

##### Static Provisioning (AWS EBS PV)

```bash
kubectl apply -f - <<EOF
apiVersion: v1
kind: PersistentVolume
metadata:
  name: ebs-pv
spec:
  capacity:
    storage: 10Gi
  accessModes:
    - ReadWriteOnce
  persistentVolumeReclaimPolicy: Retain
  awsElasticBlockStore:
    volumeID: vol-xxxxxxxx
    fsType: ext4
EOF
```

##### EBS PVC

```bash
kubectl apply -f - <<EOF
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: ebs-pvc
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 10Gi
EOF
```

##### StorageClass (Dynamic Provisioning)

```bash
kubectl apply -f - <<EOF
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: aws-dynamic-sc
provisioner: kubernetes.io/aws-ebs
parameters:
  type: gp2
reclaimPolicy: Delete
volumeBindingMode: WaitForFirstConsumer
EOF
```

##### PVC Using StorageClass

```bash
kubectl apply -f - <<EOF
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: dynamic-pvc
spec:
  accessModes:
    - ReadWriteOnce
  storageClassName: aws-dynamic-sc
  resources:
    requests:
      storage: 8Gi
EOF
```

##### Pod Using Dynamically Created Volume

```bash
kubectl apply -f - <<EOF
apiVersion: v1
kind: Pod
metadata:
  name: dynamic-pod
spec:
  containers:
  - name: app
    image: nginx
    volumeMounts:
    - mountPath: /data
      name: storage
  volumes:
  - name: storage
    persistentVolumeClaim:
      claimName: dynamic-pvc
EOF
```
