### A Spring Boot application needs frequent runtime configuration changes (log levels, feature flags). Rebuilding the container image every time is slow and unacceptable.

**Solution:**

**Step 1 - Create ConfigMap with application.properties:**
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: spring-boot-config
data:
  application.properties: |
    server.port=8080
    logging.level.root=INFO
    logging.level.com.myapp=DEBUG
    feature.new-dashboard=true
    app.timeout=30
```

**Step 2 - Mount ConfigMap as Volume in Deployment:**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: spring-boot-app
spec:
  replicas: 2
  selector:
    matchLabels:
      app: spring-boot
  template:
    metadata:
      labels:
        app: spring-boot
    spec:
      containers:
      - name: spring-boot
        image: myapp:latest
        ports:
        - containerPort: 8080
        volumeMounts:
        - name: config-volume
          mountPath: /config/application.properties
          subPath: application.properties
      volumes:
      - name: config-volume
        configMap:
          name: spring-boot-config
```

**Updating Configuration at Runtime:**
```bash
# Update the ConfigMap
kubectl edit configmap spring-boot-config
# Change logging.level.root=DEBUG

# Restart pods to pick up changes
kubectl rollout restart deployment/spring-boot-app
```

**Key Points:**
- ConfigMap stores `application.properties` file
- Mounted as a file at `/config/application.properties`
- Spring Boot automatically scans `/config` directory at startup
- Changes to ConfigMap require pod restart to take effect
- No image rebuild needed - configuration is externalized
- `subPath` ensures only the specific file is mounted
