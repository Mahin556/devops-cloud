### Multiple teams on a single cluster. Teams should request storage without admin involvement. Storage created automatically. Different performance tiers available.

**Solution:**

**Storage Classes (Defined by Admin):**
```yaml
# Standard tier - HDD storage
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: standard-hdd
  annotations:
    storageclass.kubernetes.io/is-default-class: "false"
provisioner: kubernetes.io/aws-ebs    # AWS EBS provisioner
parameters:
  type: st1                            # Throughput optimized HDD
  fsType: ext4
reclaimPolicy: Delete
allowVolumeExpansion: true
---
# Fast tier - SSD storage
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: fast-ssd
  annotations:
    storageclass.kubernetes.io/is-default-class: "true"  # Default storage class
provisioner: kubernetes.io/aws-ebs
parameters:
  type: gp3                            # General purpose SSD
  fsType: ext4
  iopsPerGB: "10"
reclaimPolicy: Delete
allowVolumeExpansion: true
---
# Premium tier - Provisioned IOPS
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: premium-iops
provisioner: kubernetes.io/aws-ebs
parameters:
  type: io2                            # Provisioned IOPS SSD
  fsType: ext4
  iopsPerGB: "50"
reclaimPolicy: Delete
allowVolumeExpansion: true
```

**Team Requests Storage (PVC):**
```yaml
# Team A: Standard HDD for logs
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: logs-storage
  namespace: team-a
spec:
  accessModes:
  - ReadWriteOnce
  resources:
    requests:
      storage: 100Gi
  storageClassName: standard-hdd       # Choose performance tier
---
# Team B: Fast SSD for database
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: db-storage
  namespace: team-b
spec:
  accessModes:
  - ReadWriteOnce
  resources:
    requests:
      storage: 50Gi
  storageClassName: fast-ssd           # Auto-provisioned SSD
---
# Team C: Premium IOPS for high-performance app
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: high-perf-storage
  namespace: team-c
spec:
  accessModes:
  - ReadWriteOnce
  resources:
    requests:
      storage: 200Gi
  storageClassName: premium-iops
```

**Automatic Provisioning Flow:**
```
1. Team creates PVC with storageClassName: fast-ssd
2. Kubernetes detects no matching PV exists
3. StorageClass "fast-ssd" provisioner (aws-ebs) is triggered
4. Cloud provider creates EBS volume (gp3, 50Gi)
5. PV is automatically created and bound to PVC
6. Pod mounts the PVC and gets storage
7. No admin intervention required!
```

**Key Points:**
- **StorageClass** defines storage policies and provisioners
- **Dynamic Provisioning** creates PVs automatically when PVCs are created
- Teams only create PVCs - no admin tickets needed
- Different storage classes = different performance tiers
- `is-default-class: "true"` makes it the default when no storageClassName specified
- Provisioner integrates with cloud storage (EBS, Azure Disk, GCE PD)
- `reclaimPolicy: Delete` automatically deletes PV when PVC is deleted
- `allowVolumeExpansion: true` allows resizing PVCs
