### Financial application storing critical transaction data. Storage must not be deleted automatically. Admin must manually review and clean up. Data must survive even PVC deletion.

**Solution:**

**PersistentVolume with Retain Policy (Static Provisioning):**

```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: financial-transactions-pv
  labels:
    app: financial-app
    data-class: critical
spec:
  capacity:
    storage: 500Gi
  volumeMode: Filesystem
  accessModes:
  - ReadWriteOnce
  persistentVolumeReclaimPolicy: Retain  # CRITICAL: Data survives PVC deletion
  storageClassName: financial-retain
  # Cloud storage backend
  csi:
    driver: ebs.csi.aws.com
    volumeHandle: vol-0a1b2c3d4e5f6g7h8  # Pre-created EBS volume
    fsType: ext4
  # Or for on-prem:
  # hostPath:
  #   path: /data/financial/transactions

---

apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: financial-transactions-pvc
  namespace: finance
spec:
  accessModes:
  - ReadWriteOnce
  resources:
    requests:
      storage: 500Gi
  storageClassName: financial-retain
  selector:
    matchLabels:
      data-class: critical              # Bind to specific PV
```

**Financial Application Deployment:**

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: financial-app
  namespace: finance
spec:
  serviceName: financial-svc
  replicas: 1                           # Single instance for financial data
  selector:
    matchLabels:
      app: financial-app
  template:
    metadata:
      labels:
        app: financial-app
    spec:
      containers:
      - name: app
        image: financial-app:latest
        volumeMounts:
        - name: transaction-data
          mountPath: /data/transactions
  volumeClaimTemplates:
  - metadata:
      name: transaction-data
    spec:
      accessModes:
      - ReadWriteOnce
      resources:
        requests:
          storage: 500Gi
      storageClassName: financial-retain
```

**Retain Policy Lifecycle:**

```bash
# 1. Application is deleted
kubectl delete statefulset financial-app
# Pod is deleted, PVC still exists

# 2. PVC is deleted
kubectl delete pvc financial-transactions-pvc
# PVC is removed

# 3. Check PV status
kubectl get pv financial-transactions-pv
# STATUS: Released (NOT deleted!)
# Data is preserved on the storage backend

# 4. Admin reviews and decides to keep data
# PV remains in "Released" state - not available for new claims

# 5. Admin manually cleans up when ready
# Step 5a: Delete the PV object
kubectl delete pv financial-transactions-pv
# Step 5b: Manually delete the actual storage (EBS volume, NFS share, etc.)
# This must be done outside Kubernetes
```

**Key Points:**
- `persistentVolumeReclaimPolicy: Retain` prevents automatic deletion
- When PVC is deleted, PV enters "Released" state
- Data remains intact on the storage backend
- PV cannot be reused until manually cleaned up
- Admin must manually: delete PV object + delete actual storage
- **Static Provisioning** gives admin full control over storage lifecycle
- Critical for compliance, audit, and financial data retention
- Contrast with `ReclaimPolicy: Delete` which removes both PV and data
