# Complete Tutorial: Testing DNS Resolution with netshoot Pod

This tutorial walks through creating a test pod, verifying the DNS configuration, and testing name resolution after the service CIDR rotation.

## Overview

After updating the kubelet configuration to use the new DNS ClusterIP (`100.96.0.10`), we need to verify that pods receive the correct DNS settings and can resolve both internal and external names.

## Step 1: Create the netshoot Pod

The netshoot container has a comprehensive set of networking tools for troubleshooting:

```bash
# Create the netshoot pod with a sleep command to keep it running
kubectl run netshoot --image=nicolaka/netshoot -- sleep 3600

# Alternative methods to keep the pod running:
# Method 1: Using command
kubectl run netshoot --image=nicolaka/netshoot --command -- sleep infinity

# Method 2: Using YAML
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: netshoot
spec:
  containers:
  - name: netshoot
    image: nicolaka/netshoot
    command: ["sleep"]
    args: ["3600"]
EOF
```

## Step 2: Verify Pod is Running

```bash
# Check pod status
kubectl get pod netshoot

# Get more details
kubectl get pod netshoot -o wide

# Expected output:
# NAME       READY   STATUS    RESTARTS   AGE
# netshoot   1/1     Running   0          10s
```

## Step 3: Get a Shell to the Pod

```bash
# Open an interactive bash shell in the pod
kubectl exec -it netshoot -- bash

# You should now be inside the container with a prompt like:
# bash-5.1#
```

## Step 4: Check /etc/resolv.conf

Once inside the pod, verify the DNS configuration:

```bash
# Display the resolv.conf file
cat /etc/resolv.conf
```

**Expected output:**
```
nameserver 100.96.0.10
search default.svc.cluster.local svc.cluster.local cluster.local
options ndots:5
```

**Verify the correct DNS IP:**
```bash
# Check the nameserver entry specifically
grep nameserver /etc/resolv.conf

# Should show: nameserver 100.96.0.10
```

## Step 5: Test DNS Resolution

Now test both internal and external DNS resolution:

### Test External Name Resolution

```bash
# Test example.com resolution
nslookup example.com

# Expected output:
# Server:         100.96.0.10
# Address:        100.96.0.10#53
#
# Non-authoritative answer:
# Name:   example.com
# Address: 93.184.216.34
# Name:   example.com
# Address: 2606:2800:220:1:248:1893:25c8:1946
```

### Test Using dig (more detailed)

```bash
# Use dig for more detailed DNS information
dig example.com

# Expected output includes:
# ;; Query time: X msec
# ;; SERVER: 100.96.0.10#53(100.96.0.10)
# ;; WHEN: ...
```

### Test Internal Kubernetes Service Resolution

```bash
# Test resolution of kubernetes service
nslookup kubernetes.default.svc.cluster.local

# Expected output:
# Server:         100.96.0.10
# Address:        100.96.0.10#53
#
# Name:   kubernetes.default.svc.cluster.local
# Address: 100.96.0.1

# Test CoreDNS service
nslookup kube-dns.kube-system.svc.cluster.local

# Should return the CoreDNS service IP (100.96.0.10 or similar)
```

## Step 6: Comprehensive DNS Testing

Run additional tests to ensure DNS is working properly:

```bash
# Test multiple record types
dig example.com A
dig example.com AAAA
dig example.com MX

# Test reverse DNS lookup
nslookup 93.184.216.34

# Test with different DNS query tools
host example.com
ping -c 2 example.com

# Check DNS search domain behavior
ping google.com  # Should use search domains

# Test specific DNS server directly
nslookup example.com 100.96.0.10
```

## Step 7: Exit the Pod Shell

```bash
# Exit the bash shell
exit

# You'll return to your normal terminal
```

## Step 8: Verify DNS from Outside the Pod (Optional)

```bash
# Test DNS resolution using kubectl exec without entering the pod
kubectl exec netshoot -- cat /etc/resolv.conf
kubectl exec netshoot -- nslookup example.com
kubectl exec netshoot -- dig kubernetes.default.svc.cluster.local

# Get a one-liner with all DNS info
kubectl exec netshoot -- sh -c 'echo "=== resolv.conf ==="; cat /etc/resolv.conf; echo "=== nslookup ==="; nslookup example.com'
```

## Step 9: Troubleshooting DNS Issues

If DNS lookups fail or time out, follow these troubleshooting steps:

### Check CoreDNS Status

```bash
# From your host terminal (not inside the pod)
kubectl get pods -n kube-system -l k8s-app=kube-dns

# Check CoreDNS logs for errors
kubectl logs -n kube-system -l k8s-app=kube-dns --tail=50

# Check CoreDNS service endpoints
kubectl get endpoints -n kube-system kube-dns
```

### Restart CoreDNS if Needed

```bash
# Restart CoreDNS deployment
kubectl -n kube-system rollout restart deployment/coredns

# Wait for rollout to complete
kubectl -n kube-system rollout status deployment/coredns

# Verify CoreDNS is ready
kubectl get pods -n kube-system -l k8s-app=kube-dns
```

### Check API Server Certificate

If you see TLS errors in CoreDNS logs:

```bash
# Check if the new service IP is in the API server certificate
openssl x509 -in /etc/kubernetes/pki/apiserver.crt -text | grep -A1 "Subject Alternative Name"

# Look for 100.96.0.1 in the output

# If missing, regenerate certificate with the new IP
# (refer to previous tutorial section on certificate regeneration)
```

### Test Network Connectivity to DNS Server

```bash
# From inside the netshoot pod, test connectivity to DNS server
kubectl exec netshoot -- nc -zv 100.96.0.10 53
kubectl exec netshoot -- nc -zuv 100.96.0.10 53  # UDP test

# Trace route to DNS server
kubectl exec netshoot -- traceroute 100.96.0.10
```

### Verify Kubelet DNS Configuration

```bash
# Check if the kubelet is using the new DNS
ps aux | grep kubelet | grep -o 'cluster-dns=[^ ]*'

# Check the kubelet config file
grep -A1 clusterDNS /var/lib/kubelet/config.yaml

# Check the kubelet ConfigMap
kubectl get cm -n kube-system kubelet-config -o yaml | grep -A2 clusterDNS
```

Save this script for future DNS testing:

## Step 11: Clean Up Resources

When finished testing, clean up the pod:

```bash
# Delete the netshoot pod
kubectl delete pod netshoot

# Verify it's deleted
kubectl get pod netshoot
# Expected: Error from server (NotFound): pods "netshoot" not found
```

## Complete Verification Script

Run this script to verify everything is working correctly:

```bash
#!/bin/bash

echo "=== Starting DNS Verification ==="

# 1. Create pod
echo "Creating netshoot pod..."
kubectl run netshoot --image=nicolaka/netshoot --rm -i --restart=Never -- sleep 3600 &
sleep 5

# 2. Check resolv.conf
echo -e "\n=== Checking /etc/resolv.conf ==="
kubectl exec netshoot -- cat /etc/resolv.conf

# 3. Check DNS server
echo -e "\n=== Checking DNS Server IP ==="
DNS_IP=$(kubectl exec netshoot -- grep nameserver /etc/resolv.conf | awk '{print $2}')
echo "DNS Server: $DNS_IP"

# 4. Test external resolution
echo -e "\n=== Testing External Resolution ==="
if kubectl exec netshoot -- nslookup example.com | grep -q "93.184.216.34"; then
    echo "✓ External DNS resolution successful"
else
    echo "✗ External DNS resolution failed"
fi

# 5. Test internal resolution
echo -e "\n=== Testing Internal Resolution ==="
if kubectl exec netshoot -- nslookup kubernetes.default | grep -q "100.96.0.1"; then
    echo "✓ Internal DNS resolution successful"
else
    echo "✗ Internal DNS resolution failed"
fi

# 6. Clean up
echo -e "\n=== Cleaning Up ==="
kubectl delete pod netshoot --grace-period=0 --force

echo -e "\n=== DNS Verification Complete ==="
```
