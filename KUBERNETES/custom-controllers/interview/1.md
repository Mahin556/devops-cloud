## What is a custom controller? Did you build one and how?

### What is a Custom Controller?
Custom controllers handle the **reconciliation of Custom Resource Definitions (CRDs)** .

### Simplified Explanation:
"Kubernetes does not handle every scenario you want. A basic example is the **Ingress Controller**—it doesn't come by default in your Kubernetes cluster."

### How It Works:

**Step 1: Define a Custom Resource Definition (CRD)**
- Create a new resource type that Kubernetes can understand
- Example: Istio defines `VirtualService`, `DestinationRule`, etc.

**Step 2: Deploy the CRD**
- Submit the CRD to your Kubernetes cluster
- Now Kubernetes can identify and accept your custom resources

**Step 3: Create a Custom Controller**
- The controller watches for changes to these custom resources
- It reconciles the desired state with the actual state
- Example: Istio controller watches for VirtualService changes and implements traffic routing

### Examples of Custom Controllers:
- **Ingress Controller** (NGINX, Traefik, Ambassador)
- **Istio Controller** (manages VirtualService, DestinationRule)
- **Prometheus Operator** (manages Prometheus, ServiceMonitor)
- **Argo CD** (manages Application resources)

### Interview Tip:
"If you have written a custom controller, explain it. If not, say: 'I understand the concept but haven't had a requirement to build one. I've used existing controllers like Ingress controllers and the Prometheus Operator.'"
