A Service IP (ClusterIP) is **static by default and remains unchanged for the lifetime of the Service**.

This stability is a core feature. It provides a reliable, permanent address for accessing a set of Pods, independent of the Pods' ephemeral IP addresses.

### ⚙️ How ClusterIPs are Allocated

When you create a Service, Kubernetes assigns its ClusterIP in one of two ways:

*   **Dynamic (Automatic)**: The control plane automatically picks an unused IP from the cluster's configured Service IP range. This is the default behavior.
*   **Static (Manual)**: You can specify a particular IP address from the Service IP range by setting the `spec.clusterIP` field.

> **Important**: Every Service ClusterIP in a cluster must be unique.

### 🔄 When Can a Service IP Change?

While a Service IP is static, it is not absolutely permanent and can change under specific circumstances:

*   **Deleting and recreating the Service**: If you delete a Service and then create a new one with the same name, it will be assigned a **new** ClusterIP (unless you manually specify the old one).
*   **Reconfiguring the cluster's Service CIDR**: Changing the cluster's Service IP range (`--service-cluster-ip-range`) is a disruptive operation. While it's possible to extend the range without downtime from v1.33 onward, a full reconfiguration can potentially lead to IP changes.
*   **Cloud Provider Load Balancer IPs**: For a `LoadBalancer` Service, the external IP assigned by the cloud provider might change if the Service is deleted and recreated. However, you can often request a **static public IP** from your cloud provider to persist across recreations.
*   **`ExternalName` Services**: These use a DNS alias and do not have a ClusterIP.

### 💎 Summary

To ensure reliable communication, **never hardcode Pod IPs**. Instead, always use a Service's stable ClusterIP or its fully qualified domain name (FQDN) like `my-service.my-namespace.svc.cluster.local`. This approach ensures your applications can reliably discover and connect to each other, regardless of Pod churn.
