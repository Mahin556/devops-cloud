### What is Split Brain?

Split Brain occurs when a cluster divides into two or more partitions that cannot communicate with each other, and **both partitions think they are the active leader** and start writing data independently.

#### Real-World Scenario:

Imagine a 2-node MySQL cluster with shared storage:

```
Initial State:
┌──────────────┐         ┌──────────────┐
│   Node 1     │◄───────►│   Node 2     │
│  (Leader)    │  Heartbeat │  (Member)    │
└──────┬───────┘         └──────┬───────┘
       │                        │
       └────────┬───────────────┘
                │
        ┌───────┴───────┐
        │  Shared Disk  │
        └───────────────┘
```

**Step 1: Network Partition Occurs**
```
┌──────────────┐         ┌──────────────┐
│   Node 1     │    ✗    │   Node 2     │
│  (Leader)    │  Break  │  (Member)    │
└──────┬───────┘         └──────┬───────┘
       │                        │
       │        ┌───────────────┘
       │        │
       └────────┴───────────┐
                │           │
        ┌───────┴───────────┴───┐
        │    Shared Disk        │
        └───────────────────────┘
```

**Step 2: Both Nodes Think They Are Leader**
- Node 1 thinks: "Node 2 is down, I am the leader, I will write queries"
- Node 2 thinks: "Node 1 is down, I am the leader, I will write queries"

**Step 3: Both Write to Shared Storage**
```
Node 1 writes: User A balance = $500
Node 2 writes: User A balance = $300

Result: DATA CORRUPTION!
What is the actual balance? $500 or $300?
```

### Split Brain in etcd Context:

When Kubernetes has multiple master nodes, each runs an etcd instance:

**Scenario: 3 Master Nodes, Network Partition**

```
Before Partition:
┌─────────┐    ┌─────────┐    ┌─────────┐
│Master 1 │◄──►│Master 2 │◄──►│Master 3 │
│etcd (L) │    │etcd (M) │    │etcd (M) │
└─────────┘    └─────────┘    └─────────┘
    L = Leader, M = Member
```

```
After Network Partition:
┌─────────┐         ┌─────────┐    ┌─────────┐
│Master 1 │    ✗    │Master 2 │◄──►│Master 3 │
│etcd (L) │  Break  │etcd (M) │    │etcd (M) │
└─────────┘         └─────────┘    └─────────┘
  Partition 1          Partition 2 (has 2 nodes)
  Votes: 1             Votes: 2
```

**Without Quorum:**
- Master 1 (Leader) continues writing
- Partition 2 elects a new leader and starts writing
- **Two leaders writing simultaneously → Split Brain → Data Corruption**

**With Quorum:**
- Partition 1 has 1 vote → Quorum NOT satisfied (needs 2)
- Partition 2 has 2 votes → Quorum SATISFIED (2 ≥ 2)
- Partition 2 elects new leader and continues operating
- Partition 1 (old leader) STOPS writing and shuts down
- **Only ONE leader writes → No data corruption**
