### Production deployment is scheduled, but application URL changes. How to handle this without rebuilding the Docker image?

Solution - ConfigMap per Environment:

Test Environment ConfigMap:

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: config-map-test
data:
  APP_URL: "https://test.example.com"
  DB_HOST: "test-db.example.com"
  APP_MODE: "testing"
  LOG_LEVEL: "debug"
```

Production Environment ConfigMap:

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: config-map-prod
data:
  APP_URL: "https://prod.example.com"
  DB_HOST: "prod-db.example.com"
  APP_MODE: "production"
  LOG_LEVEL: "warn"
```

Deployment Steps:

```bash
kubectl apply -f config-map-prod.yaml
kubectl apply -f deployment.yaml
```

Key Points:
- ConfigMap is the Kubernetes feature for environment-specific settings
- No need to rebuild images when config changes
- Separate ConfigMap files for each environment
- Deploy ConfigMap before the deployment
- Application reads settings via environment variables
- This approach is faster and more efficient than rebuilding images
