If you explicitly specify:

```bash
trivy fs --scanners misconfig .
```

then **Trivy will run only the `misconfig` scanner** from the scanner categories you specified.

It will **not** additionally scan for vulnerabilities or secrets.

### Compare:

```bash
trivy fs --scanners misconfig .
```

Scans:

```text
misconfig ✅
vuln      ❌
secret    ❌
```

Whereas:

```bash
trivy fs --scanners vuln,secret,misconfig .
```

scans:

```text
vuln      ✅
secret    ✅
misconfig ✅
```

### Example

```bash
# Only configuration/IaC misconfigurations
trivy fs --scanners misconfig .

# Only vulnerabilities
trivy fs --scanners vuln .

# Only secrets
trivy fs --scanners secret .

# All three
trivy fs --scanners vuln,secret,misconfig .
```

So remember:

> **`--scanners` explicitly controls which scanner types Trivy runs.**

For your CI/CD pipeline, you could therefore have:

```text
Source Security
    │
    └── trivy fs --scanners vuln,secret .

IaC Security
    │
    └── trivy fs --scanners misconfig .
          OR
        trivy config .

Build Image
    │
    └── trivy image ...
```

**One important distinction:** `misconfig` doesn't mean "scan every configuration file." It means Trivy's **misconfiguration scanner** analyzes supported configuration/IaC targets and checks them against its security policies.
