### Deploy a stateless frontend web app and a stateful database. Frontend pods can be replaced without impact. Database pods must keep their identity and store data persistently.

**Solution:**

**Frontend - Stateless (Deployment):**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: frontend
spec:
  replicas: 3                          # Scalable, interchangeable pods
  selector:
    matchLabels:
      app: frontend
  template:
    metadata:
      labels:
        app: frontend
    spec:
      containers:
      - name: web
        image: nginx:latest
        ports:
        - containerPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: frontend-service
spec:
  selector:
    app: frontend
  ports:
  - port: 80
    targetPort: 80
  type: ClusterIP
```

**Database - Stateful (StatefulSet):**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: db-service
  labels:
    app: database
spec:
  clusterIP: None                       # Headless service for stable DNS
  selector:
    app: database
  ports:
  - port: 5432
    targetPort: 5432
    name: postgres
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: database
spec:
  serviceName: db-service               # Links to headless service
  replicas: 3
  selector:
    matchLabels:
      app: database
  template:
    metadata:
      labels:
        app: database
    spec:
      containers:
      - name: postgres
        image: postgres:15
        ports:
        - containerPort: 5432
        volumeMounts:
        - name: db-data
          mountPath: /var/lib/postgresql/data
  volumeClaimTemplates:                 # Automatic PVC per pod
  - metadata:
      name: db-data
    spec:
      accessModes:
      - ReadWriteOnce                   # Each pod gets its own volume
      resources:
        requests:
          storage: 10Gi
```

**Resulting Resources:**
```
Pods:     database-0, database-1, database-2
PVCs:     db-data-database-0, db-data-database-1, db-data-database-2
DNS:      database-0.db-service.default.svc.cluster.local
          database-1.db-service.default.svc.cluster.local
          database-2.db-service.default.svc.cluster.local
```

**Key Points:**
- **Deployment** for stateless frontend - pods are interchangeable
- **StatefulSet** for stateful database - pods keep stable identity
- **Headless Service** (`clusterIP: None`) provides predictable DNS per pod
- **volumeClaimTemplates** creates dedicated PVC for each pod
- `ReadWriteOnce` ensures each pod has its own separate volume
- Frontend can scale freely; database pods maintain unique identity
- Pod names are predictable: `database-0`, `database-1`, `database-2`
