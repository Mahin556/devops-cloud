**Understanding `hostPath` Types**

Kubernetes supports several `hostPath` volume types that define how paths on the host are managed. For detailed information on supported types such as `Directory`, `File`, `Socket`, and `BlockDevice`, refer to the official documentation:

[Kubernetes Documentation - hostPath Volume Types](https://kubernetes.io/docs/concepts/storage/volumes/#hostpath-volume-types)

* The hostPath field tells Kubernetes where on the Node’s filesystem the data should be stored when using a hostPath volume.
* Kubernetes will store the PV’s data inside /tmp/demo-pv on the Node.
* The storage driver (hostPath provisioner) will create or use this directory.
* This directory is on the physical filesystem of the Node.

##### DirectoryOrCreate — App directory on node

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: dir-example
spec:
  containers:
  - name: app
    image: busybox
    command: ["sleep", "3600"]
    volumeMounts:
    - name: host-storage
      mountPath: /app-data   # Container sees this path
  volumes:
  - name: host-storage
    hostPath:
      path: /data/myapp      # Folder on node
      type: DirectoryOrCreate  # If not present → Kubernetes creates it
# THEORY:
# - Used for logs, cache, temp storage
# - Created as root:root with 0755
# - Node-local storage, not portable
```

##### File — Mount a single file from host

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: file-example
spec:
  containers:
  - name: app
    image: busybox
    command: ["sleep", "3600"]
    volumeMounts:
    - name: hosts-file
      mountPath: /etc/hosts-from-node
  volumes:
  - name: hosts-file
    hostPath:
      path: /etc/hosts   # Existing file on node
      type: File
# THEORY:
# - Used to expose specific config files
# - File must already exist
# - Pod reads host system configuration
```

##### BlockDevice — Direct disk access

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: block-example
spec:
  containers:
  - name: app
    image: busybox
    command: ["sleep", "3600"]
    volumeDevices:
    - name: disk
      devicePath: /dev/xvda   # Device inside container
  volumes:
  - name: disk
    hostPath:
      path: /dev/sda
      type: BlockDevice
# THEORY:
# - Gives container raw disk access
# - Used by storage systems like Ceph
# - Very dangerous — can destroy host data
```

##### CharDevice — Hardware device access

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: chardev-example
spec:
  containers:
  - name: app
    image: busybox
    command: ["sleep", "3600"]
    volumeMounts:
    - name: device
      mountPath: /dev/null
  volumes:
  - name: device
    hostPath:
      path: /dev/null
      type: CharDevice
# THEORY:
# - Used for devices like /dev/nvidia0 (GPU)
# - Needed for hardware workloads
# - Gives low-level hardware interaction
```

##### Socket — Control host services (Docker example)

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: socket-example
spec:
  containers:
  - name: docker-client
    image: docker
    command: ["sleep", "3600"]
    volumeMounts:
    - name: docker-sock
      mountPath: /var/run/docker.sock
  volumes:
  - name: docker-sock
    hostPath:
      path: /var/run/docker.sock
      type: Socket
# THEORY:
# - Pod can talk to host Docker daemon
# - Used by CI/CD tools like Jenkins
# - Pod can create/delete host containers
# - Major security risk (host takeover possible)
```
