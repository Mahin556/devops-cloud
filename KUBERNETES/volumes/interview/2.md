### Deploy MySQL database in Kubernetes. Data must survive pod restart and rescheduling. Storage must not be deleted when pod is recreated. Only one pod should write to storage at a time.

**Solution:**

**PersistentVolume (Static Provisioning):**
```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: mysql-pv
  labels:
    type: local
spec:
  capacity:
    storage: 20Gi
  volumeMode: Filesystem
  accessModes:
  - ReadWriteOnce                     # Only one pod can write
  persistentVolumeReclaimPolicy: Retain  # Don't delete on PVC deletion
  storageClassName: manual
  hostPath:                           # For demonstration; use cloud storage in production
    path: /data/mysql
  nodeAffinity:                       # Pin to specific node
    required:
      nodeSelectorTerms:
      - matchExpressions:
        - key: kubernetes.io/hostname
          operator: In
          values:
          - node-1
```

**PersistentVolumeClaim:**
```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: mysql-pvc
spec:
  accessModes:
  - ReadWriteOnce                     # Exclusive write access
  resources:
    requests:
      storage: 20Gi
  storageClassName: manual
  selector:
    matchLabels:
      type: local
```

**MySQL Deployment (Single Pod):**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: mysql
spec:
  replicas: 1                         # Only one pod (RWO volume)
  selector:
    matchLabels:
      app: mysql
  template:
    metadata:
      labels:
        app: mysql
    spec:
      containers:
      - name: mysql
        image: mysql:8.0
        ports:
        - containerPort: 3306
        env:
        - name: MYSQL_ROOT_PASSWORD
          valueFrom:
            secretKeyRef:
              name: mysql-secret
              key: password
        volumeMounts:
        - name: mysql-storage
          mountPath: /var/lib/mysql
      volumes:
      - name: mysql-storage
        persistentVolumeClaim:
          claimName: mysql-pvc
```

**Lifecycle Demonstration:**
```bash
# 1. Pod crashes
kubectl delete pod mysql-xxx

# 2. Deployment creates new pod
# 3. New pod mounts SAME PVC (mysql-pvc)
# 4. PV with Retain policy preserves data
# 5. MySQL data intact after pod recreation

# 6. Even if PVC is deleted, PV data survives (Retain policy)
kubectl delete pvc mysql-pvc
# PV status changes to "Released" - data NOT deleted
# Admin must manually clean up: kubectl delete pv mysql-pv
```

**Key Points:**
- **PersistentVolume** exists independently of pods - survives pod deletion
- `persistentVolumeReclaimPolicy: Retain` ensures data survives PVC deletion
- `accessModes: ReadWriteOnce` allows only one pod to write at a time
- PV must be manually cleaned up by admin with Retain policy
- Pod requests storage via PVC, not direct PV reference
- Same PVC reattaches to new pod after pod failure
- For production: use cloud storage (EBS, Azure Disk, GCE PD) instead of hostPath
