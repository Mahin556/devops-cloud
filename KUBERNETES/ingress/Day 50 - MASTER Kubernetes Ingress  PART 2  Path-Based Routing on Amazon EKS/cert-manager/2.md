# Complete Guide to ACME Challenge Process in Cert-Manager

## What is ACME Challenge?

ACME (Automatic Certificate Management Environment) is a protocol used by Certificate Authorities like Let's Encrypt to verify that you control a domain before issuing a certificate. The challenge process proves domain ownership.

## Challenge Types Overview

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         ACME Challenge Types                                │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │

│  │                    HTTP-01 Challenge                                │    │
│  │  • Most common, easiest to configure                              │    │
│  │  • Requires web server on port 80                                  │    │
│  │  • Verifies domain via HTTP endpoint                               │    │
│  │  • Works for wildcard? ❌ No                                       │    │
│  └────────────────────────────────────────────────────────────────────┘    │
│                                                                              │

│  │  • Works for wildcard certificates                                 │    │

│  │  • Creates TXT record for verification                             │    │
│  │  • Works for wildcard? ✅ Yes                                      │    │
│  └────────────────────────────────────────────────────────────────────┘    │
│                                                                              │
```

## HTTP-01 Challenge Process

### How HTTP-01 Works

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    HTTP-01 Challenge Flow                                    │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  Cert-Manager                    Let's Encrypt               Your Domain    │
│      │                                │                           │         │
│      │  1. Request Certificate        │                           │         │
│      ├───────────────────────────────►│                           │         │
│      │                                │                           │         │
│      │  2. Challenge: Create token    │                           │         │
│      │     at http://domain/.well-known/acme-challenge/token     │         │
│      │◄───────────────────────────────┤                           │         │
│      │                                │                           │         │
│      │  3. Create HTTP endpoint       │                           │         │
│      │     (Creates Ingress/Pod)      │                           │         │
│      ├───────────────────────────────────────────────────────────►│         │
│      │                                │                           │         │
│      │                                │  4. Verify token          │         │
│      │                                ├──────────────────────────►│         │
│      │                                │                           │         │
│      │                                │  5. Return validation     │         │
│      │                                │◄──────────────────────────┤         │
│      │                                │                           │         │
│      │  6. Challenge complete         │                           │         │
│      │◄───────────────────────────────┤                           │         │
│      │                                │                           │         │
│      │  7. Issue certificate          │                           │         │
│      │◄───────────────────────────────┤                           │         │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### Detailed HTTP-01 Challenge Steps

#### Step 1: Certificate Request
```yaml
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: example-com
spec:
  secretName: example-com-tls
  dnsNames:
    - example.com
  issuerRef:
    name: letsencrypt-prod
    kind: ClusterIssuer
```

#### Step 2: Cert-Manager Creates Challenge Resource
```yaml
apiVersion: acme.cert-manager.io/v1
kind: Challenge
metadata:
  name: example-com-123456-789012
  namespace: default
spec:
  authzURL: https://acme-v02.api.letsencrypt.org/acme/authz/123456
  dnsName: example.com
  solver:
    http01:
      ingress:
        class: nginx
  token: "abc123def456ghi789"
  key: "xyz789"
  type: HTTP-01
  url: https://acme-v02.api.letsencrypt.org/acme/challenge/123456/789012
```

#### Step 3: Cert-Manager Creates Temporary Resources

**Temporary Ingress:**
```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: cm-acme-http-solver-123456
  namespace: default
  annotations:
    kubernetes.io/ingress.class: nginx
    nginx.ingress.kubernetes.io/rewrite-target: /
    nginx.ingress.kubernetes.io/ssl-redirect: "false"
    acme.cert-manager.io/http01-solver: "true"
spec:
  rules:
    - host: example.com
      http:
        paths:
          - path: /.well-known/acme-challenge/abc123def456ghi789
            pathType: Exact
            backend:
              service:
                name: cm-acme-http-solver-123456
                port:
                  number: 8089
```

**Temporary Service:**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: cm-acme-http-solver-123456
  namespace: default
spec:
  ports:
    - port: 8089
      targetPort: 8089
  selector:
    acme.cert-manager.io/http01-solver: "123456"
```

**Temporary Pod:**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: cm-acme-http-solver-123456
  namespace: default
  labels:
    acme.cert-manager.io/http01-solver: "123456"
spec:
  containers:
    - name: acmesolver
      image: quay.io/jetstack/cert-manager-acmesolver:v1.13.2
      args:
        - "--listen-port=8089"
        - "--domain=example.com"
        - "--token=abc123def456ghi789"
        - "--key=xyz789"
      ports:
        - containerPort: 8089
```

#### Step 4: Let's Encrypt Validates

Let's Encrypt makes HTTP request:
```bash
curl http://example.com/.well-known/acme-challenge/abc123def456ghi789
```

Expected response:
```
abc123def456ghi789.xyz789
```

#### Step 5: Cleanup

After validation, cert-manager deletes temporary resources.

## DNS-01 Challenge Process

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    DNS-01 Challenge Flow                                     │

│      │                     │                      │                          │

│      │     _acme-challenge.example.com          │                          │
│      │◄─────────────────────────────────────────┤                          │
│      │                     │                      │                          │
│      │  3. Create TXT record                   │                          │
│      ├────────────────────►│                      │                          │
│      │                     │                      │                          │
│      │                     │  4. Verify TXT      │                          │
│      │                     │◄─────────────────────┤                          │
│      │                     │                      │                          │
│      │                     │  5. Validation      │                          │
│      │                     ├─────────────────────►│                          │
│      │                     │                      │                          │
│      │  6. Challenge complete                   │                          │
│      │◄─────────────────────────────────────────┤                          │
│      │                     │                      │                          │
│      │  7. Issue certificate                    │                          │
│      │◄─────────────────────────────────────────┤                          │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### Detailed DNS-01 Challenge Steps

#### Step 1: Certificate Request with Wildcard
```yaml
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: wildcard-example-com
spec:
  secretName: wildcard-example-com-tls
  dnsNames:
    - '*.example.com'
    - 'example.com'
  issuerRef:
    name: letsencrypt-prod
    kind: ClusterIssuer
```

#### Step 2: Cert-Manager Creates Challenge
```yaml
apiVersion: acme.cert-manager.io/v1
kind: Challenge
metadata:
  name: wildcard-example-com-123456
spec:
  dnsName: example.com
  token: "abc123def456ghi789"
  key: "xyz789"
  type: DNS-01
  solver:
    dns01:
      route53:
        region: us-east-1
        accessKeyID: AKIAIOSFODNN7EXAMPLE
        secretAccessKeySecretRef:
          name: route53-credentials
          key: secret-access-key
```

#### Step 3: Cert-Manager Creates DNS TXT Record
```bash
# The TXT record created:
_acme-challenge.example.com  TXT  "abc123def456ghi789.xyz789"
```

#### Step 4: Let's Encrypt Validates
```bash
dig TXT _acme-challenge.example.com
```

#### Step 5: Cleanup
After validation, cert-manager removes the TXT record.

## Challenge Solver Selectors

### Select by DNS Name
```yaml
solvers:
  - dns01:
      route53:
        region: us-east-1
    selector:
      dnsNames:
        - '*.example.com'
        - 'example.com'
```

### Select by DNS Zone
```yaml
solvers:
  - dns01:
      route53:
        region: us-east-1
        hostedZoneID: Z1234567890
    selector:
      dnsZones:
        - 'example.com'
```

### Select by Namespace
```yaml
solvers:
  - http01:
      ingress:
        class: nginx
    selector:
      namespaces:
        - 'production'
```

### Multiple Solvers with Selectors
```yaml
solvers:
  # Wildcard certificates using Route53
  - dns01:
      route53:
        region: us-east-1
        hostedZoneID: Z1234567890
    selector:
      dnsNames:
        - '*.example.com'
  
  # Non-wildcard using HTTP-01
  - http01:
      ingress:
        class: nginx
    selector:
      dnsNames:
        - 'example.com'
        - 'www.example.com'
  
  # Default solver
  - http01:
      ingress:
        class: nginx
```

### Watch Challenges in Real-Time
```bash
# Watch challenges
kubectl get challenges -A -w

# Watch orders
kubectl get orders -A -w

# Watch certificaterequests
kubectl get certificaterequests -A -w
```

### Check Challenge Status
```bash
# List challenges
kubectl get challenges -A

# Describe a challenge
kubectl describe challenge example-com-123456 -n default

# Check challenge logs
kubectl logs -n cert-manager deployment/cert-manager | grep -i challenge
```

### Challenge States
```yaml
Challenge States:
  - pending: Challenge created, waiting for validation
  - processing: Validation in progress
  - valid: Challenge passed, certificate can be issued
  - invalid: Challenge failed
  - expired: Challenge timed out
  - errored: Technical error occurred
```

## Troubleshooting Challenges

### HTTP-01 Common Issues

#### Issue: Ingress Controller Not Found
```bash
# Check if ingress controller is running
kubectl get pods -n ingress-nginx

# Check ingress class
kubectl get ingressclass
```

#### Issue: Port 80 Not Accessible
```bash
# Check if port 80 is exposed
kubectl get svc -n ingress-nginx

# Check firewall rules
# Ensure port 80 is open to the internet
```

#### Issue: Temporary Resources Not Created
```bash
# Check for solver pods
kubectl get pods -A | grep acme-solver

# Check for solver ingresses
kubectl get ingress -A | grep cm-acme

# Check cert-manager logs
kubectl logs -n cert-manager deployment/cert-manager --tail=100
```

### DNS-01 Common Issues

#### Issue: DNS Provider Credentials Invalid
```bash
# Check secret exists
kubectl get secret route53-credentials -n cert-manager

# Verify credentials are correct
kubectl get secret route53-credentials -n cert-manager -o yaml
```

#### Issue: TXT Record Not Created
```bash
# Check DNS logs in cert-manager
kubectl logs -n cert-manager deployment/cert-manager | grep -i "dns"

# Check provider specific logs
kubectl logs -n cert-manager deployment/cert-manager | grep -i "route53"
```

#### Issue: DNS Propagation Delay
```bash
# Check if record was created
dig TXT _acme-challenge.example.com

# Force DNS check
kubectl patch challenge example-com-123456 -p '{"status":{"state":"pending"}}' --type=merge
```

## Best Practices

### 1. Use Staging Environment First
```yaml
# Staging issuer (no rate limits)
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: letsencrypt-staging
spec:
  acme:
    server: https://acme-staging-v02.api.letsencrypt.org/directory
    email: admin@example.com
    privateKeySecretRef:
      name: letsencrypt-staging-private-key
    solvers:
      - http01:
          ingress:
            class: nginx
```

### 2. Set Appropriate Selectors
```yaml
solvers:
  - dns01:
      route53:
        region: us-east-1
    selector:
      dnsZones:
        - 'example.com'  # Only use DNS-01 for this zone
  - http01:
      ingress:
        class: nginx
    selector:
      dnsNames:
        - '*.internal.example.com'  # HTTP-01 doesn't work for wildcards!
```

### 3. Monitor Challenge Resources
```bash
# Set up alerts for failed challenges
kubectl get challenges -A -o json | jq '.items[] | select(.status.state != "valid")'
```

### 4. Use HTTP-01 for Simple Setups
- ✅ Easier to configure
- ✅ No API keys needed
- ❌ Doesn't support wildcards
- ❌ Requires port 80 accessible

### 5. Use DNS-01 for Advanced Setups
- ✅ Supports wildcard certificates
- ✅ Works without public ingress
- ✅ More secure (no open ports)
- ❌ Requires DNS provider API access

## Summary

The challenge process is the core of certificate automation:

1. **HTTP-01**: Simple, no API keys, doesn't support wildcards
2. **DNS-01**: Supports wildcards, requires DNS API access
3. **TLS-ALPN-01**: Alternative to HTTP-01, uses TLS

Key concepts:
- **Challenges**: Proof of domain ownership
- **Orders**: Group of challenges for a certificate
- **Solvers**: How cert-manager responds to challenges
- **Selectors**: Which solver to use for which domains

Understanding the challenge process helps you:
- Configure cert-manager correctly
- Troubleshoot certificate issues
- Choose the right solver for your use case
- Implement wildcard certificates
- Secure your applications with automated TLS!
