##  PVC (PersistentVolumeClaim) is not bound even though PV (PersistentVolume) exists.

### Storage Concept:
- **StorageClass:** Defines the type of storage (NFS, AWS EBS, Azure Disk, etc.)
- **PV:** The actual storage volume from the storage class
- **PVC:** A claim/request for a portion of a PV

### Common Causes:

**1. StorageClass Mismatch:**
- PV has one storage class, PVC requests a different one

**2. Access Mode Mismatch:**
- PVC asks for `ReadWriteMany` but PV only supports `ReadWriteOnce`
- Common access modes:
  - `ReadWriteOnce` (RWO) - Single node read/write
  - `ReadOnlyMany` (ROX) - Multiple nodes read only
  - `ReadWriteMany` (RWX) - Multiple nodes read/write

**3. Node Affinity/Zone Restrictions:**
- PV has node affinity that doesn't match pod's scheduling
- Zone restrictions prevent binding

### How to Fix:
```bash
# Check PVC status
kubectl describe pvc <pvc-name>

# Check PV details
kubectl describe pv <pv-name>

# Ensure matching:
# - Storage class name
# - Access mode
# - Zone/node affinity
```
