The `pathType` field tells the Ingress controller **how it should compare the incoming request URL with the path you defined**.

Suppose you have:

```yaml
spec:
  rules:
  - host: example.com
    http:
      paths:
      - path: /api
        pathType: ?
        backend:
          service:
            name: api-service
            port:
              number: 80
```

When a request arrives:

```text
GET /api
GET /api/
GET /api/users
GET /apis
```

the Ingress controller decides whether this rule matches based on `pathType`.

---

# 1. Exact

```yaml
path: /api
pathType: Exact
```

This means:

> Match the URL **exactly**.

## Matches

```text
/api
```

## Does NOT match

```text
/api/
/api/users
/apis
/api123
```

Visualization:

```text
Incoming URL

/api            ✔
/api/           ✘
/api/users      ✘
/apis           ✘
```

Example

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
spec:
  rules:
  - host: app.example.com
    http:
      paths:
      - path: /login
        pathType: Exact
        backend:
          service:
            name: login-service
            port:
              number: 80
```

Requests

| Request       | Match |
| ------------- | ----- |
| `/login`      | ✅     |
| `/login/`     | ❌     |
| `/login/user` | ❌     |

Use `Exact` when the endpoint should exist only at one URL.

Examples:

```text
/healthz
/metrics
/login
/logout
```

---

# 2. Prefix

This is the most commonly used path type.

```yaml
path: /api
pathType: Prefix
```

It matches based on **path elements** separated by `/`.

Think of it as:

```text
/api
     │
     ├── anything after /
```

## Matches

```text
/api
/api/
/api/users
/api/orders
/api/v1/products
```

## Does NOT match

```text
/apis
/api123
/ap
```

Notice:

```text
/api      ✔
/apis     ✘
```

because Kubernetes compares **path segments**, not simple string prefixes.

Visualization

```text
/api
   │
   ├── users
   ├── products
   ├── orders
   └── anything...
```

Example

```yaml
path: /payment
pathType: Prefix
```

Matches

```text
/payment
/payment/
/payment/status
/payment/orders
/payment/v1
```

Doesn't match

```text
/payment-service
/payment123
```

---

## How Prefix works internally

Suppose

```yaml
path: /foo/bar
```

Kubernetes splits the URL:

```text
/foo/bar

↓

foo
bar
```

Now compare

```
/foo/bar/test
```

↓

```
foo
bar
test
```

First two segments match

✔

Now

```
/foo/bar2
```

↓

```
foo
bar2
```

Second segment differs

✘

---

# 3. ImplementationSpecific

This depends entirely on the Ingress controller.

Kubernetes itself says:

> "The meaning of this path type is up to the Ingress controller."

Different controllers behave differently.

Examples

* ingress-nginx
* Traefik
* HAProxy
* Istio
* Kong

can all interpret it differently.

---

## Ingress-NGINX

With

```yaml
pathType: ImplementationSpecific
```

and

```yaml
nginx.ingress.kubernetes.io/use-regex: "true"
```

the path becomes a **regular expression**.

Example

```yaml
annotations:
  nginx.ingress.kubernetes.io/use-regex: "true"

paths:
- path: /api/.*
  pathType: ImplementationSpecific
```

Matches

```text
/api
/api/
/api/users
/api/v1/orders
```

Another example

```yaml
path: /v[0-9]+
```

Matches

```text
/v1
/v2
/v99
```

Doesn't match

```text
/version
```

---

# Regex example

```yaml
annotations:
  nginx.ingress.kubernetes.io/use-regex: "true"

paths:
- path: /shop/(.*)
  pathType: ImplementationSpecific
```

Matches

```text
/shop
/shop/
/shop/books
/shop/books/python
```



```
/api/users
```

```
Prefix
```

↓

```
api-service
```

```
Regex

```


# Longest match wins

Suppose

```yaml
/api
```

and

```yaml
/api/v1
```

Both are Prefix.

Request

```text
/api/v1/users
```

Which wins?

```
/api
/api/v1
```

The longest matching path wins.

Therefore

```
/api/v1
```

is selected.

# Summary

| Path Type                  | `/api`                    | `/api/` | `/api/users` | `/apis` | Regex Support                                    |
| -------------------------- | ------------------------- | ------- | ------------ | ------- | ------------------------------------------------ |
| **Exact**                  | ✅                         | ❌       | ❌            | ❌       | No                                               |
| **Prefix**                 | ✅                         | ✅       | ✅            | ❌       | No                                               |
| **ImplementationSpecific** | Depends on the controller | Depends | Depends      | Depends | Yes (for ingress-nginx with `use-regex: "true"`) |

## Which one should you use?

* **Exact**: Single endpoints such as `/login`, `/healthz`, `/metrics`, or `/ready`.
* **Prefix**: Most web applications and APIs, such as `/api`, `/app`, `/payment`, or `/checkout`.
* **ImplementationSpecific**: When you need controller-specific features like regular expressions or custom matching behavior. For portability across different Ingress controllers, prefer `Exact` or `Prefix` unless you specifically need those advanced features.
