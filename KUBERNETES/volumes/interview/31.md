## I want to increase the size of a PV in Kubernetes. Is it possible?

**Answer:** It depends on the **underlying storage**:

- PV itself doesn't have the property to expand
- PV depends on the **backend storage** (the actual partition/disk)
- If the underlying storage supports volume expansion (e.g., AWS EBS with expansion enabled), then you CAN expand the PV
- If the underlying storage does NOT support expansion (e.g., standard partition on local disk), you CANNOT expand from Kubernetes side

**Key Point:**
"PV says this is not my property. Your underlying storage is the one that needs to support expansion."

**Requirements for PV Expansion:**
1. StorageClass must have `allowVolumeExpansion: true`
2. Underlying storage must support online expansion
3. Filesystem must support resize (e.g., ext4, xfs)

---

## Summary: The Four Key Terms in Kubernetes Storage

| Term | Role | Scope |
|------|------|-------|
| **PV** | Represents physical storage | Cluster-wide |
| **PVC** | Request for storage | Namespace |
| **StorageClass** | Defines storage policies for dynamic provisioning | Cluster-wide |
| **CSI** | Plugin that connects Kubernetes to storage backend | Cluster-wide (installed) |

---

## Complete Flow Comparison

### Static Provisioning:
```
Admin creates PV → Developer creates PVC → PVC binds to PV → Pod uses PVC
(StorageClass NOT involved)
```

### Dynamic Provisioning:
```
Developer creates PVC (with storageClassName) → StorageClass → CSI Provisioner → PV auto-created → Binds to PVC → Pod uses PVC
(StorageClass + CSI BOTH involved)
```
