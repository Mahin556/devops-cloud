### Setting up Cassandra cluster with StatefulSet. Each pod must be directly reachable by its own hostname for replication and consistency.

**Solution - Headless Service:**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: cassandra                        # Headless service name
  labels:
    app: cassandra
spec:
  clusterIP: None                        # KEY: Makes it headless
  selector:
    app: cassandra
  ports:
  - port: 9042                           # Cassandra CQL port
    targetPort: 9042
    name: cql
```

**StatefulSet for Cassandra:**
```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: cassandra
spec:
  serviceName: cassandra                 # References headless service
  replicas: 3
  selector:
    matchLabels:
      app: cassandra
  template:
    metadata:
      labels:
        app: cassandra
    spec:
      containers:
      - name: cassandra
        image: cassandra:latest
        ports:
        - containerPort: 9042
          name: cql
```

**DNS Records Created:**
```
cassandra-0.cassandra.default.svc.cluster.local
cassandra-1.cassandra.default.svc.cluster.local
cassandra-2.cassandra.default.svc.cluster.local
```

**Key Points:**
- **Headless Service** (`clusterIP: None`) doesn't provide load balancing
- Creates individual DNS A records for each pod
- Each pod is directly addressable by its unique DNS name
- Essential for StatefulSet applications like Cassandra, MongoDB, Kafka
- Enables peer-to-peer communication for replication
- Pods can discover each other by predictable DNS names
- No virtual IP - DNS queries return pod IPs directly
- Order: cassandra-0, cassandra-1, cassandra-2 (stable network identity)
