## How etcd Leader Election Works?

### The RAFT Consensus Algorithm:

etcd uses the **RAFT algorithm** for:
1. Leader Election
2. Log Replication (data synchronization)

### Leader Election Process:

```
Initial State: 3 etcd nodes
┌─────────┐    ┌─────────┐    ┌─────────┐
│  Node A │    │  Node B │    │  Node C │
│  Vote=1 │    │  Vote=1 │    │  Vote=1 │
│ Follower│    │ Follower│    │ Follower│
└─────────┘    └─────────┘    └─────────┘
```

**Step 1: Election Timeout**
- Each follower has a random election timeout (150-300ms)
- Node B's timeout expires first → becomes Candidate
- Node B votes for itself (Vote count: B=1)
- Node B sends "Vote for me" to A and C

**Step 2: Voting**
- Node A receives request → votes for B (Vote count: B=2)
- Node C receives request → votes for B (Vote count: B=3)
- Node B has majority (3/3) → becomes **Leader**

```
┌─────────┐    ┌─────────┐    ┌─────────┐
│  Node A │    │  Node B │    │  Node C │
│ Follower│    │ LEADER  │    │ Follower│
│  Vote=1 │    │  Vote=1 │    │  Vote=1 │
└─────────┘    └─────────┘    └─────────┘
```

**Step 3: Leader Sends Heartbeats**
- Leader B continuously sends heartbeats to A and C
- If followers don't receive heartbeat → new election

**Step 4: Leader Fails**
- Leader B crashes
- Followers A and C stop receiving heartbeats
- New election triggered
- A or C becomes new leader
