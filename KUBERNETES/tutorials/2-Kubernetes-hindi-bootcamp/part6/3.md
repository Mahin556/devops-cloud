* `controller.kubernetes.io/pod-deletion-cost` (an annotation) --> 
  - **How it works**: You assign a numeric cost to a Pod. The controller deletes Pods with the **lowest cost first**.
  - **Default**: If not set, the cost is `0`.
  - **Use Case**: If you want to protect a specific Pod(high traffic serving) (e.g., it has a warm cache or is handling active traffic), set a **high** cost (e.g., `100`). Kubernetes will delete all cheaper Pods first, leaving this one until the very end.
  **Example YAML snippet:**
  ```yaml
  metadata:
    annotations:
      controller.kubernetes.io/pod-deletion-cost: "100"
  ```
* Node Spread (Automatic Balancing)
  If multiple Pods have the **same** deletion cost (or no annotation), the controller looks at which nodes they are running on.
  - **The Rule**: It favors deleting Pods that are on **nodes with more replicas** of that application.
  - **Why?**: This helps rebalance the remaining Pods across the cluster. Instead of leaving all 3 remaining Pods on a single node, it tries to spread them out.
  - **Example**: 
    - Node A has **3** Pods of your app.
    - Node B has **2** Pods.
    - When scaling down from 5 to 4, the controller will delete a Pod from **Node A** (because it has more).

- **Age of Pod**: A newly created Pod is deleted first.
