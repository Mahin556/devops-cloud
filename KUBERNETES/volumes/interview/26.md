## What is PV and PVC? Explain the Architecture.

### PersistentVolume (PV):
- **Scope:** Cluster-wide (not namespace-specific)
- **Creator:** Kubernetes administrator
- **Content:** Storage backend information (NFS server IP, path, etc.)
- **State:** Available → Bound → Released
- **Lifecycle:** Independent of any pod

### PersistentVolumeClaim (PVC):
- **Scope:** Namespace-specific
- **Creator:** Developer/Deployment team
- **Content:** Storage request (size, access mode, etc.)
- **Purpose:** Claims a PV for use in a namespace
- **Binding:** One PV can only be bound to one PVC at a time

### Flow:
```
Admin creates PV → Available state
Developer creates PVC → Binds to PV → PV becomes Bound
Pod references PVC → Pod writes data to PV
```
