This statement explains **why `target-type: ip` only works when Pod IPs are reachable from the VPC**. Let’s break it down in a practical way.

---

# Main Idea

When using `target-type: ip` with the **AWS Load Balancer Controller**, the **AWS Application Load Balancer** sends traffic **directly to Pod IPs**, not nodes.

So:

```text
Client → ALB → Pod IP → Container
```

For this to work:

> The VPC must be able to reach Pod IPs directly.

---

# 1. Why Pod IP Must Be Routable

With `target-type: ip`:

```text
ALB → 10.0.2.15:5678 (Pod IP)
```

If the VPC **cannot reach that Pod IP**, traffic fails.

So Pod IPs must exist inside the VPC network.

---

# 2. Works Automatically with Amazon VPC CNI

With **Amazon VPC CNI**:

* Pods get **real VPC IPs**
* Pods behave like EC2 instances
* ALB can reach Pods directly

Example:

```text
Node IP: 10.0.1.10
Pod IP:  10.0.2.25  ← Real VPC IP
```

So:

```text
ALB → Pod IP → Works
```

---

# 3. Does NOT Work with Overlay Networks

Overlay CNIs like:

* Calico (overlay mode)
* Cilium (tunnel mode)

Use internal Pod networks like:

```text
Pod IP: 192.168.x.x
Pod IP: 172.16.x.x
```

These are **not visible to the VPC**.

So:

```text
ALB → Pod IP → FAILS
```

Because AWS cannot route to those IPs.

---

# 4. Overlay Mode Example (Broken)

```text
ALB
 ↓
VPC Network
 ↓
Node
 ↓
Overlay Network
 ↓
Pod (192.168.1.10)
```

ALB cannot see:

```text
192.168.1.10 ❌
```

---

# 5. ENI Mode (Works)

When Calico or Cilium run in **VPC-native (ENI mode)**:

Pods get VPC IPs:

```text
Pod: 10.0.2.50
```

Now ALB can reach them:

```text
ALB → 10.0.2.50 → Works
```

---

# 6. Instance Mode vs IP Mode

## Instance Mode

```text
ALB → Node → kube-proxy → Pod
```

Works everywhere.

## IP Mode

```text
ALB → Pod
```

Needs routable Pod IPs.

---

# 7. Practical Rule

Use `target-type: ip` only if:

```text
Pod IP is inside VPC CIDR
```

Check:

```bash
kubectl get pods -o wide
```

If you see:

```text
10.x.x.x  → OK
192.168.x.x → Not OK
```

---

# 8. Why IP Mode is Faster

Instance mode:

```text
ALB → Node → kube-proxy → Pod
```

IP mode:

```text
ALB → Pod
```

One less hop.

---

# 9. Simple Summary

`target-type: ip` works only when:

* Pod IPs are routable
* VPC can reach Pods
* CNI supports VPC-native mode

Fails when:

* Overlay networking
* Tunnel mode
* Pod IPs hidden from VPC
