## 30. How Does Kubernetes Manage Storage Orchestration?

Kubernetes manages storage orchestration using objects like:

* PersistentVolumes (PV)
* PersistentVolumeClaims (PVC)
* StorageClasses
* CSI Drivers

This allows applications to use persistent storage independently of the underlying storage provider.

---

# Why Storage Orchestration Is Needed

Containers are:

* Ephemeral

When a container restarts:

* Local container storage is lost.

Kubernetes storage orchestration provides:

* Persistent storage
* Dynamic provisioning
* Portable storage management

---

# Key Components

# 1. PersistentVolume (PV)

A PersistentVolume represents:

* Actual storage resource in the cluster.

It can be:

* Manually created
* Dynamically provisioned

Examples:

* AWS EBS volume
* NFS storage
* Azure Disk
* Ceph volume

---

## Example PV

```yaml id="5m2p8"
apiVersion: v1
kind: PersistentVolume

spec:
  capacity:
    storage: 10Gi
```

---

# 2. PersistentVolumeClaim (PVC)

A PVC is:

* A storage request made by a Pod/application.

Applications do not directly use PVs.
Instead:

* They request storage using PVCs.

---

## Example PVC

```yaml id="8k1n4"
apiVersion: v1
kind: PersistentVolumeClaim

spec:
  accessModes:
    - ReadWriteOnce

  resources:
    requests:
      storage: 5Gi
```

---

# How PV and PVC Work Together

```text id="3x7q2"
Application
     ↓
PVC Request
     ↓
Kubernetes Matches PV
     ↓
Storage Attached to Pod
```

---

# 3. StorageClass

A StorageClass defines:

* Type of storage
* Provisioning behavior
* Performance characteristics

Examples:

* SSD
* HDD
* Encrypted storage

---

## Example StorageClass

```yaml id="6v1m5"
apiVersion: storage.k8s.io/v1
kind: StorageClass

provisioner: ebs.csi.aws.com
```

---

# Dynamic Provisioning

Without StorageClass:

* Admin manually creates PVs

With StorageClass:

* Kubernetes automatically creates storage when PVC is requested.

This is called:

* Dynamic Provisioning

---

# 4. CSI (Container Storage Interface)

CSI is the standard interface between:

* Kubernetes
* Storage providers

It enables Kubernetes to work with:

* Cloud storage
* SAN/NAS systems
* Distributed storage platforms

in a vendor-independent way.

---

# Examples of CSI Drivers

| Storage Provider | CSI Driver            |
| ---------------- | --------------------- |
| AWS EBS          | ebs.csi.aws.com       |
| Azure Disk       | disk.csi.azure.com    |
| Google PD        | pd.csi.storage.gke.io |
| Ceph             | ceph-csi              |

---

# Storage Orchestration Workflow

```text id="2k8n7"
Pod Created
     ↓
PVC Requested
     ↓
StorageClass Invokes CSI Driver
     ↓
Storage Provisioned Automatically
     ↓
PV Bound to PVC
     ↓
Volume Mounted into Pod
```

---

# Access Modes

| Access Mode         | Meaning                   |
| ------------------- | ------------------------- |
| ReadWriteOnce (RWO) | Mounted by one node       |
| ReadOnlyMany (ROX)  | Multiple read-only nodes  |
| ReadWriteMany (RWX) | Multiple read/write nodes |

Database Pod:

* Requests 100Gi PVC
* StorageClass provisions SSD volume

# Interview-Ready Answer

“Kubernetes manages storage orchestration using PersistentVolumes, PersistentVolumeClaims, StorageClasses, and CSI drivers. Applications request storage through PVCs, and Kubernetes either binds them to existing PersistentVolumes or dynamically provisions new storage using a StorageClass and CSI driver. The Container Storage Interface (CSI) provides a standard way for Kubernetes to integrate with different storage providers like AWS EBS, Azure Disk, or Ceph.”
