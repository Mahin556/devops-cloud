# 1. Basic Application Setup
Example:
* App Pod → Running website
* MySQL Pod → Database
* MySQL Service → Internal access (ClusterIP)

Database is internal:
```
App → mysql-service → MySQL Pod
```
Users cannot access ClusterIP services directly.

---
# 2. Exposing Application (NodePort)
First method is **NodePort**:
```
User → NodeIP:30080 → Service → Pods
```
Example:
```
http://192.168.1.10:30080
```
Problems:
* Must use IP
* Must use port
* Not production-friendly
* User can't remember the IP and PORT
---

# 3. Add DNS Mapping
Instead of IP:
```
my-online-store.com → NodeIP
```
Now users access:
```
http://my-online-store.com:30080
```
Still problem:
* Port number required

---

# 4. Add Proxy Server
Add a proxy:
```
User → Proxy(80) → NodePort(30080) → Service → Pods
```
Now users access:
```
http://my-online-store.com
```
Better but:
* Manual setup
* Hard to manage

---

# 5. Cloud LoadBalancer Service(automatic)
If using cloud like:
* AWS
* GCP
* Azure
You can use:
```
Service Type = LoadBalancer
```
Flow:
```
User → Cloud LoadBalancer → Service → Pods
```
Kubernetes automatically creates:
* External IP
* Load balancer
Example:
```
http://35.1.2.3
```
DNS:
```
my-online-store.com → 35.1.2.3
```

---

# 6. Multiple Services Problem

Now you add:
* Wear Service
* Video Service
Without ingress:
```
Wear → LoadBalancer → IP1
Video → LoadBalancer → IP2
```
Example:
```
wear.com → 34.1.1.1
video.com → 35.2.2.2
```
Problems:
* Multiple IPs
* Expensive
* Hard to manage
* Multiple LoadBalancers
* Multiple SSL configs

---

# 7. Path Based Routing Requirement
You want:
```
my-online-store.com/wear
my-online-store.com/video
```
But LoadBalancer can't route by path.
So you need another load balancer:
```
User
  ↓
Main LoadBalancer
  ↓
Wear LB → Wear Service
Video LB → Video Service
```
Too complex and expensive.

---

# 8. What Ingress Does
Ingress provides:
```
User
  ↓
Ingress
  ↓
Services
  ↓
Pods
```
Single entry point.

---

# 9. Ingress Routing Example
```
my-online-store.com/wear  → wear-service
my-online-store.com/video → video-service
```
Ingress rules:
```
Path routing
Host routing
SSL
Load balancing
```

---
# 10. Ingress Architecture
```
Internet
   ↓
LoadBalancer
   ↓
Ingress Controller
   ↓
Services
   ↓
Pods
```
Ingress Controller examples:
* NGINX
* Traefik
* AWS ALB

# 15. Example Ingress YAML

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: store-ingress
spec:
  rules:
  - host: my-online-store.com
    http:
      paths:
      - path: /wear
        pathType: Prefix
        backend:
          service:
            name: wear-service
            port:
              number: 80

      - path: /video
        pathType: Prefix
        backend:
          service:
            name: video-service
            port:
              number: 80
```

# 17. Key Point (Very Important)

Ingress is NOT a LoadBalancer.

Ingress needs:

```
Ingress Controller
```

Examples:

* nginx-ingress
* traefik
* alb ingress
