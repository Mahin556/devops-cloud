### WHY YOU SHOULD NEVER RUN CONTAINERS / PODS AS ROOT
By default, containers run as UID 0 (root) unless specified otherwise.
- Root inside a container ≠ Root on the host (by default).
- Container root is restricted by:
  - Linux namespaces (PID, NET, MOUNT, USER)
  - cgroups
  - Seccomp
  - Capabilities

BUT…
- Container root still has MANY Linux capabilities.
- If compromised, attacker gains strong control inside container.

#### Running container/pod as Non-Root user
```bash
kubectl delete pod root-pod

# Effect:
# - Container runs as normal user
# - No root privileges
# - No dangerous Linux capabilities
#
# Inside container:
#   id                   -> uid=10001
#   capsh --print        -> Current: =
#   yum install          -> Permission denied

# WHY NON-ROOT CONTAINERS ARE SECURE
# - No privilege escalation
# - No package installation
# - Reduced blast radius if compromised
# - Enforces immutable infrastructure
# - Aligns with Zero Trust principles

kubectl apply -f -<<EOF
apiVersion: v1
kind: Pod
metadata:
  name: nonroot-pod
spec:
  securityContext:
    runAsNonRoot: true
    runAsUser: 1001
  containers:
  - name: demo
    image: registry.access.redhat.com/ubi8/ubi
    command: ["sleep", "3600"]
EOF

kubectl exec -it nonroot-pod -- bash
id
# uid=1001 gid=0(root) groups=0(root) #User  is part of root group
```
