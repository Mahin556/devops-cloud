A Kubernetes `ResourceQuota` is an object that limits total aggregate resource consumption and object counts per namespace. It ensures fair resource sharing and prevents single teams or workloads from monopolizing cluster CPU, memory, storage, or object totals.

- Compute Resources: Total CPU and memory requests and limits (requests.cpu, limits.memory, etc.).
- Storage Resources: Persistent volume claims and total storage requests (requests.storage, persistentvolumeclaims).
- Object Counts: Maximum allowed quantities for API objects like pods, services, configmaps, and secrets.

#### How It Works
- Namespace Scope: Quotas apply strictly within individual namespaces.
- Admission Control: The API server checks incoming resource creation requests against active quotas.
- Rejection: If a new pod or object pushes usage past the hard limit, creation is blocked immediately.
- Enforced Requests/Limits: Setting a CPU or memory quota requires new pods to explicitly declare requests or limits.

#### Troubleshooting
- When a ResourceQuota has compute requirements, EVERY pod must specify requests/limits. The quota enforces this.
  - `kubectl get events --sort-by='.lastTimestamp'`
  - `kubectl describe resourcequota <quota-name>`
