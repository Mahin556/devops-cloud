### You're managing a Kubernetes cluster shared by multiple teams working on different projects. How would you isolate their resources and avoid naming conflicts?

## Kubernetes Namespaces

To isolate resources and avoid naming conflicts in a shared Kubernetes cluster, we use **Namespaces**.

A Namespace divides a Kubernetes cluster into multiple virtual environments, allowing different teams or projects to work independently inside the same cluster.

---

## Benefits of Namespaces

### 1. Resource Isolation

* Each team gets its own namespace.
* Prevents accidental interference between teams.

### 2. Avoids Naming Conflicts

* Same resource names can exist in different namespaces.

Example:

```text id="5m2p8"
team-a/web-service
team-b/web-service
```

### 3. Access Control

* Use RBAC (Role-Based Access Control) to control permissions for each namespace.

### 4. Resource Quotas

* Limit CPU, memory, and storage usage per namespace.

---

## Example

```bash id="8k1n4"
kubectl create namespace team-a
```

Deploy resources inside a namespace:

```bash id="3x7q2"
kubectl apply -f app.yaml -n team-a
```

---

### Simple Interview Answer

“In Kubernetes, Namespaces are used to isolate resources between teams or projects within the same cluster. They help avoid naming conflicts, provide access control using RBAC, and allow resource quota management.”
