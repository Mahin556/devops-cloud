Perfect! Now that you have the exact cgroup path for that Docker container scope, here are **3 ways** to see its memory and CPU limits. 

Since this is a Docker container, **Method 1 (Docker commands)** is the easiest and most human-readable. Methods 2 and 3 show you the raw systemd/cgroup data.

---

### Method 1: Using Docker (Easiest & Recommended)
Your scope name contains the full Docker container ID: `543dd4e96c046c3575c6e1da83a85be03f3299a5351674755493dd70e15e25d2`

**To see the configured limits (in MB/GB/CPUs):**
```bash
docker inspect 543dd4e96c046c3575c6e1da83a85be03f3299a5351674755493dd70e15e25d2 | grep -E "Memory|Cpu"
```
Or for a cleaner output with specific fields:
```bash
docker inspect 543dd4e96c046c3575c6e1da83a85be03f3299a5351674755493dd70e15e25d2 --format='Memory Limit: {{.HostConfig.Memory}} bytes | CPU Shares: {{.HostConfig.CpuShares}} | CPU Quota: {{.HostConfig.CpuQuota}}'
```

**To see real-time usage** (memory used right now, CPU %):
```bash
docker stats 543dd4e96c046c3575c6e1da83a85be03f3299a5351674755493dd70e15e25d2 --no-stream
```

---

### Method 2: Using systemctl (systemd properties)
Use `systemctl show` on the exact scope name:

```bash
systemctl show docker-543dd4e96c046c3575c6e1da83a85be03f3299a5351674755493dd70e15e25d2.scope | grep -E "MemoryMax|MemoryHigh|CPUQuota|TasksMax"
```
- **`MemoryMax`** = Hard memory limit (in bytes). If empty or missing, there is **no limit**.
- **`CPUQuota`** = CPU time limit. Example: `50%` means half a core. If empty, there is **no limit**.

---

### Method 3: Reading Cgroup Files Directly (Raw kernel values)
Since your system uses cgroups v2, you can read the limit files directly from the exact path shown in your `systemd-cgls` output.

**Memory limit (hard):**
```bash
cat /sys/fs/cgroup/system.slice/docker-543dd4e96c046c3575c6e1da83a85be03f3299a5351674755493dd70e15e25d2.scope/memory.max
```
- Output `max` means **unlimited**.
- Output a number (e.g., `1073741824`) means 1 GB.

**CPU limit (quota/period):**
```bash
cat /sys/fs/cgroup/system.slice/docker-543dd4e96c046c3575c6e1da83a85be03f3299a5351674755493dd70e15e25d2.scope/cpu.max
```
- Output `max 100000` means **unlimited**.
- Output `50000 100000` means 50% of a single CPU core.

---

### Bonus: See Current *Usage* (not just limits) for this container
To see how much memory and CPU it is *currently using* via the cgroup filesystem:

```bash
# Current memory usage in bytes
cat /sys/fs/cgroup/system.slice/docker-543dd4e96c046c3575c6e1da83a85be03f3299a5351674755493dd70e15e25d2.scope/memory.current

# Current CPU usage stats (user + system time)
cat /sys/fs/cgroup/system.slice/docker-543dd4e96c046c3575c6e1da83a85be03f3299a5351674755493dd70e15e25d2.scope/cpu.stat
```

### Quick Tip for the Future
If you just want to see limits for a running container but don't want to type the long ID, use the first 12 characters:
```bash
docker inspect 543dd4e96c04 --format '{{.HostConfig.Memory}}'
```
Docker will automatically match the unique prefix. 

Try **Method 1** first—it will give you the limits in Megabytes/Gigabytes directly, which is much easier to read than raw bytes!
