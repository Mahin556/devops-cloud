**No — all containers in a pod share exactly one IP address.** This is a fundamental design decision, not a limitation.

## Why They Share One IP

Going back to what we covered about namespaces — all containers in a pod share the **same network namespace**, which means they share:

```
Pod IP: 10.244.1.5  (one IP for the entire pod)
         │
         ├── container A (nginx)      → also on 10.244.1.5
         ├── container B (fluentd)    → also on 10.244.1.5
         └── container C (envoy)      → also on 10.244.1.5

All three containers share:
  - same IP address
  - same network interfaces (eth0)
  - same routing table
  - same port space
```

The **pause container** is what holds this shared network namespace open, as we covered earlier.

## What This Means Practically

**Containers communicate via localhost:**
```bash
# nginx on port 80, fluentd on port 24224
# From inside container A:
curl localhost:24224   # reaches fluentd directly
curl localhost:80      # reaches nginx directly

# No pod-to-pod hop needed — it's just localhost
```

**Port conflicts become YOUR problem:**
```yaml
containers:
  - name: app
    ports:
      - containerPort: 8080    # ✅ fine
  - name: sidecar
    ports:
      - containerPort: 8080    # ❌ CONFLICT — same IP, same port
                                #    one will fail to bind
```

## Can You Work Around It?

**No real workaround** — this is intentional. If you need two separate IPs, those workloads belong in **separate pods**, not separate containers in one pod.

```
Need separate IPs?          → separate pods
Need to share localhost?    → same pod, different ports
Need to share files?        → same pod, shared volume
```

## The One Exception — Multus CNI

In specialized environments (OpenShift, bare-metal, telco/network functions), you can use **Multus CNI** to attach additional network interfaces to a pod:

```yaml
# Multus annotation — attaches a second network interface
metadata:
  annotations:
    k8s.v1.cni.cncf.io/networks: macvlan-conf

# Result:
# eth0 → 10.244.1.5   (primary pod network, shared by all containers)
# net1 → 192.168.1.10 (secondary interface, also shared by all containers)
```

But even with Multus, all containers in the pod still share **both** interfaces and **both** IPs — you can't give one container `eth0` and another container `net1`. The network namespace is shared at the pod level, not the container level.

**One-line answer:** One pod = one IP, always. Separate containers get separate ports on that one IP, not separate IPs.
