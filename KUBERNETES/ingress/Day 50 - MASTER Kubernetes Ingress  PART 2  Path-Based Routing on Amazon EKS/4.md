Here is a **complete practical example** of using
`target-type: instance` (NodePort mode) with the **AWS Load Balancer Controller**, where the **AWS Application Load Balancer** sends traffic to **EC2 nodes → NodePort → kube-proxy → Pod**.


# 1. How `target-type: instance` Works (Quick Recap)

Traffic flow:

```
Client → ALB → EC2 Node (NodePort) → kube-proxy → Service → Pod
```

Key points:

* ALB targets = **EC2 nodes**
* Service type = **NodePort**
* kube-proxy forwards to Pods
* More hops than IP mode

---

# 2. Step 1 — Deploy an App (iphone app)

Example deployment:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: iphone-app
spec:
  replicas: 2
  selector:
    matchLabels:
      app: iphone
  template:
    metadata:
      labels:
        app: iphone
    spec:
      containers:
      - name: iphone
        image: hashicorp/http-echo
        args:
        - "-text=Hello from iPhone"
        ports:
        - containerPort: 5678
```

Apply:

```bash
kubectl apply -f deploy.yaml
```

---

# 3. Step 2 — Create NodePort Service

This is **required** for `target-type: instance`.

```yaml
apiVersion: v1
kind: Service
metadata:
  name: iphone-service
spec:
  type: NodePort
  selector:
    app: iphone
  ports:
  - port: 80
    targetPort: 5678
    nodePort: 30007
```

Apply:

```bash
kubectl apply -f service.yaml
```

Check:

```bash
kubectl get svc
```

Example output:

```
iphone-service   NodePort   10.0.0.5   <none>   80:30007/TCP
```

Now every node listens on:

```
<NodeIP>:30007
```

---

# 4. Step 3 — Create Ingress with instance Mode

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: iphone-ingress
  annotations:
    alb.ingress.kubernetes.io/target-type: instance
    alb.ingress.kubernetes.io/scheme: internet-facing
spec:
  ingressClassName: alb
  rules:
  - http:
      paths:
      - path: /iphone
        pathType: Prefix
        backend:
          service:
            name: iphone-service
            port:
              number: 80
```

Apply:

```bash
kubectl apply -f ingress.yaml
```

---

# 5. Step 4 — What Gets Created in AWS

The controller automatically creates:

```
ALB
 ├── Listener (80)
 ├── Target Group
 │     ├── Node1:30007
 │     ├── Node2:30007
 │     └── Node3:30007
```

Targets = **Nodes**, not Pods.

---

# 6. Step 5 — Packet Flow (Real Path)

When you access:

```
http://alb-dns-name/iphone
```

Flow:

```
1 Client
   ↓
2 ALB
   ↓
3 NodeIP:30007
   ↓
4 kube-proxy
   ↓
5 ClusterIP Service
   ↓
6 Pod IP
   ↓
7 Container:5678
```

---

# 7. Step 6 — Verify Targets

Check ALB targets:

* Go to AWS Console
* EC2 → Target Groups
* You’ll see:

```
10.0.1.10:30007
10.0.1.11:30007
```

These are **nodes**, not pods.

---

# 8. Step 7 — Test NodePort Directly

Find node IP:

```bash
kubectl get nodes -o wide
```

Test:

```bash
curl http://NODE-IP:30007
```

Expected:

```
Hello from iPhone
```

This proves:

```
NodePort → kube-proxy → Pod works
```

---

# 9. Step 8 — kube-proxy Routing

kube-proxy creates iptables rules like:

```
NodePort:30007
   ↓
ClusterIP:80
   ↓
Pod1:5678
Pod2:5678
```

Load balancing happens here.

---

# 10. Step 9 — Health Checks

ALB health check:

```
ALB → NodeIP:30007 → kube-proxy → Pod
```

Important:

* Health checks are **node-level**
* Not pod-level

# 12. When to Use `instance` Mode

Use when:

* Legacy setup
* NodePort already used
* Simpler networking
* IP mode not supported

---

# 13. Instance vs IP Mode

| Feature     | instance | ip        |
| ----------- | -------- | --------- |
| Target      | Node     | Pod       |
| Service     | NodePort | ClusterIP |
| Hop Count   | More     | Less      |
| kube-proxy  | Yes      | No        |
| Performance | Lower    | Higher    |

---

# 14. Most Important Practical Points

You **must have**:

```
Service type = NodePort
target-type = instance
```

Otherwise it won't work.
