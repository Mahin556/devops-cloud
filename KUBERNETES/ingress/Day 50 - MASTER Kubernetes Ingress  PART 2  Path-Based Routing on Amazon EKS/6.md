Multiple Lb for Same Ingress

Deploying multiple Load Balancers (LBs) for a single Ingress controller is possible and commonly used to achieve traffic isolation, multi-network access (public/private), or high availability. However, the approach depends on the Ingress controller and cloud provider.

### **Nginx Ingress Controller**
- **Multiple LBs via Multiple Services**: The Nginx Ingress Controller can be configured to create **multiple Services** (e.g., one for public and one for private network access) using annotations like `service.beta.kubernetes.io/alibaba-cloud-loadbalancer-address-type: intranet` (Alibaba Cloud) or equivalent for AWS/GCP.
- **Example**: On Alibaba Cloud, you can deploy a second Service (`nginx-ingress-lb-intranet`) in a different namespace or with a different annotation to attach an internal SLB, while the default Nginx Ingress Controller uses an external SLB.
- **Key Limitation**: You cannot have two Services with the same name. The `nginx-ingress-lb` Service name is reserved, so you must use a unique name for additional Services (e.g., `nginx-ingress-lb-intranet`).

### **AWS ALB Ingress Controller**
- **IngressGroup for Shared ALB**: Multiple Ingress resources can share a single Application Load Balancer (ALB) by using the `alb.ingress.kubernetes.io/group.name` annotation. This allows multiple Ingresses (across namespaces) to be bound to the same ALB, reducing the number of external LBs.
- **Separate ALBs**: If you need isolated traffic, each Ingress can be assigned a unique `group.name`, resulting in separate ALBs.

### **GKE / EKS**
- **GKE Ingress**: By default, GKE provisions one external load balancer per Ingress Controller. To use multiple LBs, you need to deploy multiple Ingress controllers or use a third-party controller like Nginx.
- **EKS with AWS ALB Controller**: Multiple Ingresses can share one ALB using `group.name`, but separate ALBs are created if `group.name` is not used.

### **Best Practices**
- Use **IngressClass** to differentiate between controllers (e.g., `nginx`, `alb`).
- Use **annotations** to control LB type (public/private), network access, and grouping.
- Avoid naming conflicts when creating multiple Services.
- For private clusters, consider using internal LBs with appropriate network policies.

> **Note**: Some cloud providers (like GKE) do not support combining multiple Ingress resources into a single load balancer directly. In such cases, use an **in-cluster ingress controller** (e.g., Nginx, Contour) behind a single Service of type `LoadBalancer` to manage multiple Ingresses efficiently.
