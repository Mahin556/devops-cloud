### Application pods need to connect to PostgreSQL database hosted outside the cluster. Provide a stable internal DNS name.

**Solution:**

**Step 1 - Create Service (without selector):**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: external-db-service             # DNS: external-db-service
spec:
  type: ClusterIP
  ports:
  - port: 5432                           # PostgreSQL port
    targetPort: 5432
    protocol: TCP
# NOTE: No selector! This is intentional.
```

**Step 2 - Create Endpoints Manually:**
```yaml
apiVersion: v1
kind: Endpoints
metadata:
  name: external-db-service             # MUST match service name
subsets:
- addresses:
  - ip: 192.168.1.200                   # External PostgreSQL IP
  - ip: 192.168.1.201                   # Secondary DB IP (if available)
  ports:
  - port: 5432
    protocol: TCP
```

**Step 3 - Use in Application:**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app-deployment
spec:
  replicas: 2
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
    spec:
      containers:
      - name: app
        image: myapp:latest
        env:
        - name: DB_HOST
          value: "external-db-service"   # Internal DNS resolves to external DB
        - name: DB_PORT
          value: "5432"
        - name: DB_NAME
          value: "mydb"
        - name: DB_USER
          valueFrom:
            secretKeyRef:
              name: db-credentials
              key: username
        - name: DB_PASSWORD
          valueFrom:
            secretKeyRef:
              name: db-credentials
              key: password
```

**Verify Setup:**
```bash
# Apply both files
kubectl apply -f external-db-service.yaml
kubectl apply -f external-db-endpoints.yaml

# Verify
kubectl get service external-db-service
kubectl get endpoints external-db-service
kubectl describe service external-db-service
```

**Alternative - ExternalName Service:**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: external-db-service
spec:
  type: ExternalName
  externalName: db.example.com          # External DNS name
  ports:
  - port: 5432
```

**Key Points:**
- Service without selector allows manual endpoint definition
- Endpoints object maps service to external IPs
- Service name and Endpoints name must match exactly
- Application pods use internal DNS: `external-db-service`
- External DB IPs are hidden behind a stable DNS name
- Supports multiple external IPs for basic failover
- Alternative: `ExternalName` service type for DNS-based external services
- Credentials stored in Kubernetes Secrets (not hardcoded)
- If external DB IP changes, just update the Endpoints object
