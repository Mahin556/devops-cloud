### `app.example.com` routes to app service, `admin.example.com` routes to admin service. All traffic must use HTTPS with TLS certificates stored in Kubernetes.

**Solution:**

**Step 1 - Create TLS Secret:**
```bash
# From certificate files
kubectl create secret tls example-com-tls \
  --cert=path/to/tls.crt \
  --key=path/to/tls.key \
  -n production

# Or from YAML (base64 encoded)
```

**TLS Secret YAML:**
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: example-com-tls
type: kubernetes.io/tls
data:
  tls.crt: <base64-encoded-certificate>
  tls.key: <base64-encoded-private-key>
```

**Step 2 - Ingress with Host-Based Routing and TLS:**
```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: host-based-ingress
spec:
  ingressClassName: nginx
  tls:
  - hosts:
    - app.example.com
    - admin.example.com
    secretName: example-com-tls      # TLS certificate from Kubernetes Secret
  rules:
  - host: app.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: app-service
            port:
              number: 80
  - host: admin.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: admin-service
            port:
              number: 80
```

**Traffic Flow:**
```
Request to https://app.example.com  → TLS terminated at Ingress → app-service:80
Request to https://admin.example.com → TLS terminated at Ingress → admin-service:80
```

**Key Points:**
- Host-based routing uses `host` field in rules
- TLS section lists all domains covered by the certificate
- TLS termination happens at the Ingress level
- Backend services receive plain HTTP traffic
- TLS certificate stored securely in Kubernetes Secret of type `kubernetes.io/tls`
- Single Ingress handles multiple domains with HTTPS
- Ingress Controller (e.g., NGINX) handles TLS decryption
