## What is the difference between `requests` and `limits` in container resource specification?

### Requests (Guaranteed/Reserved Memory):
- **Meaning:** This is the MINIMUM guaranteed amount of resource
- **Analogy from transcript:** A confirmed train seat reservation
- **Behavior:** The container is GUARANTEED to get this much resource
- **Scheduling:** Scheduler uses this value to decide which node has enough capacity
- **Example:** `memory: 200Mi` request means 200Mi is reserved for this container

### Limits (Maximum Allowed):
- **Meaning:** This is the MAXIMUM the container can use
- **Analogy from transcript:** The entire seat you booked but may not fully occupy
- **Behavior:** Container can use UP TO this limit, but it's NOT guaranteed beyond request
- **Throttling:** If container exceeds limit, CPU is throttled; if memory exceeds, container is OOMKilled
- **Example:** `memory: 400Mi` limit means container can use max 400Mi

### Example from transcript:
```
requests:
  memory: 200Mi    # Guaranteed 200Mi (like confirmed seat)
limits:
  memory: 400Mi    # Max 400Mi (can use full seat if available)
```

The extra 200Mi (400-200) is NOT guaranteed. It will be given only if other applications are not using their full reservations.

### Key Difference:

| Feature | Request | Limit |
|---------|---------|-------|
| **Type** | Guaranteed minimum | Maximum allowed |
| **Scheduling** | Used for node selection | Not used for scheduling |
| **Exceeding** | Can exceed up to limit | Cannot exceed (throttled/killed) |
| **Guarantee** | 100% guaranteed | Not guaranteed beyond request |
