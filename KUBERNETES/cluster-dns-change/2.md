# Complete Tutorial: Updating Kubelet DNS Configuration After Service CIDR Rotation

This tutorial walks through updating all kubelets to use the new DNS ClusterIP after changing the service CIDR range.

## Overview

After rotating the service CIDR to `100.96.0.0/12`, the CoreDNS service now has a new ClusterIP (e.g., `100.96.0.10`). Kubelets need to be updated to point pods to this new DNS IP for proper name resolution.

## Prerequisites
- Completed service CIDR rotation
- New CoreDNS ClusterIP identified (`100.96.0.10` in this example)
- Root/sudo access to controlplane node

## Step 1: Identify the New DNS ClusterIP

```bash
# Get the new kube-dns service IP
kubectl get svc -n kube-system kube-dns -o jsonpath='{.spec.clusterIP}'
echo ""

# Expected output: 100.96.0.10 or similar in 100.96.0.0/12 range
```

## Step 2: Update Local Kubelet Configuration File

Edit the kubelet config file on the node:

```bash
# Backup the current configuration
cp /var/lib/kubelet/config.yaml /var/lib/kubelet/config.yaml.bak

# Edit the kubelet config
vi /var/lib/kubelet/config.yaml
```

Find and update the `clusterDNS` section:

```yaml
apiVersion: kubelet.config.k8s.io/v1beta1
authentication:
  anonymous:
    enabled: false
  webhook:
    cacheTTL: 0s
    enabled: true
  x509:
    clientCAFile: /etc/kubernetes/pki/ca.crt
authorization:
  mode: Webhook
  webhook:
    cacheAuthorizedTTL: 0s
    cacheUnauthorizedTTL: 0s
cgroupDriver: systemd
clusterDNS:                    # Change this section
- 100.96.0.10                  # Update to new DNS IP
clusterDomain: cluster.local
# ... rest of configuration remains the same
```

Save and exit.

## Step 3: Update Kubelet ConfigMap in kube-system Namespace

The ConfigMap serves as the source of truth for kubelet configurations:

```bash
# Edit the kubelet-config ConfigMap
kubectl -n kube-system edit cm kubelet-config
```

Update the `clusterDNS` value inside the ConfigMap:

```yaml
apiVersion: v1
data:
  kubelet: |
    apiVersion: kubelet.config.k8s.io/v1beta1
    authentication:
      anonymous:
        enabled: false
      webhook:
        cacheTTL: 0s
        enabled: true
      x509:
        clientCAFile: /etc/kubernetes/pki/ca.crt
    authorization:
      mode: Webhook
      webhook:
        cacheAuthorizedTTL: 0s
        cacheUnauthorizedTTL: 0s
    cgroupDriver: systemd
    clusterDNS:                # Update this section
    - 100.96.0.10              # New DNS ClusterIP
    clusterDomain: cluster.local
    # ... rest of the configuration
kind: ConfigMap
metadata:
  creationTimestamp: "..."
  name: kubelet-config
  namespace: kube-system
  # ... other metadata
```

Save and exit.

## Step 4: Apply the Kubelet Configuration Update

Use kubeadm to update the kubelet configuration:

```bash
# Apply the updated kubelet configuration
kubeadm upgrade node phase kubelet-config

# Expected output:
# [upgrade] Reading configuration from the cluster...
# [upgrade] FYI: You can look at this config file with 'kubectl -n kube-system get cm kubelet-config -o yaml'
```

## Step 5: Reload and Restart Kubelet

```bash
# Reload systemd daemon to pick up changes
systemctl daemon-reload

# Restart the kubelet service
systemctl restart kubelet

# Verify kubelet is running
systemctl status kubelet

# Check kubelet logs for any errors
journalctl -u kubelet -f --tail=20
```

## Step 6: Verify the Kubelet Configuration

```bash
# Check the effective kubelet configuration
kubectl get configmap -n kube-system kubelet-config -o yaml | grep -A2 clusterDNS

# Verify kubelet is using the new DNS
ps aux | grep kubelet | grep cluster-dns
```

## Step 7: Update All Worker Nodes (If Applicable)

For a multi-node cluster, repeat steps 2-5 on each worker node:

```bash
# For each worker node, SSH into the node and run:
ssh worker-node-1

# Backup and update config
cp /var/lib/kubelet/config.yaml /var/lib/kubelet/config.yaml.bak
sed -i 's/clusterDNS:.*$/clusterDNS:\n- 100.96.0.10/' /var/lib/kubelet/config.yaml

# Apply and restart
kubeadm upgrade node phase kubelet-config
systemctl daemon-reload
systemctl restart kubelet

# Exit back to controlplane
exit
```

## Step 8: Test DNS Resolution with New Kubelet Configuration

Create a test pod to verify pods get the correct DNS configuration:

```bash
# Create a test pod
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: dns-test-pod
spec:
  containers:
  - name: test
    image: busybox:1.28
    command: ['sh', '-c', 'echo "DNS test pod running"; sleep 3600']
  restartPolicy: Never
EOF

# Wait for pod to be ready
kubectl wait --for=condition=ready pod/dns-test-pod --timeout=60s

# Check the pod's resolv.conf file
kubectl exec dns-test-pod -- cat /etc/resolv.conf

# Expected output should show:
# nameserver 100.96.0.10
# search default.svc.cluster.local svc.cluster.local cluster.local
# options ndots:5

# Test DNS resolution
kubectl exec dns-test-pod -- nslookup kubernetes.default
kubectl exec dns-test-pod -- nslookup google.com

# Clean up
kubectl delete pod dns-test-pod
```

## Step 9: Verify Existing Pods Get Updated DNS

Existing pods may need to be restarted to pick up the new DNS configuration:

```bash
# Option 1: Rollout restart all deployments
kubectl rollout restart deployment --all -A

# Option 2: Delete and recreate pods (for standalone pods)
kubectl delete pods --all -A --field-selector status.phase=Running

# Option 3: Rollout restart specific namespaces
kubectl rollout restart deployment --all -n <namespace>
```

```bash

kubectl logs -n kube-system -l k8s-app=kube-dns --tail=50
```

## Troubleshooting Common Issues

### Issue 1: Kubelet fails to restart

```bash
# Check kubelet logs
journalctl -u kubelet -n 50 --no-pager

# Validate config file syntax
kubelet --config=/var/lib/kubelet/config.yaml --dry-run=client

# Restore from backup if needed
cp /var/lib/kubelet/config.yaml.bak /var/lib/kubelet/config.yaml
systemctl restart kubelet
```

### Issue 2: Pods still have old DNS IP

```bash
# Check if pod was created before kubelet update
kubectl get pod <pod-name> -o yaml | grep creationTimestamp

# Force pod recreation
kubectl delete pod <pod-name> --force --grace-period=0
```

### Issue 3: ConfigMap edit not applying

```bash
# Verify ConfigMap was updated
kubectl get cm -n kube-system kubelet-config -o yaml | grep -A2 clusterDNS

# Force kubelet to re-read config
kubeadm upgrade node phase kubelet-config
systemctl restart kubelet
```

### Issue 4: DNS resolution intermittently failing

```bash
# Check CoreDNS replica count
kubectl get deployment -n kube-system coredns

# Scale CoreDNS if needed
kubectl scale deployment -n kube-system coredns --replicas=2

# Check CoreDNS logs for errors
kubectl logs -n kube-system -l k8s-app=kube-dns --tail=100
```

## Verification Checklist

- [ ] `/var/lib/kubelet/config.yaml` has `clusterDNS: [100.96.0.10]`
- [ ] `kubelet-config` ConfigMap has updated DNS value
- [ ] `kubeadm upgrade node phase kubelet-config` completed successfully
- [ ] Kubelet service restarted successfully
- [ ] Test pod shows `nameserver 100.96.0.10` in `/etc/resolv.conf`
- [ ] DNS resolution works for cluster services
- [ ] DNS resolution works for external domains
- [ ] All existing pods can resolve DNS after restart

## Summary

You've successfully:
1. Updated the local kubelet configuration file with the new DNS ClusterIP
2. Modified the kubelet ConfigMap in the kube-system namespace
3. Applied the configuration using `kubeadm upgrade node phase kubelet-config`
4. Reloaded and restarted the kubelet service
5. Verified that new pods receive the correct DNS configuration

All new pods will now use the new DNS ClusterIP (`100.96.0.10`) for name resolution, ensuring proper service discovery in the updated service CIDR range.
