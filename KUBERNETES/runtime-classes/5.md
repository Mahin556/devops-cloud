## Why Wasm Can’t Run on `runc`

- **Binary Format**: Wasm files (`.wasm`) are **bytecode**, not native machine code (x86_64, ARM, etc.).
- **Execution Needs**: They require a **virtual machine** or **JIT/AOT compiler** to translate bytecode into CPU instructions.
- **System Calls**: Wasm uses **WASI** (WebAssembly System Interface) for I/O and other operations, whereas `runc` expects direct Linux kernel syscalls.

Thus, you need a **Wasm‑aware runtime** – either a special OCI runtime or a dedicated containerd shim.

## Option 1: Configure `crun` with `containerd`

In this approach, you replace `runc` with `crun` (compiled with Wasm support) as the low‑level runtime for `containerd`.

### Step 1: Install `containerd`

```bash
export VERSION="1.5.7"
sudo apt install -y libseccomp2 wget
wget https://github.com/containerd/containerd/releases/download/v${VERSION}/cri-containerd-cni-${VERSION}-linux-amd64.tar.gz
sudo tar --no-overwrite-dir -C / -xzf cri-containerd-cni-${VERSION}-linux-amd64.tar.gz
sudo systemctl daemon-reload
```

### Step 2: Generate the default containerd configuration

```bash
sudo mkdir -p /etc/containerd/
sudo bash -c "containerd config default > /etc/containerd/config.toml"
```

### Step 3: Build a Wasm‑enabled `crun`

You need to compile `crun` with support for Wasm (e.g., using WasmEdge). Follow the official guide to build `crun` with the `--with-wasmedge` flag. The resulting binary (e.g., `/usr/local/bin/crun`) will be used later.

### Step 4: Modify `/etc/containerd/config.toml`

Add a new runtime handler that points to your custom `crun`. For example:

```toml
version = 2
[plugins."io.containerd.grpc.v1.cri".containerd.runtimes.crun]
  runtime_type = "io.containerd.runc.v2"
  pod_annotations = ["*.wasm.*"]
  [plugins."io.containerd.grpc.v1.cri".containerd.runtimes.crun.options]
    BinaryName = "/usr/local/bin/crun"
```

### Step 5: Restart `containerd`

```bash
sudo systemctl restart containerd
```

### Step 6: Run a Wasm workload using `ctr`

```bash
sudo ctr run --rm --runc-binary crun \
    --runtime io.containerd.runc.v2 \
    --label module.wasm.image/variant=compat-smart \
    docker.io/wasmedge/example-wasi:latest \
    wasm-example /wasi_example_main.wasm 50000000
```

**Key flags**:
- `--runc-binary crun` – uses `crun` instead of `runc`.
- `--runtime io.containerd.runc.v2` – tells containerd to use the v2 runtime interface.
- `--label module.wasm.image/variant=compat-smart` – marks the image as a Wasm workload.

## Option 2: Run Wasm via Docker (Docker Desktop)

Docker Desktop has built‑in support for Wasm (currently in Beta/Experimental, please check the latest documentation).

### Enable Wasm in Docker Desktop

1. Open Docker Desktop **Settings**.
2. Under **General**, check **Use containerd for pulling and storing images**.
3. Under **Features in development**, enable **Enable Wasm**.
4. Click **Apply** and let Docker download the necessary Wasm runtime.

### Run a Wasm container with `docker run`

```bash
docker run \
    --runtime=io.containerd.wasmedge.v1 \
    --platform=wasi/wasm \
    secondstate/rust-example-hello
```

**Explanation**:
- `--runtime=io.containerd.wasmedge.v1` – selects the Wasm shim.
- `--platform=wasi/wasm` – forces the platform to Wasm/WASI.

### Use Docker Compose

Define a service in `docker-compose.yml`:

```yaml
services:
  app:
    image: secondstate/rust-example-hello
    platform: wasi/wasm
    runtime: io.containerd.wasmedge.v1
```

Then run `docker compose up`.
