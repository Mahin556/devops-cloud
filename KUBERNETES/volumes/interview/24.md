## What is the way to persist container data in Kubernetes? What practice do you follow?

### The Complete Answer Flow:

**Step 1: PersistentVolume (PV)**
- PV is a cluster-wide resource that represents storage
- It contains information about WHERE the storage is (NFS, Ceph, GlusterFS, cloud storage, etc.)
- PV is created by the Kubernetes administrator
- PV exists independently of any pod

**Step 2: PersistentVolumeClaim (PVC)**
- PVC is a namespace-scoped request for storage
- Development team creates PVC to "claim" a PV
- PVC acts as a binding between PV and the pod
- Without a claim, no one can use the PV

**Step 3: Mount in Pod/Deployment**
- Reference the PVC name in the deployment YAML
- Pod writes data to the mounted volume
- Data persists even if pod is deleted

### PV States:
- **Available:** PV is created but not yet claimed
- **Bound:** PV is claimed by a PVC in a namespace
- **Released:** PVC is deleted but PV data is not yet cleaned up

### Two Types of PV Provisioning:

**1. Static Provisioning:**
- Administrator manually creates PV
- Every time storage is needed, admin must intervene
- Admin coordinates with storage team to create the underlying storage
- Manual process, not automated

**2. Dynamic Provisioning:**
- StorageClass object is created
- When PVC is created, PV is automatically provisioned
- No admin intervention needed
- Uses provisioner (CSI driver) to create storage on-demand
