## What is CSI (Container Storage Interface)?

**Full Form:** Container Storage Interface

**Why CSI is needed:**

The instructor explains the problem CSI solves:

- Kubernetes API server has built-in knowledge for common storage types like NFS, iSCSI
- But there are MANY third-party storage vendors in the market (AWS EBS, EFS, Azure Disk, NetApp, Dell EMC, etc.)
- Each storage vendor has its own API and principles
- If a vendor introduces a new feature or new storage type, the Kubernetes API code would need to be modified
- This is NOT practical - changing API code for every storage vendor update

**How CSI solves this:**
- CSI acts as a **plugin/interface** between Kubernetes API and third-party storage
- Instead of modifying the API code, vendors provide a CSI plugin
- The CSI plugin translates between Kubernetes API and the storage vendor's API
- This provides **portability** - any storage can be integrated without changing Kubernetes core code

**Architecture:**
```
Kubernetes API → CSI Plugin → Storage Backend (EBS, NFS, NetApp, etc.)
```

**Examples:**
- AWS provides CSI driver for EBS
- AWS provides CSI driver for EFS
- NetApp provides its own CSI driver
- Dell EMC provides its own CSI driver
