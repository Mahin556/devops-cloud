## Ingress Controller vs MetalLB

| Feature | Ingress Controller | MetalLB |
|---------|-------------------|---------|
| **Layer** | Layer 7 (Application) | Layer 3/4 (Network) |
| **Protocol** | HTTP, HTTPS | TCP, IP |
| **Works with** | Web apps, REST APIs | Databases, SSH, SMTP, Telnet |
| **Routing** | Path-based, Host-based | Port-based only |
| **Cloud** | Works everywhere | On-premises only |
| **Service Type** | Used with ClusterIP services | Used with LoadBalancer type services |

### Why MetalLB is On-Premises Only:
- Cloud providers already have their own Network Load Balancers (AWS NLB, Azure LB, GCP LB)
- When you create a `LoadBalancer` type service in cloud, it automatically provisions a cloud NLB
- On-premises data centers don't have this automatic provisioning
- MetalLB fills this gap for on-premises clusters

### When to Use MetalLB:
- Exposing non-HTTP services: MySQL (3306), SSH (22), SMTP (25), Telnet (23)
- When you need TCP/IP level load balancing
- Only in on-premises (bare metal) Kubernetes clusters
