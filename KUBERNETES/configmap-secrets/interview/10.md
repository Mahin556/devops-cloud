### Same application runs in dev, staging, and prod. Database hostname and log levels differ per environment. Must reuse the same container image across all environments.

**Solution:**

**Dev Environment ConfigMap:**
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
  namespace: dev
data:
  DB_HOST: "dev-db.example.com"
  LOG_LEVEL: "debug"
  APP_MODE: "development"
```

**Staging Environment ConfigMap:**
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
  namespace: staging
data:
  DB_HOST: "staging-db.example.com"
  LOG_LEVEL: "info"
  APP_MODE: "staging"
```

**Production Environment ConfigMap:**
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
  namespace: production
data:
  DB_HOST: "prod-db.example.com"
  LOG_LEVEL: "error"
  APP_MODE: "production"
```

**Dev Secrets:**
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: db-secret
  namespace: dev
type: Opaque
stringData:
  DB_PASSWORD: "dev-password-123"
```

**Production Secrets:**
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: db-secret
  namespace: production
type: Opaque
stringData:
  DB_PASSWORD: "prod-secure-password-456"
```

**Deployment YAML (Same for all environments):**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 2
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: app
        image: myapp:latest          # Same image across all environments
        envFrom:
        - configMapRef:
            name: app-config          # Injects environment-specific config
        - secretRef:
            name: db-secret           # Injects environment-specific secrets
```

**Deployment Process:**
```bash
# Deploy to Dev
kubectl apply -f dev-configmap.yaml
kubectl apply -f dev-secret.yaml
kubectl apply -f deployment.yaml -n dev

# Deploy to Production
kubectl apply -f prod-configmap.yaml
kubectl apply -f prod-secret.yaml
kubectl apply -f deployment.yaml -n production
```

**Key Points:**
- One container image built once, reused everywhere
- ConfigMaps and Secrets are namespace-scoped
- Each environment has its own ConfigMap and Secret with same name
- Deployment YAML references ConfigMap/Secret by name only
- Kubernetes injects correct values based on namespace
- No code changes or image rebuilds when moving between environments
- Sensitive values (passwords) stored in Secrets, not ConfigMaps
