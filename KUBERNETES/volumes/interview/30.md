## What is StorageClass and when does it come into the picture?

### When StorageClass is NOT used:
- In **Static Provisioning**, StorageClass is NOT involved
- Admin manually creates PV, developer claims it with PVC
- Simple flow: PV → PVC → Pod

### When StorageClass IS used:
- In **Dynamic Provisioning**, StorageClass is essential
- Users don't interact with CSI directly
- Users create PVC with a StorageClass name
- StorageClass forwards the request to the CSI provisioner

### Dynamic Provisioning Flow:
```
PVC (with storageClassName) → StorageClass → CSI Provisioner → PV created automatically
```

### What StorageClass contains:
- **Provisioner name** (which CSI driver to use)
- **Parameters** (storage type, IOPS, filesystem type, etc.)
- **Reclaim policy** (Retain, Delete, Recycle)
- **Volume binding mode** (Immediate, WaitForFirstConsumer)
- **Allow volume expansion** (true/false)

### Example Parameters:
- Storage size (GB)
- Reclaim policy (Retain/Delete)
- Binding mode (Immediate/WaitForFirstConsumer)
- Whether volume can be expanded later

### Why not directly call CSI?
- Users have specific requirements (size, policy, etc.)
- These are user-specific values that change per request
- Hard-coding these in CSI doesn't make sense
- StorageClass acts as an abstraction layer between user requests and CSI
