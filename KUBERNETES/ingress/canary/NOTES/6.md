```text
                        Client
                           |
                    NGINX Ingress
                           |
          +----------------+----------------+
          |                                 |
     Stable Ingress                  Canary Ingress
     (Normal Traffic)              (Canary Rules)
          |                                 |
     stable-service                  canary-service
          |                                 |
     Deployment v1                   Deployment v2
```

# Stable Deployment

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app-v1
spec:
  replicas: 3
  selector:
    matchLabels:
      app: app-v1
  template:
    metadata:
      labels:
        app: app-v1
    spec:
      containers:
      - name: app
        image: hashicorp/http-echo:1.0
        args:
        - "-text=Stable Version"
        ports:
        - containerPort: 5678
```

# Canary Ingress (20% Traffic)

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: canary-ingress
  annotations:
    nginx.ingress.kubernetes.io/canary: "true"
    nginx.ingress.kubernetes.io/canary-weight: "20"
spec:
  ingressClassName: nginx
  rules:
  - host: demo.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: canary-service
            port:
              number: 80
```

# Header-Based Canary

Instead of weight, replace the annotations with:

```yaml
metadata:
  annotations:
    nginx.ingress.kubernetes.io/canary: "true"
    nginx.ingress.kubernetes.io/canary-by-header: "X-Canary"
    nginx.ingress.kubernetes.io/canary-by-header-value: "always"
```

### Test without the header

```bash
curl -H "Host: demo.example.com" http://<INGRESS-IP>
```

Output:

```text
Stable Version
```

### Test with the header

```bash
curl \
  -H "Host: demo.example.com" \
  -H "X-Canary: always" \
  http://<INGRESS-IP>
```

Output:

```text
Canary Version
```

# Cookie-Based Canary

Use these annotations:

```yaml
metadata:
  annotations:
    nginx.ingress.kubernetes.io/canary: "true"
    nginx.ingress.kubernetes.io/canary-by-cookie: "user_type"
```

Test without the cookie:

```bash
curl -H "Host: demo.example.com" http://<INGRESS-IP>
```

→ **Stable Version**

Test with the cookie:

```bash
curl \
  -H "Host: demo.example.com" \
  --cookie "user_type=always" \
  http://<INGRESS-IP>
```

→ **Canary Version**

# Evaluation Order

If multiple canary annotations are configured, the NGINX Ingress Controller evaluates them in this order:

| Priority | Annotation         | Description                                                                      |
| -------: | ------------------ | -------------------------------------------------------------------------------- |
|        1 | `canary-by-header` | Highest priority. If the header rule matches, the request is sent to the canary. |
|        2 | `canary-by-cookie` | Used only if no header rule matched.                                             |
|        3 | `canary-weight`    | Used only if neither the header nor cookie rules matched.                        |

For example, suppose your canary Ingress has:

```yaml
annotations:
  nginx.ingress.kubernetes.io/canary: "true"
  nginx.ingress.kubernetes.io/canary-by-header: "X-Canary"
  nginx.ingress.kubernetes.io/canary-by-header-value: "always"
  nginx.ingress.kubernetes.io/canary-weight: "20"
```

* A request with `X-Canary: always` **always** goes to the canary, regardless of the 20% weight.
* A request without that header is then evaluated against the cookie rule (if present).
* If neither the header nor cookie rules apply, the request participates in the 20% weighted traffic split.
