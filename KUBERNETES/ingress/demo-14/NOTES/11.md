If you're using an **NGINX reverse proxy in front of your Kubernetes Ingress**, you have two choices.

## Option 1: SSL Passthrough (recommended if Ingress handles TLS)

The reverse proxy simply forwards HTTPS traffic to the Ingress.

```
Client
   │ HTTPS
   ▼
NGINX Reverse Proxy
   │ HTTPS
   ▼
Ingress Controller
   │
Backend
```

Example:

```nginx
server {
    listen 443 ssl;
    server_name myapp.example.com;

    ssl_certificate     /etc/nginx/certs/proxy.crt;
    ssl_certificate_key /etc/nginx/certs/proxy.key;

    location / {
        proxy_pass https://172.18.0.120;

        proxy_ssl_server_name on;
        proxy_ssl_verify off;   # self-signed certificate
        proxy_set_header Host $host;

        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }
}
```

The important line is:

```nginx
proxy_ssl_verify off;
```

Since your Ingress uses a **self-signed certificate**, the reverse proxy won't trust it unless you either disable verification or configure the CA.

---

## Option 2: Trust your self-signed certificate (recommended over disabling verification)

Copy the CA or self-signed certificate:

```text
tls.crt
```

to the reverse proxy, for example:

```text
/etc/nginx/certs/ingress-ca.crt
```

Then configure:

```nginx
location / {
    proxy_pass https://172.18.0.120;

    proxy_ssl_server_name on;
    proxy_ssl_trusted_certificate /etc/nginx/certs/ingress-ca.crt;
    proxy_ssl_verify on;
    proxy_ssl_verify_depth 2;

    proxy_set_header Host $host;
}
```

Now NGINX verifies the backend certificate instead of blindly accepting it.

---

# Option 3: Terminate TLS at the reverse proxy

This is common in production.

```
Client
      HTTPS
        │
        ▼
Reverse Proxy
   decrypt TLS
        │
    HTTP
        ▼
Ingress
        │
Backend
```

NGINX:

```nginx
server {
    listen 443 ssl;
    server_name myapp.example.com;

    ssl_certificate /etc/nginx/certs/myapp.crt;
    ssl_certificate_key /etc/nginx/certs/myapp.key;

    location / {
        proxy_pass http://172.18.0.120;
        proxy_set_header Host $host;
    }
}
```

In this case:

* The reverse proxy presents the certificate to clients.
* Communication between the reverse proxy and the Ingress is plain HTTP.
* You would typically **disable** the Ingress annotation:

```yaml
nginx.ingress.kubernetes.io/ssl-redirect: "false"
```

because the reverse proxy has already handled HTTPS.

---

# Which one should you choose?

For your Kind + MetalLB lab:

```
Laptop
    │ HTTPS
    ▼
NGINX Reverse Proxy (VM)
    │ HTTPS
    ▼
Ingress Controller (Kind)
    │
Backend Services
```

I recommend either:

* **Quick lab:** `proxy_ssl_verify off;`
* **Better lab / production practice:** configure `proxy_ssl_trusted_certificate` with your self-signed CA or certificate and keep `proxy_ssl_verify on;`

This preserves end-to-end encryption while still validating the backend certificate.
