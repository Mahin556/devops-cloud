### What is Quorum?

etcd uses a quorum-based model, where a majority of members must agree on state updates to ensure data consistency and prevent split-brain. 

It relies on the  Raft consensus algorithm , requiring a majority of nodes to be operational for writing, electing leaders, and committing logs, crucial for Kubernetes cluster reliability. 

Key Aspects of etcd Quorum: 

• Formula: For a cluster with $N$ members, quorum is $\frac{N}{2}+1$. 
	• 3 members: Quorum = 2 
	• 5 members: Quorum = 3 
 
• Failure Tolerance: A 3-member cluster can only lose 1 member; a 5-member cluster can lose 2. 
• Odd Numbers Recommended: Odd-numbered clusters (3, 5, 7) are preferred to maximize fault tolerance without increasing quorum requirements. 
• Quorum Loss Consequences: If a majority is lost, the cluster becomes unrecoverable, becoming read-only or unresponsive, which requires manual restoration. 
• Reads & Writes: Writes must reach a majority. While some reads can happen without full quorum, strong consistency reads require interaction with the leader. [1, 5, 6, 7, 8]  

Why Quorum is Essential:It ensures that all members agree on data, avoiding inconsistent states, especially during network partitions. If a partition occurs, only the side with the majority can continue operating. [1, 4, 5, 7, 9]
