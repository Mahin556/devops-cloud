## Summary Table

| Concept | Key Point |
|---------|-----------|
| **Split Brain** | Two partitions both think they're the leader → simultaneous writes → data corruption |
| **Quorum** | Minimum votes needed = floor(Total Votes/2) + 1 |
| **3 Nodes** | Quorum=2, tolerates 1 failure, majority always wins |
| **4 Nodes (Why NOT)** | Quorum=3, 2+2 split = both sides fail, WORSE than 3 |
| **Odd Numbers** | Always ensure one partition has majority in any split |
| **RAFT Algorithm** | Used by etcd for leader election and log replication |
| **Leader Role** | Only leader handles writes; members handle reads |
| **Leader Election** | Automatic when leader fails; based on vote majority |
| **Worker Connection** | Via load balancer, not direct to specific master |
| **LB Intelligence** | Write queries → leader; Read queries → any member |
